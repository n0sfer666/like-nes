# like-nes — правила репозитория

Контекст проекта: [`.context/`](.context/) (README, stack, architecture, conventions, specs,
decisions, notes). Читать перед началом любой задачи. Стиль кода —
[`.context/conventions.md`](.context/conventions.md).

## Ветки

| Ветка | Роль | Правила |
|---|---|---|
| `main` | Дефолтная, релизная. Отражает подтверждённое состояние движка. | Прямые коммиты **запрещены**. Только merge из PR. |
| `dev` | Рабочая: код, PoC, проверка гипотез, промежуточные коммиты. | Коммитим сюда. Может быть шумной. |

Фича-ветки (`feat/*`, `fix/*`, `poc/*`) — по желанию, от `dev`, вливаются в `dev`.
Долгоживущих параллельных веток не заводить: одна линия `dev` → `main`.

## Раунд → PR

**Раунд** = завершённая веха: закрытая спека из roadmap, отдельная вертикаль PoC,
или согласованный блок работ с зафиксированным DoD.

После **каждого раунда** — обязательно PR `dev` → `main`:

1. Проверки пройдены, CI зелёный на всех 3 ОС (`.github/workflows/ci.yml`).
2. `.claude/.verify-state.json` и `.claude/.review-state.json` — свежие, `result: pass`.
3. `gh pr create --base main --head dev` — заголовок в стиле conventional commits,
   тело: что сделано / DoD и как проверено / ссылки на спеку и ADR.
4. Merge (по умолчанию `--squash` не использовать — история раундов линейная и осмысленная,
   merge-commit сохраняет границу раунда).
5. После merge — `git checkout dev && git merge main` (синхронизация), продолжаем работу.

Промежуточные коммиты внутри раунда в `main` не попадают отдельно — только через PR раунда.

## Сборочный гейт (обязателен перед КАЖДЫМ коммитом)

У C++ нет отдельного тайпчекера — его роль играет компилятор, поэтому строгая сборка здесь
ровно то же, чем `tsc --noEmit` служит фронтенду. Гейт: **ноль ошибок и ноль предупреждений**.

```
bash scripts/build_check.sh      # то же, что гоняет CI и pre-commit hook
```

- Скрипт валит прогон, если сборка упала **или** в её логе есть хоть одно предупреждение.
  Проверок две, потому что `-Werror` покрывает только компилятор: драйвер (MSVC `D9xxx`),
  линкер и CMake проходят мимо него.
- **Набор целей задаётся набором опций**, поэтому по умолчанию скрипт возвращает `AUDIO_MINIAUDIO`,
  `PLUGIN_UI` и `PLUGIN_WASM` в `ON`: каталог, однажды сконфигурированный headless, иначе навсегда
  делал бы гейт зелёным по целям, которых он не собирает. Урезанный набор разрешён только тому,
  кто заявил его явно через `LIKE_NES_BUILD_SUBSET=1` — это шаг `Configure` в CI (imgui и
  miniaudio собираются там отдельными шагами, каждый в своём каталоге и одной целью через
  `LIKE_NES_BUILD_TARGETS`; wasm-гейту нужен wasmtime C-API из `deps/`, которого на раннерах нет)
  и headless-этап `preflight.sh`.
- Наш код собирается с `-Wall -Wextra -Werror` (`/W4 /WX` на MSVC) — включается
  [`cmake/warnings.cmake`](cmake/warnings.cmake) строго между зависимостями и
  `add_subdirectory` нашего кода; порядок в `CMakeLists.txt` несущий.
- Сторонние зависимости из этого исключены: с их целей **снимается уровень** предупреждений
  (`like_nes_strip_warning_level`) и дописывается `-w` — их пин на коммит есть условие
  байт-детерминизма бейка, править их нельзя. Именно снимается, а не перекрывается: `/w` поверх
  уровня даёт `Command line warning D9025 : overriding '/W4' with '/w'` — предупреждение драйвера,
  мимо `/WX`, но прямо в лог, который читает гейт. `-Wextra`/`/WX` на цели остаются и молчат:
  промотировать в ошибку после `-w` нечего.
- Вендоренный исходник рядом с нашим (`stb_impl.cpp`, `stb_vorbis_impl.c`, `miniaudio_impl.c`,
  imgui) по той же причине живёт **отдельной OBJECT-целью** (`like_nes_vendored_object`), а не
  свойством исходника: уровень предупреждений — свойство ЦЕЛИ, и снять его с одного файла внутри
  общей цели нечем. Объекты попадают в потребителя через `target_link_libraries`, наш код в той же
  цели (`wgpu_imgui.cpp`, `device.cpp`) остаётся строгим. Цель, где чужого кода целиком
  (`basis_transcoder`), глушится `like_nes_vendored_target`.
- Предупреждение **не глушится** `-Wno-…`, чтобы «пройти гейт»: либо чинится код, либо
  доказывается, что диагностика относится к стороннему TU.
- `LIKE_NES_WERROR=OFF` существует ровно для одного сценария — собрать дерево целиком и
  увидеть ВСЕ предупреждения разом, а не первое. Коммит с ним не проходит: скрипт возвращает
  флаг в `ON` и пересобирает.

- Вызов всегда через `bash`, а не по exec-биту: на Windows-раннере шелл — git-bash, и exec-бит
  из индекса он не наследует. По той же причине `.gitattributes` держит `*.sh` и `*.py` в `eol=lf`:
  скрипт, выехавший из checkout с CRLF, умирает на собственном шебанге.

**Без зелёного `build_check.sh` коммит запрещён.** Команда прописана в
[`.context/checks.json`](.context/checks.json) — её читает pre-commit hook и шаг `Build` в CI.

## Линтер workflow (обязателен перед КАЖДЫМ коммитом)

```
python3 scripts/ci_lint.py             # блокирующий гейт, в checks.json
python3 scripts/ci_lint.py --selftest  # правила проверяются сломанными фикстурами
```

Круг «push → 20+ минут на трёх ОС → красный по опечатке в шаге» — самая дорогая ошибка в этом
проекте, поэтому [`scripts/ci_lint.py`](scripts/ci_lint.py) разбирает workflow статически.
Каждое правило — уже случившаяся красная сборка, а не гипотеза:

| правило | что ловит | откуда взялось |
|---|---|---|
| `portability` | команда, которой нет на ОС шага (`shasum`, `apt-get`, `otool`), и GNU-диалекты (`sed -i`, `grep -P`, `stat -c`) | `shasum: command not found` на Windows-раннере: git-bash — не POSIX |
| `env-assumption` | абсолютный системный путь литералом без проверки существования | прошитый путь ICD lavapipe: пропажа файла читалась как «no suitable adapter» в движке |
| `vacuous-gate` | греп-гейт, который не доказывает, что поиск вообще работает | опечатка в пути даёт вечно зелёный гейт |
| `gate-downgrade` | `continue-on-error` на шаге, не названном best-effort | инвариант 3 спеки #12 |
| `unparsed` | шаг, у которого нет ни `uses:`, ни разобранного тела | «не разобрал» выглядело как «находок нет» |
| `arg-mangling` | MSVC-флаг слэшем (`/DWIN32`, `/EHsc`) в шаге `shell: bash` на Windows | git-bash подменяет его на `C:/Program Files/Git/DWIN32`; clang-cl жалуется на `/Fo`, флаг в диагностике не назван |

Линтер знает про `if: runner.os` и про рантайм-ветку `if [ "$RUNNER_OS" = … ]`, так что честно
защищённый вызов молчит. Осознанное исключение — комментарий `# ci-lint: allow <правило|команда>`
с причиной **минимум в три слова**: односимвольная отписка не подавляет. Перед каждым запуском
гоняется самопроверка: сломанное правило молчит ровно так же, как чистый файл, и линтер незаметно
стал бы декорацией.

## Перед push — `scripts/preflight.sh`

Всё, что можно узнать про будущий прогон CI, не запуская CI: подпись DCO на коммитах ветки →
самопроверка правил → линтер workflow → статические инварианты дерева (`scripts/tree_invariants.sh`, тот же скрипт, что и
шаги CI) → `actionlint` + `shellcheck` (severity `warning`) → `shellcheck` самих гейт-скриптов → сборка в
конфигурации CI → сборка полного набора опций → сверка `game.bundle` с исходниками → сборка gcc,
если он установлен. Этапы не останавливают друг друга: один прогон обязан выдать все находки разом.

Сверка бандла стоит после сборок, потому что сверяет их продуктом. `example_ugly_game/assets/game.bundle`
лежит в git готовым, а перепечь его ЦЕЛИКОМ негде, кроме машины владельца: текстурная секция тянет
`tint` и `basisu`. Поэтому `assetc --verify-game` перепекает секции, у которых пекарь — чистый
парсер (`input.txt`, `achievements.txt`), и сверяет их с тем, что лежит в бандле. До этого гейта
правка раскладки без перепекания проезжала молча, хотя на бандле стоят и игра-образец, и
sim-golden. Гейт несёт собственный позитивный контроль: испорченная копия таблицы обязана быть
отбита ТЕМ ЖЕ сравнением — иначе первая же опечатка в нём делает гейт вакуумно зелёным. Тот же
шаг гоняется в CI на трёх ОС.

Этап подписи стоит первым и на полсекунды: job `dco.yml` — единственный, который срабатывает
**только на pull_request**, поэтому коммит без `-s` доживает незамеченным до самого раунда, а
чинится единственным способом — `git rebase --signoff` + `--force-with-lease`, то есть
переписыванием всех SHA ветки, после чего протухают ссылки на коммиты в ADR, теле PR и dev-log.
Критерий тот же, что у job'а (подпись совпадает с автором **или** коммиттером): локально строже
значило бы отбивать то, что CI пропускает.

`tree_invariants.sh` собирает четыре греп-гейта: условная компиляция по ОС, `argv` и окружение
только через швы (инвариант 2 спеки #12) и направление зависимостей подсистем (инвариант 1 спеки
#14). Каждый держит ПОЗИТИВНЫЙ КОНТРОЛЬ: сначала утверждает, что видит то, что обязано быть
(совпадения внутри шва, ≥ 15 найденных `main`, рёбра линковки), и только потом ищет нарушение —
греп-гейт без этого зелен вакуумно после первой же опечатки в пути. CI зовёт их по одному
(`… .sh seam|argv|env|deps`), чтобы в логе было названо сломанное; preflight — все разом.

Две конфигурации, потому что набор опций меняет состав целей: предупреждение внутри выключенной
цели (imgui, miniaudio, wasm, IDE) в headless-сборке не всплывает. Локально не проверяется и
остаётся за CI: **MSVC `/W4`**, поведение Windows-раннера и lavapipe/Vulkan на Linux.

Этап «Сборка gcc» на macOS **пропускается**: у gcc нет ObjC ARC для `.mm`, а заголовки Apple SDK
написаны на блоках. Обещать его после `brew install gcc` было неверно — там он не собирает дерево
вообще.

## Аудит чужим компилятором — `scripts/tu_sweep.py`

```
python3 scripts/tu_sweep.py build-sweep      # каталог сконфигурирован ЦЕЛЕВЫМ компилятором
```

Обходит `compile_commands.json` и компилирует каждый TU по одному. Нужен там, где чужой компилятор
не собирает дерево ЦЕЛИКОМ: сборка встаёт на первой упавшей цели и не даёт сказать про остальные
ничего, хотя несобираемость обычно локальна — на macOS gcc умирает на трёх файлах из ста семидесяти.
Независимая компиляция TU это разводит. Так найден `-Wstringop-overflow` в `tools/ide/game_child.cpp`
(разыменование nullptr), которого не видел ни один раннер.

`-Werror` из команд снимается: обход — аудит, а не гейт, и он обязан выдать ВСЕ находки TU, а не
первую. Гейт остаётся у `build_check.sh`. Пропущенные файлы печатаются поимённо — «пропущено молча»
и «находок нет» с одного взгляда неразличимы (то же основание, что у правила `vacuous-gate` в
`ci_lint.py`). Не в `checks.json`: требует каталога под другой компилятор, запускается руками.

## Коммиты

Conventional commits, английский: `feat(scope): …`, `fix(ci): …`, `docs: …`.
Без AI-подписей и `Co-Authored-By`. Не коммитить код, не прошедший линтер/типы/сборку.
