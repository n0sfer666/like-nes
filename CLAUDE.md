# like-nes — правила репозитория

Контекст проекта: [`.context/`](.context/) (README, stack, architecture, conventions, specs,
decisions, notes). Читать перед началом любой задачи. Стиль кода —
[`.context/conventions.md`](.context/conventions.md).

## Ветки

| Ветка | Роль | Правила |
|---|---|---|
| `main` | Дефолтная, релизная. Отражает подтверждённое состояние движка. | Прямые коммиты **запрещены**. Только merge из PR. |
| `dev` | Рабочая: код, PoC, проверка гипотез, промежуточные коммиты. | Коммитим сюда. Может быть шумной. |

Фича-ветки (`feat/*`, `fix/*`, `poc/*`) — по желанию, от `dev`, вливаются в `dev`.
Долгоживущих параллельных веток не заводить: одна линия `dev` → `main`.

## Раунд → PR

**Раунд** = завершённая веха: закрытая спека из roadmap, отдельная вертикаль PoC,
или согласованный блок работ с зафиксированным DoD.

После **каждого раунда** — обязательно PR `dev` → `main`:

1. Проверки пройдены, CI зелёный на всех 3 ОС (`.github/workflows/ci.yml`).
2. `.claude/.verify-state.json` и `.claude/.review-state.json` — свежие, `result: pass`.
3. `gh pr create --base main --head dev` — заголовок в стиле conventional commits,
   тело: что сделано / DoD и как проверено / ссылки на спеку и ADR.
4. Merge (по умолчанию `--squash` не использовать — история раундов линейная и осмысленная,
   merge-commit сохраняет границу раунда).
5. После merge — `git checkout dev && git merge main` (синхронизация), продолжаем работу.

Промежуточные коммиты внутри раунда в `main` не попадают отдельно — только через PR раунда.

## Ручная проверка владельцем (правило 18 глобального CLAUDE.md)

Владелец гоняет живое железо сам: **macOS**, **Linux** (Nobara, evdev, X11 и Wayland) и
**Windows** (MSVC, XInput) — плюс реальные пад, мышь, трекпад, наушники. VM тут не предлагать:
половина находок этих раундов (Wayland-поверхность, знак сырой оси Y, шум покоящегося XInput)
недостижима ни на раннере, ни в виртуалке.

Артефакты этой проверки — **код задачи, а не документация «потом»**:
[`docs/owner-verification.md`](docs/owner-verification.md) (сценарии гейтов, каждый закрытый — с
баннером `Closed` и уликами), [`docs/owner-setup.txt`](docs/owner-setup.txt) (чистая машина →
прогон, с ОЖИДАЕМЫМ выводом построчно), [`docs/first-run.md`](docs/first-run.md),
[`scripts/win-dev.bat`](scripts/win-dev.bat) (обёртка, владеющая vcvars),
`scripts/owner_check.sh` и `scripts/gate8_e2e.sh`. Меняется поведение или имя цели — процедура
обновляется **в том же коммите**: устаревший сценарий не падает, он молча проверяет вчерашний код.
Так уже было — `./build/game_sidescroller` в runbook'е без шага сборки этой цели.

## Сборочный гейт (обязателен перед КАЖДЫМ коммитом)

У C++ нет отдельного тайпчекера — его роль играет компилятор, поэтому строгая сборка здесь
ровно то же, чем `tsc --noEmit` служит фронтенду. Гейт: **ноль ошибок и ноль предупреждений**.

```
bash scripts/build_check.sh      # то же, что гоняет CI и pre-commit hook
```

- Скрипт валит прогон, если сборка упала **или** в её логе есть хоть одно предупреждение.
  Проверок две, потому что `-Werror` покрывает только компилятор: драйвер (MSVC `D9xxx`),
  линкер и CMake проходят мимо него.
- **Набор целей задаётся набором опций**, поэтому по умолчанию скрипт возвращает `AUDIO_MINIAUDIO`,
  `PLUGIN_UI` и `PLUGIN_WASM` в `ON`: каталог, однажды сконфигурированный headless, иначе навсегда
  делал бы гейт зелёным по целям, которых он не собирает. Урезанный набор разрешён только тому,
  кто заявил его явно через `LIKE_NES_BUILD_SUBSET=1` — это шаг `Configure` в CI (imgui и
  miniaudio собираются там отдельными шагами, каждый в своём каталоге и одной целью через
  `LIKE_NES_BUILD_TARGETS`; wasm-гейту нужен wasmtime C-API из `deps/`, которого на раннерах нет)
  и headless-этап `preflight.sh`.
- Наш код собирается с `-Wall -Wextra -Werror` (`/W4 /WX` на MSVC) — включается
  [`cmake/warnings.cmake`](cmake/warnings.cmake) строго между зависимостями и
  `add_subdirectory` нашего кода; порядок в `CMakeLists.txt` несущий.
- Сторонние зависимости из этого исключены: с их целей **снимается уровень** предупреждений
  (`like_nes_strip_warning_level`) и дописывается `-w` — их пин на коммит есть условие
  байт-детерминизма бейка, править их нельзя. Именно снимается, а не перекрывается: `/w` поверх
  уровня даёт `Command line warning D9025 : overriding '/W4' with '/w'` — предупреждение драйвера,
  мимо `/WX`, но прямо в лог, который читает гейт. `-Wextra`/`/WX` на цели остаются и молчат:
  промотировать в ошибку после `-w` нечего.
- Вендоренный исходник рядом с нашим (`stb_impl.cpp`, `stb_vorbis_impl.c`, `miniaudio_impl.c`,
  imgui) по той же причине живёт **отдельной OBJECT-целью** (`like_nes_vendored_object`), а не
  свойством исходника: уровень предупреждений — свойство ЦЕЛИ, и снять его с одного файла внутри
  общей цели нечем. Объекты попадают в потребителя через `target_link_libraries`, наш код в той же
  цели (`wgpu_imgui.cpp`, `device.cpp`) остаётся строгим. Цель, где чужого кода целиком
  (`basis_transcoder`), глушится `like_nes_vendored_target`.
- Предупреждение **не глушится** `-Wno-…`, чтобы «пройти гейт»: либо чинится код, либо
  доказывается, что диагностика относится к стороннему TU.
- `LIKE_NES_WERROR=OFF` существует ровно для одного сценария — собрать дерево целиком и
  увидеть ВСЕ предупреждения разом, а не первое. Коммит с ним не проходит: скрипт возвращает
  флаг в `ON` и пересобирает.

- Вызов всегда через `bash`, а не по exec-биту: на Windows-раннере шелл — git-bash, и exec-бит
  из индекса он не наследует. По той же причине `.gitattributes` держит `*.sh` и `*.py` в `eol=lf`:
  скрипт, выехавший из checkout с CRLF, умирает на собственном шебанге.

**Без зелёного `build_check.sh` коммит запрещён.** Команда прописана в
[`.context/checks.json`](.context/checks.json) — её читает pre-commit hook и шаг `Build` в CI.

## Линтер workflow (обязателен перед КАЖДЫМ коммитом)

```
python3 scripts/ci_lint.py             # блокирующий гейт, в checks.json
python3 scripts/ci_lint.py --selftest  # правила проверяются сломанными фикстурами
```

Круг «push → 20+ минут на трёх ОС → красный по опечатке в шаге» — самая дорогая ошибка в этом
проекте, поэтому [`scripts/ci_lint.py`](scripts/ci_lint.py) разбирает workflow статически.
Каждое правило — уже случившаяся красная сборка, а не гипотеза:

| правило | что ловит | откуда взялось |
|---|---|---|
| `portability` | команда, которой нет на ОС шага (`shasum`, `apt-get`, `otool`), и GNU-диалекты (`sed -i`, `grep -P`, `stat -c`) | `shasum: command not found` на Windows-раннере: git-bash — не POSIX |
| `env-assumption` | абсолютный системный путь литералом без проверки существования | прошитый путь ICD lavapipe: пропажа файла читалась как «no suitable adapter» в движке |
| `vacuous-gate` | греп-гейт, который не доказывает, что поиск вообще работает | опечатка в пути даёт вечно зелёный гейт |
| `gate-downgrade` | `continue-on-error` на шаге, не названном best-effort | инвариант 3 спеки #12 |
| `unparsed` | шаг, у которого нет ни `uses:`, ни разобранного тела | «не разобрал» выглядело как «находок нет» |
| `arg-mangling` | MSVC-флаг слэшем (`/DWIN32`, `/EHsc`) в шаге `shell: bash` на Windows | git-bash подменяет его на `C:/Program Files/Git/DWIN32`; clang-cl жалуется на `/Fo`, флаг в диагностике не назван |
| `list-drift` | руками написанный список исходников или целей в шаге разъехался со своим эталоном | `query_index.cpp` попал в цель CMake и не попал в `LIB=` санитайзерного шага: `undefined reference` на линковке при всех зелёных локальных гейтах |

Сверка списков (`list-drift`) ОПТ-ИН: список объявляет эталон комментарием прямо над собой —
`# ci-lint: mirrors-target <CMakeLists.txt> <цель>` (список обязан содержать все исходники цели и
не нести из её каталога ничего лишнего) или `# ci-lint: mirrors-var <файл.sh> <ПЕРЕМЕННАЯ>`
(равенство множеств, так связаны цели Debug-шага и `STATE_TARGETS` в `check_debug_golden.sh`), или
`# ci-lint: mirrors-group <имя>` — равенство копий МЕЖДУ СОБОЙ, когда внешнего эталона у списка
нет. Третью форму потребовал список платформенного шва: он перечисляет posix-ветку, то есть
подмножество цели, `mirrors-target` отбивал бы его ложно, а копий у него три (`PLAT_FS` в двух
шагах, `TILES_FS` в третьем) — и до 2026-08-24 их не сверял никто, из-за чего одна отстала на два
файла и дала `undefined reference to platform::root_len` на единственном раннере, где шаг вообще
запускается. Группа из ОДНОГО списка — тоже находка: вторую копию переименовали, и равенство,
которому не с чем сравнивать, зелено вакуумно. Общего
правила «список обязан совпадать с каталогом» не бывает: соседний `CHAR=` в том же шаге
перечисляет четыре файла из восьми осознанно, и равенство отбивало бы его ложно. Ноль маркеров в
дереве — находка, а не молчание: переехавший формат комментария читается как чистый прогон.

Линтер знает про `if: runner.os` и про рантайм-ветку `if [ "$RUNNER_OS" = … ]`, так что честно
защищённый вызов молчит. Осознанное исключение — комментарий `# ci-lint: allow <правило|команда>`
с причиной **минимум в три слова**: односимвольная отписка не подавляет. Перед каждым запуском
гоняется самопроверка: сломанное правило молчит ровно так же, как чистый файл, и линтер незаметно
стал бы декорацией.

## Бюджет длины файлов (обязателен перед КАЖДЫМ коммитом)

```
python3 scripts/line_budget.py             # блокирующий гейт, в checks.json
python3 scripts/line_budget.py --selftest  # правила проверяются сломанными фикстурами
```

Правило 5 (мягкие 200 строк, жёсткие 250) до этого раунда жило одним абзацем в глобальном
`CLAUDE.md`, и результат виден по дереву: за мягкий лимит перевалили тринадцать файлов, а сам
`scripts/preflight.sh` дорос до 297 при жёстком пороге 250. **Лимит, который не проверяет никто,
лимитом не является**, поэтому он стал механическим.

- Выше 200 строк файл живёт **только с записью** в [`scripts/line_budget_allow.py`](scripts/line_budget_allow.py)
  (пороги и закрытый список видов обоснования — рядом, в
  [`scripts/line_budget_rules.py`](scripts/line_budget_rules.py): таблица причин 2026-09-03 сама
  перевалила жёсткий лимит, а он причиной не выкупается ни для кого, включая её). Сама таблица
  разрешений перевалила его следом и разрезана по ПРЕДМЕТУ на две половины —
  [`line_budget_allow_tools.py`](scripts/line_budget_allow_tools.py) (гейты, обёртки, файлы сборки)
  и [`line_budget_allow_code.py`](scripts/line_budget_allow_code.py) (движок и игра-образец), —
  а `line_budget_allow.py` их сливает и **валит прогон на записи, попавшей в обе**: молчаливая
  подмена потолка читалась бы как выписанное разрешение. Запись такова:
  потолок числом, вид обоснования из закрытого списка (`data` — неделимый массив данных, `text` —
  читаемое сверху вниз, `single` — одна ответственность с длинной линейной логикой) и причина
  словами, не короче трёх. Не подошло ни одно обоснование — файл идёт в разбиение, а не в таблицу.
- Выше 250 не живёт вовсе: **жёсткий порог причиной не выкупается**. Упёрся и декомпозиция кажется
  вредной — остановиться и спросить.
- Потолок в записи **персональный**, а не «разрешено навсегда»: файл, доросший до следующей строки
  сверх выписанного, проходит решение заново. Иначе allowlist работает ровно как его отсутствие,
  только медленнее — именно так `preflight.sh` и добрался до 297.
- Протухшие записи гейт ловит сам: файл удалён/переименован, файл ужался обратно под 200, потолок
  выписан выше жёсткого — всё это находки, а не молчание.
- **Область — авторский код**: `.c/.cc/.cpp/.h/.hpp/.mm`, `.bat`, `.cmake`, `.py`, `.sh` и
  `CMakeLists.txt`. `.md`, `.txt` и workflow-YAML сюда не входят по самому тексту правила 5 (текст,
  читаемый целиком сверху вниз), поэтому `ci.yml` на 1200 строк молчит не по недосмотру гейта.
  Расширить список — отдельное решение, а не правка фильтра.
- Вендоренный исходник (`stb_impl.cpp`, `stb_vorbis_impl.c`, `miniaudio_impl.c`) исключён по тому же
  основанию, что и уровень предупреждений в `cmake/warnings.cmake`: его пин на коммит есть условие
  байт-детерминизма бейка, резать его нам нечем. Список вендоренного — единственный бесследный
  обход гейта, поэтому каждая его строка обязана указывать на живой файл: висящая запись молча
  погасила бы будущий файл с тем же путём, и это отдельная находка.
- Обход берёт файлы у git **вместе с ненаписанными в индекс** (`--cached --others
  --exclude-standard`): иначе свежесозданный файл на четыреста строк проходил бы локальный прогон
  молча и падал бы только на коммит-гейте, когда под него уже написан код.
- Позитивный контроль двойной: самопроверка правил сломанными фикстурами перед каждым прогоном
  (та же дисциплина, что у `ci_lint.py`) плюс утверждение, что обход видит собственный исходник —
  гейт, не нашедший `scripts/line_budget.py`, печатает `FAIL`, а не «находок нет».

## Кодировка на швах процесса — `scripts/check_py_utf8.py`

```
python3 scripts/check_py_utf8.py             # блокирующий гейт, в checks.json
python3 scripts/check_py_utf8.py --selftest  # правила проверяются сломанными фикстурами
```

Python берёт кодировку stdout у ЛОКАЛИ, и на windows-раннере GitHub это `cp1252`. Русская строка
там не «портится»: `print` падает `UnicodeEncodeError`, скрипт возвращает **ненулевой код на
исправном дереве**, и «гейт нашёл нарушение» становится неотличимо от «гейт не смог напечатать
вердикт». Ровно это и случилось 2026-09-06 в прогоне `ee75955`: четыре опорных `pass` самопроверки
врезок отдали код 1 при исправных фикстурах, а сам набор умер трейсбеком в собственном `print`.

- **Мера была и до раунда — ТРЕМЯ копиями трёх строк** внутри `ci_lint.py`, `line_budget.py` и
  `ascii_output_check.py`, и четыре новых скрипта её просто не взяли. Список без эталона молчит:
  то же основание, по которому заведены правило `list-drift` в `ci_lint.py` и сверка копий списка
  корней. Теперь сущность одна — [`scripts/py_utf8.py`](scripts/py_utf8.py), — а гейт требует её
  вызова у каждого, кому она нужна.
- **Правил ДВА, потому что у шва процесса две стороны.** Первое — про НАШ вывод, второе — про
  вывод ДОЧЕРНЕГО процесса: `subprocess.run(..., text=True)` без `encoding` декодирует его той же
  локалью, и поток-читатель умирает `UnicodeDecodeError`. Второе правило заведено потому, что
  прогон `3381a95` покраснел на том же шаге и том же раннере уже ПОСЛЕ того, как первое закрыло
  запись, — и с тем же исходом: все двадцать порч самопроверки врезок «прошли», получив ненулевой
  код от чужого отказа, а упал единственный опорный `pass`. Область второго правила — ВСЕ файлы
  `.py`, а не кандидаты: шебанг отделяет точку входа только у своего вывода, чужой декодирует тот,
  кто его читает. Имя модуля берётся из ИМПОРТА — прибитая строкой `subprocess` делала бы правило
  обходимым через `import subprocess as sp`, и это доказано порчей.
- **Кандидат первого правила — ШЕБАНГ плюс не-ASCII в СТРОКОВОМ ЛИТЕРАЛЕ.** Шебанг отделяет точку входа от модуля:
  импортируемому поток настраивает тот, кто его запустил, и требовать вызова у библиотеки значило бы
  делать настройку побочным эффектом импорта. Литералы, а не файл целиком: комментарии по-русски —
  стиль репозитория, и до вывода они не доезжают; без этого правило выродилось бы в «зови всегда».
- **Вызов ищется `ast`, а не грепом.** `py_utf8.enable()`, написанное в комментарии, обязано
  отбиваться наравне с отсутствующим, и требуются ОБА факта — импорт и вызов: каждый порознь
  оставляет скрипт с локальной кодировкой. То же основание, по которому `ci_lint.py` разбирает
  workflow, а не грепает его.
- **Обход берёт файлы у git вместе с ненаписанными в индекс** (`--cached --others
  --exclude-standard`): иначе свежесозданный скрипт проходил бы локальный прогон молча и падал бы
  только на коммит-гейте.
- **Ноль кандидатов или ноль текстовых вызовов — ОТКАЗ**, а не «находок нет»: обход,
  промахнувшийся мимо дерева, обязан отличаться от чистого прогона. Плюс утверждение, что обход видит собственный исходник — гейт, не
  нашедший `scripts/check_py_utf8.py`, описывает не то дерево, по которому его запустили. Тот же
  класс, что правило `vacuous-gate` в `ci_lint.py`.
- **Фикстура — настоящий git-репозиторий**, а не `os.walk`: обход берёт файлы у git, и подмена
  механизма означала бы, что набор проверяет не то, чем гейт пользуется на дереве. Контролей
  семнадцать: 5 опорных `pass` (кандидат зовёт; модуль без шебанга освобождён; шебанг с
  ASCII-литералами вызова не требует; модуль без шебанга задаёт кодировку; байтовый вызов кодировки
  не требует — без него второе правило неотличимо от «`encoding` обязателен всегда»), 11 отбитых
  порч (не зовёт вовсе; вызов написан в комментарии; импорт без вызова; вызов без импорта; дерево
  без кандидатов; собственный исходник скрыт от обхода `.gitignore`; текстовый вызов без
  `encoding`; старая форма `universal_newlines`; обход через алиас импорта; нарушение в самой точке
  входа; дерево без единого текстового вызова) и прогон на настоящем дереве. Исправный текстовый
  вызов лежит в КАЖДОЙ фикстуре: без него опорные `pass` первого правила падали бы по чужой
  причине — отказу второго.
- **Гейт идёт на одной ОС, самопроверка — на всех трёх**: дерево одно, а предмет самопроверки —
  переносимость самих утверждений. Граница та же, что у гейта документации, и именно самопроверка
  на Windows этот дефект и вскрыла.

## Выбор bash на швах процесса — `scripts/posix_bash.py`

```
python3 scripts/posix_bash_selftest.py   # заглушка-мост в PATH: правила на сломанных кандидатах
```

Python, зовущий шелл по ИМЕНИ, получает первый `bash` из PATH, а на windows-раннере GitHub первым
там стоит `C:\Windows\System32\bash.exe` — **мост в WSL, а не шелл**. Без установленного
дистрибутива он печатает своё сообщение в UTF-16 и возвращает 1, и 2026-09-06 самопроверка врезок
прочитала одиннадцать строк «Windows Subsystem for Linux has no installed distributions» как
одиннадцать документов дерева: отказ выглядел оборвавшимся обходом `docs/`, которого не было вовсе.
Диагноз держался ровно до того прогона, где контроль напечатал сам полученный список.

- **Кандидат выбирается ОТВЕТОМ, а не наличием имени в PATH** — то же решение, по которому
  `check_release_container.sh` выбирает движок ответом `info`, а не наличием бинаря. Перебираются
  ВСЕ `bash` из PATH (под Windows — по PATHEXT-набору имён), первый ответивший пробой и берётся.
- **Судится вывод ВМЕСТЕ с кодом возврата.** Мост возвращает единицу и печатает своё; «код ноль»
  порознь принял бы за шелл всё, что молча завершается, а «напечатал слово» порознь — то, что
  печатает и падает. Обе половины держат свои кейсы.
- **Проба спрашивает про файловую систему ХОСТА**, а не только про умение исполнить `-c`: мост с
  УСТАНОВЛЕННЫМ дистрибутивом `printf` отработает и вернёт мусор на windows-путь, который ему потом
  отдадут в `cwd`. Файл-маркер лежит в каталоге хоста, и linux-сторона моста его не видит.
- **Не ответил ни один — ОТКАЗ со списком проверенных И ПРИЧИН**, а не молчаливый откат на строку
  `"bash"`: откат вернул бы ровно тот мост, ради которого модуль и заведён, а отказ без причин по
  кандидатам восстанавливается на чужом раннере ровно ничем — неверный диагноз этой же порчи стоил
  четырёх прогонов CI. Поэтому и порчи требуют ПОДСТРОКИ в тексте отказа, а не только его факта.
- **Заглушка, которую перебор не ВИДИТ или не ЗАПУСКАЕТ, читается как «выбор её отбил»**: кейс
  «в PATH только мост» отказал бы тогда по причине соседнего — «ни одного кандидата» — или по
  невозможности запуска, ничего не сказав об ответе. Поэтому и видимость подставленного кандидата,
  и его запуск (честная заглушка, печатающая слово пробы, обязана быть ВЫБРАНА) утверждаются
  отдельно, до порч. Контролей девять: 5 опорных `pass` и 4 отбитых кандидата.
- Самопроверка идёт **на всех трёх ОС** и ПЕРЕД набором врезок, который этим выбором пользуется:
  сам гейт видит лишь исход выбора, а порча живёт только здесь. Ветвление по ОС внутри фикстуры
  предметно и неизбежно: на Windows исполняемым кандидатом может быть только файл из PATHEXT —
  настоящий PE фикстуре взять негде.

## Документация en/ru — `scripts/check_docs.sh`

```
bash scripts/check_docs.sh                   # блокирующий гейт, в checks.json
bash scripts/check_docs_selftest.sh          # пара языков: правила на сломанных фикстурах
bash scripts/check_docs_content_selftest.sh  # содержимое документа: ссылки и лицензия
bash scripts/docs_stamp.sh docs/ru/<путь>    # проштамповать ОДИН перевод суммой его источника
```

**en — источник истины, ru — перевод** (решение 1 спеки #19), и расхождение между ними обязано быть
находкой, а не поводом для рассуждений. Документация ломается правкой ТЕКСТА, а не сборкой, поэтому
гейт стоит в `checks.json` рядом с линтером workflow и бюджетом длины: ни сборки, ни сети ему не
нужно.

- **Свежесть перевода доказывается ШТАМПОМ СУММЫ ИСТОЧНИКА** — `<!-- en-sha256: <64hex> -->` первой
  строкой ru-файла. HTML-комментарием, а не frontmatter'ом, потому что документ обязан читаться
  прямо на хостинге репозитория (решение 2 спеки), а frontmatter там показывается таблицей поверх
  текста. Сумму берёт `sha256_of` из `release_lib.sh` — своя копия разъехалась бы с релизной в
  первый же переезд между `shasum` и `sha256sum`, а те уже разведены там по ОС.
- **Штамповка — акт подтверждения, как подпись DCO**, и штампуется ОДИН названный файл. Механически
  отличить перевод от штампа нельзя, поэтому массовая штамповка дерева была бы кнопкой «сделать
  зелёным», и первое же отставание уехало бы к читателю.
- **Критичные разделы отстают ОШИБКОЙ, прочие — предупреждением** (`docs_pair_critical`):
  `README.ru.md` и `docs/ru/getting-started/**` — то, по чему человек ставит движок, и устаревшая
  инструкция установки не «немного не та», она не работает. Обе половины различия держат свои
  кейсы: некритичное отставание обязано ПРОХОДИТЬ, иначе «ошибка на всём подряд» выглядела бы так же.
- **Пары «источник → перевод» и список проверяемых файлов ВЫВОДЯТСЯ обходом** (`docs_pairs`,
  `docs_all_files`) — одним местом на гейт, штамповщик и все пять утверждений. Раздел, добавленный
  в `docs/`, иначе молча остался бы непроверенным: ровно `list-drift`.
- **Ссылка разрешается ПУТЁМ, а не поиском подстроки.** `../../ru/getting-started/build.md` и
  `../ru/getting-started/build.md` отличаются одним сегментом, имя пары есть в обеих, и открывается
  ровно одна. Нормализатор свой, на awk: `realpath` на macOS без coreutils не умеет несуществующих
  путей, а битую ссылку надо НАЗВАТЬ, а не упасть на ней.
- **Переключатель языка ищется в ШАПКЕ** (первые 12 строк): ссылка, до которой читатель доскроллит
  на двадцатой строке, переключателем не является. Фикстура под это обязана ССЫЛКУ СОХРАНИТЬ и лишь
  опустить её ниже шапки — первая её версия брала тело со второй строки, то есть выбрасывала
  переключатель вовсе и падала по причине СОСЕДНЕГО кейса «документ не ссылается на свою пару»,
  ничего не доказывая о границе шапки. Теперь порча утверждает, что испорченный файл ссылку несёт.
- **Якорь ссылки ведёт в существующий заголовок.** Без этого утверждения гейт 4 закрыт наполовину:
  `prerequisites.md#windows-which-shell` остаётся зелёной после переименования заголовка — то есть
  ровно тогда, когда у читателя она и ломается. Slug считается по правилу хостинга (нижний регистр,
  пунктуация выброшена, пробелы стали дефисами, кириллица НЕ транслитерируется), а `#` внутри
  ```-блока заголовком не считается: комментарий шелла, принятый за заголовок, делал бы живым якорь,
  которого у документа нет. Читается slug и НАПРЯМУЮ, отдельным кейсом: в скобочном выражении BSD
  sed `[ \t]` есть «пробел, слэш или буква t», из-за чего `Prerequisites` давал `prerequisi-es`, —
  а на дереве такая порча остаётся зелёной на любой ссылке, которая её повторяет.
- **Заголовки цели забираются в ПЕРЕМЕННУЮ, а не текут в `grep -q` пайпом.** Под `pipefail` ранний
  выход grep'а по первому совпадению рвёт пайп, писатель слева получает SIGPIPE, и код пайплайна
  становится ненулевым РОВНО НА СОВПАДЕНИИ: гейт печатал FAIL на живом якоре, а тот же вызов из
  шелла без `pipefail` — OK. Тот же класс, что «импорты до фильтра» в `assert_redist_expected_named`.
- **Ссылка, ушедшая выше корня дерева, проверкой существования НЕ ловится**: пустой путь делает
  `[ -e "$root/" ]` истинным всегда, а сохранённые нормализатором `..` уводят проверку в каталог над
  репозиторием, где файл с таким именем может и найтись. И то и другое — «ссылка жива» про то, чего
  в дереве нет.
- **Тексты лицензий проверяются ОДИН раз, а не внутри цикла по двум README**: одна пустая лицензия
  печаталась двумя строками, и читатель прогона считал бы две поломки там, где она одна.
- **Пустое равно пустому — отказ, а не «нарушений нет»**: ноль документов, ноль пар, ноль ссылок,
  лицензионная часть, проверенная не в обоих README. Тот же класс, что правило `vacuous-gate` в
  `ci_lint.py`, и здесь он опаснее обычного: гейт описывает дерево, которое сам же и обходит.
- **Лицензионная часть проверяется в ОБОИХ README** (гейт 7 спеки): свободный движок, чьё README не
  называет лицензию, юридически читается как «все права защищены» — то есть заявление спеки #9
  существует только в файлах, которых читатель не открывает. Перевод, потерявший эту часть, врёт
  ровно так же. Сверх имени лицензии требуются ССЫЛКИ на тексты и непустые сами тексты: читателю,
  которому назвали лицензию и открыли пустоту, не дали ничего.
- Самопроверок **две, граница по ПРЕДМЕТУ**, и вторая зовётся ВНЕШНЕЙ командой, чтобы в логе стояло
  имя упавшего набора: `check_docs_selftest.sh` ломает СВЯЗЬ двух языков (5 опорных `pass`, 14
  отбитых порч), `check_docs_content_selftest.sh` — содержимое одного документа (6 и 14). Фикстурные
  деревья обоим строит ОДНА фабрика (`docs_fixture_lib.sh`), а штампы в них ставит НАСТОЯЩИЙ
  `docs_stamp.sh`: собери набор штамп сам — и «гейт отбил отставший перевод» проверялось бы на
  дереве иного устройства, чем то, которое штампует человек. Поэтому у штамповщика разведены
  ШТАМПУЕМОЕ ДЕРЕВО (`DOCS_ROOT`) и каталог, откуда грузятся библиотеки.
- **Якорь на настоящем дереве стоит в обоих наборах.** Фикстура игрушечная по построению, и
  утверждение, случайно заточенное под неё, выглядело бы здоровым ровно до первого прогона гейта.
- Первый же прогон самопроверки нашёл дефект, которого гейт не видел и увидеть не мог: в ветке
  «ссылка ведёт в никуда» подстановка `$link` упиралась в кавычку-ёлочку, bash в UTF-8 локали брал
  её первый байт частью имени переменной, и вместо НАЗВАННОЙ битой ссылки ветка падала
  `unbound variable`. Гоняется она только на сломанном дереве — то есть без порчи о ней не было
  известно ничего.
- В CI **гейт идёт на одной ОС** (дерево одно), а **самопроверка на всех трёх**: предмет у неё
  другой — переносимость самих утверждений (`sha256_of`, `sed -i` в git-bash, `find`, порядок
  `sort` под разными локалями).

## Код в документации — `check_docs_examples.sh` и `check_docs_snippets.sh`

```
bash scripts/check_docs_examples.sh [каталог]           # гейт 2: примеры собраны и печатают голдены
bash scripts/check_docs_examples_selftest.sh [каталог]  # правила на сломанных фикстурах
bash scripts/check_docs_snippets.sh                     # гейт 3: врезки = помеченные куски примеров
python3 scripts/check_docs_snippets_selftest.py         # правила на сломанных фикстурах
python3 scripts/docs_snippet_sync.py                    # переписать врезки по источникам
```

**«Примерного кода» в документации нет** (решение 5 спеки #19): всё, что показано читателю,
компилируется и запускается здесь же. Источник живёт в `docs/examples/*.cpp` и обрамляется
`// docs:begin(<имя>)` / `// docs:end(<имя>)`, документ вставляет кусок между
`<!-- snippet: docs/examples/<файл>#<имя> -->` и `<!-- /snippet -->`.

- **Гейтов два, и один другого не заменяет.** Врезки сверяют ТЕКСТ с ТЕКСТОМ и ничего не говорят о
  том, что источник собирается; примеры сверяют текст с ПОВЕДЕНИЕМ и ничего не говорят о том, что в
  документе показан именно он. «Показанный код работает» есть конъюнкция двух утверждений.
- **Пропавший маркер — ОШИБКА, а не пустая врезка.** Имя, которого в источнике нет, — самый
  вероятный исход переименования, и «показать нечего» выглядело бы честным пустым блоком. Ноль
  врезок в дереве, ноль примеров, ноль пар — отказ: тот же класс, что `vacuous-gate`.
- **У каждого примера свой голден** (`<имя>.out`): цель `doc_example_<имя>` обязана вернуть ноль и
  напечатать ровно его. Пара `.cpp` ↔ `.out` сверяется РАВЕНСТВОМ МНОЖЕСТВ — голден, переживший свой
  пример, есть находка. Возврат каретки снимается: на Windows stdout идёт текстовым режимом, и
  голден на LF расходился бы там на каждой строке. Снимается он с ОБЕИХ сторон сравнения: на
  windows-раннере `core.autocrlf=true` выводит из checkout с CRLF и сам голден, то есть `diff`
  краснел бы на КАЖДОЙ строке ровно на той ОС, ради которой мера и заведена (пин `*.out text eol=lf`
  в `.gitattributes` — второй замок, а не замена ей). Сравниваются ФАЙЛЫ, а не подстановки: `$( … )`
  съедает хвостовые переводы строк с обеих сторон, и пример, потерявший последнюю строку вывода,
  сходился бы с голденом.
- **Список целей выводится `file(GLOB CONFIGURE_DEPENDS)`**, имена примеров и голденов — обходом
  (`docs_examples_names`): рукописный разъехался бы с каталогом молча, ровно `list-drift`.
- **Каталог сборки гейт НЕ создаёт** — его передаёт вызывающий (`build-full` в preflight, `build` в
  CI), и промах каталога есть отказ, а не пропуск: то же решение, что у `check_goldens.sh`.
  Самопроверка берёт тот же каталог тем же аргументом, иначе её единственный кейс на настоящих
  бинарях молча пропускался бы в CI.
- **Примеры гоняются на ТРЁХ ОС, врезки — на одной.** Для примеров платформа и есть предмет: тот,
  что печатает на macOS и Windows разное, — врезка, врущая части читателей. Врезкам сборки не нужно,
  дерево одно; они стоят в `checks.json` и группе правил дерева, примеры — в preflight после сборок.
- **Комментарии в `docs/examples/` — английские**, единственное исключение из конвенции репозитория
  (`.context/conventions.md`): эти файлы читатель видит целиком, а источник истины документации
  английский.
- `docs/examples` — полноправный корень дерева: он стоит в `ROOTS_CODE`/`ROOTS` инвариантов
  (`tree_invariants.sh`) и в `ascii_output_check.py`, и это доказано порчами — кириллица в литерале
  валит ASCII-гейт, обход шва `platform::Args` валит argv-гейт.
- **Врезка без маркера — ошибка, и маркер без врезки тоже**: множество имён `docs:begin` во всех
  источниках сверяется с множеством употреблённых врезок. Направление у гейта было одно, и
  переименованная врезка оставляла в примере мёртвый маркер, молча описывающий вчерашний текст, —
  ровно тот класс, что стережёт `assert_examples_paired` у соседа («голден, переживший свой
  пример»). Файл, показанный ЦЕЛИКОМ, освобождает все свои маркеры.
- **Голый фенс языка КОДА вне врезки — находка.** Без этого утверждения решение 5 держалось
  дисциплиной: гейт сверял врезки с источниками и молчал про блок, написанный руками рядом. Список
  языков кода ЗАКРЫТ (`cpp`, `c`, `cc`, `h`, `hpp`) — `sh`, `text`, `powershell` и `bat` показывают
  команду и вывод, компилируемого источника у них не бывает, и требовать его значило бы запретить
  документации показывать вызов. Опорный `pass` на голом ` ```sh ` стоит рядом с порчей: без него
  утверждение неотличимо от «запрещены все фенсы».
- **Принадлежность каталогу проверяется ПОСЛЕ нормализации пути**: `docs/examples/../../engine/…`
  начинается с нужного префикса и открывает файл, про который никто не утверждает, что он
  собирается, — тот же класс, что ссылка, ушедшая выше корня дерева, в гейте документации. Маркеры
  источника по той же причине разбираются ВСЕГДА, а не только для именованной врезки: незакрытый
  `docs:begin` в файле, показанном целиком, забирает тело до конца файла.
- Позитивный контроль: **14 контролей у примеров** (3 опорных `pass` на фикстурах, 2 на настоящем
  дереве, 9 отбитых порч) и **24 у врезок** (5 и 19). Фикстурный бинарь — скрипт-заглушка: предмет
  набора в том, что утверждения умеют падать, а не в компиляторе; настоящую сборку проверяет сам
  гейт на дереве.

## Инструкция установки на чистой машине — `scripts/check_docs_start.sh`

```
bash scripts/check_docs_start.sh                     # блокирующий гейт разметки, в checks.json
bash scripts/check_docs_start.sh --live              # прогон на голой Ubuntu, нужен движок контейнеров
bash scripts/check_docs_start_selftest.sh            # текст документа: правила на сломанных фикстурах
bash scripts/check_docs_start_run_selftest.sh        # прогон: база, монтирование, заглушка клона
```

Гейт 5 спеки #19: **чистая машина проходит `getting-started` ДОСЛОВНО** и получает то, что документ
обещает. `check_docs.sh` держит пару языков, ссылки и якоря и не говорит о командах НИЧЕГО:
страница бывает идеально зеркальной, идеально слинкованной и неверной в каждой команде.

- **Команды берутся ИЗ документа**, а не пишутся рядом с ним: рукописная копия разъехалась бы с
  текстом молча и проверяла бы вчерашнюю инструкцию — ровно `list-drift`. Разметка —
  `<!-- container: <роль>[ <ожидание>] -->` перед фенсом, роли ЗАКРЫТЫ (`install`, `build`, `run`,
  `check`), и **порядок прогона задают РОЛИ, а не имена файлов**: алфавит поставил бы `build.md`
  впереди `prerequisites.md`, то есть сборку впереди установки.
- **Строка, ПОХОЖАЯ на маркер, но не той формы, — находка.** Незнакомая роль отбивалась и раньше, а
  лишний пробел или заглавная буква молча выкидывали блок из прогона: покрытие сжималось при
  зелёном гейте. Отсутствие хоть одной из фаз — отказ по той же причине.
- **Ожидание живёт в разметке, но обязано быть обещано ЧИТАТЕЛЮ** — и в источнике, и в переводе:
  иначе разметка вправе требовать любой строки, и «гейт проверил обещание документа» держалось бы
  тем, что писавший маркер не ошибся. Строки самой разметки из поиска выброшены, иначе поиск
  находил бы ожидание всегда. У блока роли `check` ожидание ОБЯЗАТЕЛЬНО: без него блок узнавал бы о
  своей беде в `--live`, через четверть часа и после полной сборки.
- **Текст забирается в ПЕРЕМЕННУЮ, а не течёт в `grep -q` пайпом**: под `pipefail` ранний выход
  grep'а рвёт пайп писателю, и код пайплайна ненулевой РОВНО НА СОВПАДЕНИИ — блокирующий гейт
  объявлял бы нарушение на исправном дереве. Тот же класс, что «заголовки цели» в `check_docs.sh`;
  виден только на ДЛИННОМ документе, поэтому опорный `pass` набора дописывает в фикстуру 20000
  строк, а рядом стоит порча, возвращающая пайп.
- **База — ГОЛАЯ и пиннута дайджестом**, и берётся тем же `container_base_pin`, что у релизной
  вертикали: релизный образ ставит пакеты сам, и прогон на нём был бы зелёным при документе,
  забывшем половину списка. Дерево монтируется `:ro`, а **клон подменяется копией дерева** — иначе
  прогон судил бы то, что уже лежит на GitHub, а не то, что коммитят. Улика подмены — отсутствие
  `.git` в каталоге прогона.
- **Заглушка клона ЗАПУСКАЕТСЯ, а не только грепается.** Живой прогон нашёл ровно то, чего греп не
  видит: заглушка звала внутри себя `git ls-files`, PATH вёл в неё же, каталог оставался пустым — и
  сборка падала «нет CMakeLists.txt» на исправном документе. Вырезанная чистка PATH до защиты от
  самонахождения гейт не роняла, а ВЕШАЛА — на каждом коммите, потому что гейт стоит в
  `checks.json`. Подменяется ТОЛЬКО адрес документа: чужой клон уходит настоящему git (иначе
  FetchContent получал копию нашего дерева вместо glfw), флаги перед адресом разбираются, `sudo`
  исполняет команду.
- **awk прогона режет поля подстановками, а не интервалом.** `sub(/^([^\t]*\t){3}/, …)` на macOS
  работает, а на голой Ubuntu awk — это mawk, интервалов у него нет: подстановка молча не
  срабатывает, `git clone` среди команд не находится, и живой прогон обвиняет документ в дефекте
  раннера. Держит это `assert_start_awk_portable` (`docs_start_awk_lib.sh`), и список файлов он
  обходит РЕКУРСИВНО, в обеих формах подключения: библиотека, подключённая из библиотеки,
  исполняется на чистой машине наравне с прочими. Найденные библиотеки считаются ОТДЕЛЬНЫМ
  счётчиком — общий (вместе с раннером) не бывает нулевым по построению, то есть обход,
  промахнувшийся мимо всех подключений, объявлял бы дерево чистым. Порча к утверждению возвращает
  интервал: на машине владельца дефект неразличим по построению. Команды при этом забираются в
  ПЕРЕМЕННУЮ: пайп в `awk … exit` под `pipefail` отдал бы ненулевой код ровно на совпадении.
- **Признак запуска ОДИН на обе фазы прогона** (`start_run_cmd`): фаза A выбрасывает ровно то, что
  фаза B запускает, и две копии признака разъехались бы молча. Блок ролей `run`/`check`, в котором
  запуска из дерева не нашлось, есть ОТКАЗ, а не пропуск: `cd build && ./editor_shell` иначе выпадал
  бы из фазы B, и продукт, который документ обещает, не осматривал бы никто. Команда исполняется
  ЦЕЛИКОМ, с аргументами документа: `./build/editor_shell --gate6` без флага — другой прогон с
  другим выводом. Под `timeout`: продукт, ждущий окна или ввода, держал бы `--live` до дедлайна, а
  висящий гейт читают как «ещё считает». Код возврата забирается через `|| rc=$?`, а не из `$?`
  внутри `if ! …` — там он равен нулю, и ветка таймаута не сработала бы никогда.
- **Греп по нашим скриптам идёт по коду со снятыми комментариями** (`start_code`): слово в
  комментарии объявляет меру существующей там, где её нет, — тем и был вакуумно-зелёным
  `assert_ci_no_second_packer`.
- Наборов **два, граница по предмету**, и второй зовётся ВНЕШНЕЙ командой, чтобы в логе стояло имя
  упавшего: `check_docs_start_selftest.sh` ломает ТЕКСТ документа (3 опорных `pass`, 18 отбитых
  порч), `check_docs_start_run_selftest.sh` — то, чем текст исполняется (1 и 21). Имя набора стоит в
  КАЖДОЙ строке, а не только в вердикте: оснастка общая, и «упало что-то из сорока» не говорит, в
  каком файле искать порчу. Оснастка у них
  общая (`docs_start_selftest_lib.sh`), деревья строит одна фабрика: собери каждый свою копию
  правил — и «утверждение отбило подмену» проверялось бы на деревьях разного устройства. Список
  библиотек фикстура и проверка определённости выводят ИЗ ГЕЙТА.
- **В CI гейт стоит ОТДЕЛЬНЫМ шагом на одной ОС** (дерево одно), **самопроверка — на всех трёх**:
  предмет у неё переносимость самих утверждений. Охранник шага при этом не значит, что на прочих ОС
  правила не гоняются: опорный кейс самопроверки прогоняет гейт по НАСТОЯЩЕМУ дереву, и делает это
  везде — иначе позитивный контроль на двух ОС из трёх подтверждал бы только игрушечные фикстуры. `--live` в CI нет: движка контейнеров на раннере нет, и прогон
  идёт с машины владельца — он же шаг 0 §17 `docs/owner-verification.md`. Субъективная половина
  (окно редактора, играющая игра, hot-reload) и обе прочие ОС остаются владельцу: правило 18.

## Список ручных гейтов — `scripts/check_owner_gates.sh`

```
bash scripts/check_owner_gates.sh            # блокирующий гейт, в checks.json
bash scripts/check_owner_gates_selftest.sh   # правила на сломанных фикстурах
```

Правило 18 отдаёт владельцу то, чего не проверить из кода, и до этого гейта список этой половины
жил **тремя рукописными копиями одного факта**: перечнем в `scripts/owner_check.sh`, таблицей шапки
`docs/owner-verification.md` и числами её вводного абзаца. Разъехались все три — перечень звал гейт
9 спеки #17 открытым **четыре дня после закрытия** и не называл шести открытых вовсе, таблица несла
12 строк на 18 гейтов, а вводный абзац — числа, неверные оба. Ровно `list-drift` из `ci_lint.py`,
только эталон у списка **есть**: сам документ.

- **Статус живёт МЕТКОЙ под заголовком раздела** — `<!-- gate: open | <что делать> -->` или
  `<!-- gate: closed <дата> -->`. HTML-комментарием, по тому же основанию, что и штамп свежести
  перевода: документ обязан читаться прямо на хостинге репозитория, а метка читателю не
  показывается. Разметка в документации у нас уже есть (`<!-- container: <роль> -->`,
  `<!-- en-sha256: … -->`), и это та же дисциплина, а не новый механизм.
- **ДЕЙСТВИЕ владельца живёт в метке открытого, и пустым быть не может.** Первая версия перечня
  печатала адрес — «#17 гейт 2 ОТКРЫТ (§8 руководства)», — то есть отправляла владельца искать, что
  там делать, в документе на две с половиной тысячи строк. Правило 18 держит процедуру частью
  задачи, а не документацией «потом», поэтому заголовок раздела говорит КУДА идти, а метка — ЧТО
  там делать, и открытый без действия валит гейт.
- **Метка и БАННЕР `> **Closed <дата>**` сверяются между собой.** Дифф, убравший три рукописные
  копии одного факта, завёл четвёртую: метка машинная, баннер человеческий, и метка `open` над
  разделом с «Closed …» убирает гейт из перечня владельца ровно тогда, когда читатель документа
  видит обратное. Обе стороны различия держат свои кейсы — метка открыта над закрытым разделом,
  баннер называет чужую дату, у закрытого баннер пропал вовсе. У §6 за баннером идёт ещё и
  `Re-closed`, поэтому берётся ПЕРВЫЙ.
- **Тело ```-блоков разбором пропускается.** Документ САМ показывает читателю форму метки, и `## 3.
  …` внутри показанного блока читался бы структурой документа. Ту же границу проводит
  `check_docs.sh`, где комментарий шелла, принятый за заголовок, делал живым якорь, которого у
  документа нет; опорный `pass` набора дописывает такой блок в исправное дерево.
- **Перечень ВЫВОДИТСЯ, а не сверяется двумя копиями.** У списка корней дерева и у пары
  redist-имён внешнего эталона нет, поэтому там форма `mirrors-group`; здесь эталон один и
  назван — значит `owner_check.sh` печатает открытые разбором документа
  (`owner_gates_open_lines`), а не хранит их у себя. Что он именно читает, держит
  `assert_owner_check_reads_doc`: строка `ОТКРЫТ`/`ЗАКРЫТ` в его коде есть находка — это вторая
  копия списка, и она разъедется.
- **Таблица шапки и вводный абзац сверяются с разделами** равенством МНОЖЕСТВ (спека, номер, дата)
  и числами. Раздел, не попавший в таблицу, и таблица, назвавшая гейт, которого нет, — обе стороны
  различия держат свои кейсы. Дата закрытия сверяется тоже: ячейка бывает прозой
  («2026-08-30, re-closed with artefacts 2026-09-01»), поэтому берётся её первое совпадение с
  датой, а не ячейка целиком.
- **Ноль разделов — ОТКАЗ**, а не «нарушений нет»: разбор, промахнувшийся мимо документа, обязан
  отличаться от чистого прогона. Тот же класс, что правило `vacuous-gate` в `ci_lint.py`.
- **Номера разделов идут подряд**: `§N` — адрес, по которому владельца отправляют и dev-log, и
  тела PR, и сам `owner_check.sh`, а повторённый номер уводит в чужой раздел молча.
- **Заголовок разбирается ПО ПОЛЯМ**, а не регуляркой: `## 15. Gates 1 and 3 of #20 — …` несёт ДВА
  гейта в одном разделе (разделов 17, гейтов 18), и форма, не узнанная разбором, есть находка —
  иначе раздел выпадал бы из сверки, сжимая покрытие при зелёном гейте.
- **Нумерация на пустом разборе — тоже ОТКАЗ.** Цикл, не выполнившийся ни разу, печатал
  «пронумерованы подряд (1..0)»: соседние утверждения свой пустой случай стерегут, а это — нет.
- **Поля разбора разделяет US (`0x1f`), а не таб.** Таб входит в «IFS whitespace» шелла, поэтому
  подряд идущие табы `read` схлопывает в ОДИН: пустое поле (нет действия у закрытого, нет баннера у
  открытого) исчезает и сдвигает все следующие — дата баннера приезжала в поле действия, и оба
  новых утверждения валили ИСПРАВНЫЙ документ. Найдено прогоном, а не рассуждением.
- Em dash в awk передаётся `-v dash=…` и ищется `index()`: восьмеричные escape (`\342\200\224`)
  в ERE awk не интерпретируются, и `sub()` по такому образцу молча не срабатывает. Класс с датой
  задан СТРОКОЙ (`"[0-9/-]"`), а не литералом `/…/`: у §2 дата двойная (`2026-08-05/06`), слэш
  внутри скобочного выражения обрывает сам литерал, а экранировать его нельзя — в скобочном
  выражении ERE обратный слэш по POSIX ЛИТЕРАЛЕН (gawk трактует как escape, mawk и BSD — нет), то
  есть `[0-9\/-]` судил бы платформу. Тот же класс, что `[ \t]` в BSD sed, давший `prerequisi-es`
  в гейте документации. Интервалов `{4}` тут нет по третьей причине: mawk на голой Ubuntu их не
  понимает.
- **Комментарии перед грепом снимаются СТРОКАМИ, а не хвостами от первого `#`.** Удалённый перечень
  начинался каждой строкой с `#<спека>` внутри литерала (`say "  #17 гейт 9 ОТКРЫТ — …"`), и
  `sed 's/#.*//'` резала его до `say "  ` — искомого слова в осмотренном тексте не оставалось
  ВООБЩЕ, то есть гейт был зелен ровно на том дефекте, ради которого заведён. Верное определение
  репозиторий уже знает: `ci_lint_rules.py` — «комментарий это `#` в начале слова». Найдено
  ревью; порча набора теперь пишет ту самую строку с `#17`.
- Позитивный контроль — 2 опорных `pass` (исправное дерево; разметка внутри ```-блока разделом не
  считается) и 21 отбитая порча: закрытый назван открытым, метки нет, закрытый без даты, дата в
  метке словом, открытый без действия, номер гейта словом, строка таблицы пропала, лишний гейт в
  таблице, чужая дата в таблице, чужое число во вводном абзаце и абзац без чисел вовсе, перечень
  снова написан руками, закрытые снова написаны руками, `owner_check.sh` потерял разбор,
  повторённый номер раздела, разбор мимо документа (дважды — своим needle у формы и у нумерации),
  метка открыта над закрытым разделом, баннер называет чужую дату, у закрытого пропал баннер,
  документа нет. Порча обязана РЕАЛЬНО менять файл (`cksum` до и после): подмена, ничего не
  подменившая, читается как «утверждение её отбило».
- Гейт стоит в `checks.json`, гейт и его самопроверка — в группе `preflight_tree_rules.sh`: сборки
  и сети им не нужно, читается ТЕКСТ дерева. **В CI гейт идёт на одной ОС** (дерево одно),
  **самопроверка — на всех трёх**: предмет у неё другой — переносимость самих утверждений (диалект
  awk, `sed`, `cksum`, порядок `sort` под разными локалями). Та же граница, что у гейта
  документации.

## Релизный пакет — `scripts/check_release.sh`

```
bash scripts/release.sh --version v0.1.0   # пакет в release/<версия>/
bash scripts/check_release.sh              # гейт: упаковать ДВАЖДЫ и сверить
bash scripts/check_release_selftest.sh     # правила проверяются сломанными фикстурами
```

Компонент установки `engine` (`cmake/install_engine.cmake`) — редактор, пекарь, рантайм wgpu, семь
лицензий (#9) и `version.txt` со штампом версии, коммита и целевой тройки. Гейт **упаковывает пакет
дважды из одной сборки** и сверяет прогоны между собой, а не с записанным числом: сумма релиза
зависит от тулчейна, и голден пришлось бы обновлять каждым его обновлением — то есть он перестал бы
что-либо ловить в первый же раз, когда его обновили не глядя. Двоичной воспроизводимости САМОЙ
сборки он не утверждает.

- **Наполовину заданная конфигурация — отказ.** `editor_shell` собирается только при `PLUGIN_UI=ON`,
  поэтому `-DLIKE_NES_RELEASE=ON` без него — `FATAL_ERROR` на конфигурации. Иначе каталог, однажды
  сконфигурированный headless, молча отдавал бы пакет без редактора.
- **Каталог сборки у релиза СВОЙ** (`build-release`), и чужой он не переписывает: увидев
  `CMakeCache.txt` без `LIKE_NES_RELEASE=ON`, `release.sh` отказывается. Одолженный ему `build-full`
  оставался релизным навсегда — кеш переживает следующий прогон, который тех же флагов уже не
  передаёт, — и этап «Сборка полного набора опций» молча собирал не ту конфигурацию, которую
  заявляет, штампуя игру-образец версией гейта. Тот же класс, что чинит `LIKE_NES_BUILD_TYPE` в
  `build_check.sh`.
- **Версии нет — отказ, а не «0.0.0»**: скрипт берёт тег с HEAD, иначе требует `--version`.
  Код 3 — «эта платформа собирается не здесь»: `--only linux` и `--only windows` его лишились, когда
  за ними появились делегаты (контейнер и задача CI), и он остался за ветвью, где делегата нет, —
  пакет macOS с чужого хоста. Молчаливый пропуск такой трети релиза выглядит ровно как успех; код 2
  остаётся за ошибкой употребления (нет значения у флага, незнакомое `--only`), чтобы оркестратор
  отличал незакрытую вертикаль от своей опечатки.
- **Состав сверяется РАВЕНСТВОМ МНОЖЕСТВ**, а не «всё ожидаемое на месте»: файл, добавленный в
  `install_engine.cmake` и не названный гейтом, обязан валить его. Ожидаемое считается из тех же
  источников, что и пакет (`cmake/licenses.manifest`, имя рантайма по ОС), — рукописная копия
  разъехалась бы молча. Имя рантайма вдобавок сверяется с **независимым** источником —
  `WGPU_RUNTIME_LIB` из кеша CMake: список ветвится по ОС руками, а самопроверка строит фикстуру из
  него же, и общая ошибка обеих половин была бы зелёной.
- **Тройка у пакета одна.** Её называет `release.sh` (`-DLIKE_NES_TARGET_TRIPLE`), и она же стоит в
  штампе: пока их считали двое, архив с именем `…-macos-arm64` нёс внутри `target Darwin-arm64`, а
  утверждение о штампе принимало любую строку. Теперь тройка штампа сверяется с именем пакета.
- **Нормализация архива проверяется по САМОМУ архиву**: владелец `0`, порядок имён `LC_ALL=C`,
  занулённое время в заголовке gzip. Двух прогонов на это не хватает — они идут на одной машине из
  одного стейджа, где uid и порядок совпадают по построению, и `--numeric-owner` можно было бы
  выкинуть незаметно.
- **Гейт убирает свой каталог** (`release/v0.0.0-check`): он в `.gitignore`, то есть `git status`
  его не видит, и утверждение «следов не осталось» без уборки было слепо ровно к единственному
  следу, который прогон и оставляет.
- **Позитивный контроль двойной**: сломанные фикстуры (нет лицензии, лицензия на нуль байт, лишний
  файл, чужая версия и чужая тройка в штампе, лишняя строка, CRLF-штамп, чужой рантайм в кеше,
  подменённый байт, пустой архив, чужая сумма, симлинк в стейдже, незнакомая ОС) плюс ПОДМЕННЫЕ
  реализации, которые набор обязан отбить: проверка составом-подмножеством, штамп «файл
  существует» и три подмены архива — без зануления владельца, без сортировки и со временем,
  вписанным прямо в заголовок gzip. Снятый `gzip -n` подменой быть не может: у GNU gzip из stdin
  флаг — пустышка (ни имени, ни mtime записывать не с чего), время пишет только gzip Apple, и такая
  фикстура отбивалась бы на macOS, молчала на Linux и в git-bash и проверяла бы платформу, а не
  утверждение.
  Утверждение, у которого нет фикстуры, где оно падает, неотличимо от отсутствующего.
- Наборов два, и второй зовётся ВНЕШНЕЙ командой: `check_release_pack_selftest.sh` — про форму
  архива и гигиену прогона, `check_release_selftest.sh` — про содержимое пакета. Граница по
  предмету (как у `ci_watch_wait_selftest.sh`), и в логе стоит имя упавшего набора.
- Не в `checks.json`: требует полной сборки с `PLUGIN_UI`. Гейт живёт в `preflight.sh`, а его
  самопроверка — ещё и в CI на трёх ОС, где предмет — **переносимость утверждений** (диалект tar,
  `shasum` против `sha256sum`, `touch -t`, git-bash), а не имена файлов: их проверяет настоящий
  гейт на машине, которая собрала пакет.

## Пакет Linux с машины macOS — `scripts/check_release_container.sh`

```
bash scripts/release.sh --version v0.1.0 --only linux   # пакет в контейнере
bash scripts/check_release_container.sh                 # правила, демон не нужен
bash scripts/check_release_container.sh --live          # собрать ДВАЖДЫ и сверить
bash scripts/check_release_container_selftest.sh        # правила на сломанных фикстурах
```

Контейнер здесь даёт **линукс-хост, а не второй упаковщик**: внутри работает тот же `release.sh`,
поэтому состав, штамп и нормализация архива достаются от него, а не от копии, которая разъедется с
оригиналом в первый же месяц. Гейт это и утверждает: `assert_no_second_packer` ищет в
`release_container.sh` собственный вызов `tar`, `gzip`, `appimagetool` или `mksquashfs` — и
**сначала доказывает, что видит там `release.sh`**, иначе опечатка в пути делала бы его вечно
зелёным. Имён четыре, а не два, с шага B: контейнер отдаёт ещё и `.AppImage`, и «второй упаковщик»
для него зовут именно последними двумя — половина продукта линукс-хоста жила бы без утверждения.

- **База пиннута дайджестом** (`ubuntu@sha256:…`), а не тегом: `ubuntu:24.04` переезжает на новый
  образ молча, и пакет, собранный «той же командой», перестаёт быть тем же пакетом. Версии apt
  внутри не пиннуты сознательно — Ubuntu вычищает pool, и пин ломал бы сборку раз в квартал;
  источник держится подписью apt.
- **Тег образа несёт архитектуру** (`like-nes-release:33ceb71981b6-aarch64`): один тег на две
  платформы отдал бы `linux/amd64`-пакет из `arm64`-слоя, и заметно это стало бы по штампу, а не
  по отказу.
- **Отказы разведены кодами.** 3 — «эта платформа собирается не здесь» (пакет macOS с чужого
  хоста), 4 — «машина не готова» (нет docker/podman, или демон молчит). Движок выбирается не наличием в PATH,
  а ответом `info`: установленный Docker Desktop с погашенным демоном иначе выглядел бы годным и
  падал бы посреди сборки.
- **Дерево монтируется `:ro`**, каталог сборки — во временном каталоге ВНЕ дерева. Кеш от упавшего
  прогона (`CMakeCache.txt` есть, `build.ninja` нет) сносится ГРОМКО: конфигурация пишет кеш раньше
  наших опций, поэтому обломок молча выглядел бы как «каталог сконфигурирован не релизом».
- **`git safe.directory` открыт звёздочкой**, а не списком путей: FetchContent разворачивает клоны
  в `/build/_deps/…`, чьи имена заранее не назовёшь, и первый живой прогон умер именно на
  `detected dubious ownership`.
- **Флаг чужого этажа отвергается по тому, дойдёт ли прогон до контейнера**, а не по имени
  платформы. `--only host` разворачивается в имя хоста ДО сравнения, поэтому условие `$ONLY != linux`
  съедало `--platform` молча ровно на линукс-машине — то есть на той ОС, где гейт не гонялся, а
  утверждение о нём само ветвилось по хосту. Теперь оно делает себе линукс-хост заглушкой `uname` и
  проверяет одно и то же на всех трёх, а фикстура со старым условием обязана валить его везде.
  Найдено первым прогоном набора на настоящем Linux; утверждения о ДИСПАТЧЕ вынесены в
  `scripts/release_refusal_check_lib.sh` — предмет у них свой, тот же, что у их набора.
- Самопроверка держит **18 опорных `pass` и 22 отбитые подмены на macOS** (на линукс-хосте 17 и 21:
  делегирование и отказ по linux там своя сборка, и два утверждения пропускаются ВСЛУХ) и разведена
  на три файла по предмету, как пара
  `check_release_selftest.sh` / `check_release_pack_selftest.sh`: основной ломает
  ФАЙЛЫ контейнерного пути (копия скрипта с вырезанной мерой), `check_release_container_impl_selftest.sh` —
  механику библиотеки (подмена поверх загруженной реализации), `check_release_refusal_selftest.sh` —
  ветвление `release.sh` на диспатче (коды 2/3/4). Оба соседних зовутся внешней командой, чтобы
  в логе стояло имя упавшего набора. Числа здесь — не украшение: они и разошлись с фактом на
  предыдущем прогоне, когда набор считали грепом по `expect`, а не прогоном. Три утверждения — про сам набор:
  промах копирования обязан валить его, нетронутая копия обязана ПРОХОДИТЬ утверждение, которое
  валит её сломанный близнец, и каждое имя `assert_*`, которое гейт зовёт, обязано быть
  определено. Первые два появились после того, как набор напечатал `PASS`, не создав ни одной
  копии (`local a="$1" b="$a"` на bash 3.2 macOS — `unbound variable`; уборка копий по той же
  причине идёт ШАБЛОНОМ, а не списком: список накапливался в сабшелле `$( … )` и до trap не
  доезжал), третье — после того, как
  ветка `--live` свалилась на `assert_pack_normalized: command not found`, которого этап правил
  не касался вовсе.
- **Код 3 проверяется формой БЕЗ `--version`, и с вертикали 3 — на ЧУЖОЙ платформе, а не на
  windows.** Вертикаль 2 подняла резолюцию версии выше диспатча, и `--only windows` на HEAD без тега
  стал отказывать кодом 2 («укажи --version») вместо обещанного кода 3 — то есть оркестратор читал
  незакрытую вертикаль как свою же опечатку. Утверждение этого не видело, потому что само
  подставляло `--version v0.0.0-check`: проверять контракт «код 3 НЕЗАВИСИМО от версии» версией,
  которую сам же и дал, значит не проверять его. Резолюция вернулась внутрь ветки-делегата (там она
  нужна: сборка образа стоит четверть часа, прогон CI — до часа). Вертикаль 3 забрала у windows его
  код 3, и утверждение переехало на единственную ветку, где тот остался живым, — `*)`, пакет macOS с
  чужого хоста. Она недостижима на машине владельца, поэтому чужой хост делается **заглушкой
  `uname` в `PATH`**, а ветвления по ОС у утверждения больше нет: оно проверяет одно и то же на всех
  трёх. Заглушка проверяется первой строкой самого утверждения — не подхватилась, значит проверять
  нечего, и это находка, а не пропуск.
- В `preflight.sh` идут правила и самопроверка; живая сборка — руками по `--live`: она поднимает
  демон и тянет базовый образ, а preflight гоняется перед каждым push.
- В CI шага НЕТ, и это не недосмотр: предмет гейта — «машина macOS собирает пакет Linux», а на
  линукс-раннере `--only linux` есть своя хостовая сборка, где половина утверждений (делегирование,
  отказ кодом 3) пропускается по `uname -s` — громко, но пропускается. Windows не при делах вовсе.
  Переносимость утверждений здесь проверять не на чем.

## Пакет Windows задачей CI — `scripts/check_release_ci.sh`

```
bash scripts/release.sh --version v0.1.0 --only windows   # пакет забирается из прогона CI
bash scripts/check_release_ci.sh                          # правила, сеть не нужна
bash scripts/check_release_ci.sh --live                    # dispatch, ожидание, скачивание, сверка
bash scripts/check_release_ci_selftest.sh                  # правила на сломанных ФАЙЛАХ
bash scripts/check_release_ci_impl_selftest.sh             # подмены РЕАЛИЗАЦИЙ библиотеки
```

Прогон CI здесь даёт **Windows-хост, а не второй упаковщик** — ровно тот же инвариант, что у
контейнера: внутри `.github/workflows/release_engine.yml` работает тот же `release.sh`, и состав,
штамп и нормализация архива достаются от него. Нативный пакет требует MSVC, честного способа
получить его на macOS нет — поэтому `--only windows` делегирует, а не отказывает.

- **Пакет движка живёт СВОИМ workflow**, а не job'ом в `release.yml`: тот создаёт публичный GitHub
  Release, и каждая проверка оркестратора публиковала бы релиз. Свойство стережёт
  `assert_ci_publishes_nothing` (`permissions: contents: read`, ни `gh release`, ни `steamcmd`) —
  оно теряется первой же правкой, а замечено было бы уже по странице релизов.
- **Цепочка — главное утверждение вертикали.** Оркестратор просил собрать конкретный коммит; GitHub
  отдал артефакт конкретного прогона; штамп внутри пакета называет коммит независимо от обоих.
  Сходятся все три — доехал ТОТ пакет; не сходятся — доехал какой-то, и разница между этими
  случаями есть всё, что даёт путь через чужую машину. Сверка суммы с `SHA256SUMS` из того же
  артефакта — про доставку («архив доехал целым»), а не про подлинность: подписи у артефакта нет, и
  называть её защитой значило бы врать.
- **О составе приехавшего пакета утверждается то же, что о собранном здесь** — поимённый состав,
  лицензии и штамп с тройкой (`assert_ci_package`, те же три функции, что зовут вертикали 1-2).
  Цепочка о содержимом не говорит НИЧЕГО: пакет без `editor_shell.exe`, без `wgpu_native.dll` или с
  лицензией в нуль байт сходился по версии и коммиту и доезжал как успех. Прогон CI тоже ничего не
  утверждает: там `release.sh` и upload. Тройка берётся из ИМЕНИ пакета, а `ci_os_of_triple` —
  единственный источник соответствия «тройка → ОС» и для гейта, и для фикстур: сравнивай гейт с
  копией маппинга, и общая ошибка обеих половин осталась бы зелёной.
- **Прогон выбирается по коммиту, свежайший из своих.** Тег переставляется одной командой, и
  прогон, найденный по нему, мог быть собран из другого дерева. Повторный dispatch по тому же
  коммиту — штатное действие, поэтому «первый попавшийся» отдал бы старый прогон с истёкшим
  артефактом.
- **Имя артефакта читается ИЗ workflow** (`ci_artifact_name`), как дайджест базы читается из
  Dockerfile. Имя в двух местах разъезжается молча: workflow переименовал артефакт, оркестратор
  ищет прежний и печатает «артефакта нет» на успешном прогоне — отказ, неотличимый от красной
  сборки. Это тот же класс, ради которого в `ci_lint.py` заведено правило `list-drift`.
- **Разбор строки выбора живёт в библиотеке** (`ci_picked_verdict`) и проверяется фикстурой с
  ПУСТЫМ `conclusion`. Это находка ревью, а не вкус: у идущего прогона поле пусто, `set -- $PICKED`
  давал два позиционных параметра, и `"$3"` под `set -u` убивал оркестратор на главном же пути —
  «дождаться прогон». Ветка `pending` не достигалась никогда, и не видело этого ни одно утверждение:
  сам ЦИКЛ не гоняет никто, кроме `--live`. Вынесенный разбор сделал суждение об идущем прогоне
  проверяемым без сети.
- **Коммит сверяется с remote ДО dispatch.** Прогон собирает то, что лежит на GitHub, а не рабочее
  дерево: незапушенный коммит дал бы прогон по чужому SHA, цепочка развалилась бы на штампе, и
  выглядело бы это как испорченный артефакт. Отказ называет оба хеша и говорит «git push».
- **Скачанное едет через СТЕЙДЖ**, и суммы каталога пересчитываются общей с хостовым упаковщиком
  `write_sums`: копирование прямо в `release/<версия>/` затирало `SHA256SUMS`, где уже стояли linux-
  и macos-пакеты — то есть путь через CI ломал результат двух других вертикалей.
- **Вход `workflow_dispatch` приходит в шаг ОКРУЖЕНИЕМ.** Подстановка `${{ }}` склеивается с текстом
  скрипта до запуска шелла, поэтому строка из формы запуска там код, а не данные; валидация версии
  идёт уже ПОСЛЕ склейки и этого не лечит. Алфавит версии проверяется отдельным `case`: `v[0-9]*`
  пропускает всё, что стоит после цифры, включая пробел и `;`, а версия едет в имя каталога, в имя
  архива и в штамп.
- **Нет `gh` или он не авторизован — код 4** со словами, называющими ту причину, которая есть:
  «поставь» и «войди» — разные действия. Делегирование доказывается **исходом делегата** (код 4 из
  `release_ci.sh`), а не грепом по диспатчу: пока windows отказывал кодом 3, вертикаль была закрыта
  наполовину, и различить это можно только так. Хост при этом делается ЧУЖИМ платформе windows
  **заглушкой `uname`** — на macOS и Linux это ничего не меняет, а на windows-раннере меняет всё:
  там `--only windows` совпадает с хостом, диспатча не касается вовсе и уходит в НАСТОЯЩУЮ сборку,
  то есть утверждение о делегировании полчаса проверяло бы сборку. Гейт идёт в preflight на всех
  трёх ОС, так что «на macOS работает» тут не аргумент.
- Самопроверок **три, граница по предмету**, как у пары `check_release_selftest.sh` /
  `check_release_pack_selftest.sh`: `check_release_ci_selftest.sh` ломает ФАЙЛЫ (копия workflow без
  вызова `release.sh`, со своим `tar`, без `workflow_dispatch`, с `contents: write`, с
  `gh release create`; копия workflow без пина WiX, с `latest`, без суммы, со стёртой суммой и
  чужим 64-hex рядом, с суммой, которую никто не сравнивает; копия `release.sh`, вернувшая windows
  код 3) — 6 опорных `pass` и 16 отбитых;
  `check_release_ci_impl_selftest.sh` подменяет РЕАЛИЗАЦИИ поверх загруженной библиотеки и ломает
  сам ПАКЕТ (нет лицензии, лицензия в нуль байт, нет рантайма, чужая тройка в штампе) — 7 опорных
  `pass` и 19 отбитых. Третьим отсюда внешней командой зовётся
  `check_release_msi_ci_selftest.sh`: предмет у него — приехавший УСТАНОВЩИК, и строить фикстуру ему
  нужно настоящим компилятором. Фикстурные пакеты всем трём строит ОДНА фабрика
  (`release_ci_fixture_lib.sh`):
  собери гейт честный пакет своей копией, а набор — сломанный своей, и «утверждение отбило подмену»
  проверялось бы на пакете иного устройства, чем тот, на котором утверждение проходит.
- **Подмена, которая ничего не подменила, читается как «утверждение её отбило»** — копия остаётся
  исправной и честно проходит. Так и вышло в соседнем refusal-наборе: `sed` промахнулся мимо
  строки, уехавшей в этой же вертикали, и фикстура полгейта проверяла собственный промах. Теперь
  каждая порча сверяется с оригиналом (`mutated`) в обоих наборах — тот же класс, что правило
  `vacuous-gate` в `ci_lint.py`.
- **`contents: write` отбивается ГДЕ УГОДНО в теле**, а не проверяется наличием `contents: read`
  сверху: permissions job'а верхние ПЕРЕКРЫВАЮТ, а не складываются с ними, и копия с обеими
  строками проходила гейт зелёной.
- Позитивный контроль нашёл **три вакуумно-зелёных утверждения** сразу: `permissions` и
  `contents: read` находились в собственном КОММЕНТАРИИ шапки workflow (тот же класс, что уже
  чинили в `assert_ci_no_second_packer`), `workflow_dispatch` — в теле шага, ветвящегося по
  `github.event_name`, а имя артефакта проверялось кодом возврата чтения, то есть реализация,
  вернувшая ноль и пустую строку, проезжала — а `gh run download -n ''` скачивает весь прогон.
  Утверждение, у которого нет фикстуры, где оно падает, неотличимо от отсутствующего.
- **С шага C вертикали 4 прогон отдаёт ещё и `.msi`**, и об установщике утверждается ровно то же,
  что о самом пакете: он лежит рядом с архивом, имя называет тройку, внутри — поимённый состав,
  лицензии и штамп (`assert_ci_msi`). Осмотр требует msitools, которых на Windows нет; их
  отсутствие вырождает утверждение в «установщик доехал» и говорит об этом ВСЛУХ. Инструмент, каким
  прогон его собирает, пиннут версией и суммой — `assert_ci_wix_pinned`; шаг, зовущий `wixl` или
  `candle`/`light` сам, отбивается `assert_ci_no_second_packer` наравне с собственным `tar`.
  Подробности — секция «Установщик Windows» ниже.
- В `preflight.sh` идут правила и самопроверка; живой прогон — руками по `--live`: он занимает
  раннер до часа. Шага в CI у гейта нет: предмет — «машина владельца забирает пакет из CI», и
  внутри самого CI проверять это не на чем.

## Образ macOS — `scripts/check_release_dmg.sh`

```
bash scripts/release.sh --version v0.1.0        # рядом с .tar.gz кладётся ещё и .dmg
bash scripts/check_release_dmg.sh               # упаковать ДВАЖДЫ и сверить СОДЕРЖИМОЕ образа
bash scripts/check_release_dmg_selftest.sh      # правила на сломанных ФИКСТУРАХ тома
bash scripts/check_release_dmg_impl_selftest.sh # подмены РЕАЛИЗАЦИЙ раскладки и запечатывания
bash scripts/check_release_dmg_live_selftest.sh # живой цикл hdiutil: упаковать, смонтировать, снять
```

`.tar.gz` — доставка тому, кто и так живёт в терминале; на macOS пакет ставят перетаскиванием
бандла в `Applications`, и до этого раунда такого пакета у нас не было вовсе. Образ несёт
`like-nes.app` (редактор, пекарь, рантайм wgpu, семь лицензий и `version.txt` — тот же компонент
`engine`, что и в архиве) и симлинк на `/Applications`.

- **Воспроизводится СОДЕРЖИМОЕ образа, а байты — нет**, и граница названа вслух здесь, в ADR,
  в шапке гейта и в выводе `release.sh`. `hdiutil` пишет в UDIF время сборки и UUID: два `create`
  из одного каталога дают разные И сумму, И размер (3565424 против 3565431 байта на первом же
  прогоне). Обещать байт-равенство `.dmg` значило бы обещать то, чего формат не даёт, поэтому гейт
  пакует дважды и сверяет **манифест смонтированного тома** — имена, права, посуммно содержимое.
  Строка `.dmg` — единственная в таблице `release.sh`, которая меняется между прогонами, и владелец
  сверяет прогоны именно по этой таблице, поэтому скрипт печатает это прямо под ней.
- **Второй образ монтируется**, а не только сверяются манифесты между собой: равенство манифестов
  есть утверждение о двух каталогах стейджа, и образ второго прогона без этого шага не осматривает
  никто.
- **Ожидаемый состав считает та же `dmg_app_path`, которой раскладывал упаковщик** — то есть общая
  ошибка обеих половин остаётся зелёной по построению. Поэтому рядом стоят утверждения, ничего не
  знающие о раскладке: зеркало стейджа (мультимножество сумм), лицензии с ЯВНО заданным подкорнем,
  имя рантайма из кеша CMake и права по каталогам. Каждое из них доказано подменой `dmg_app_path`,
  которая утверждение о составе ПРОХОДИТ.
- **Рантайм обязан лежать рядом с точкой входа**, в `Contents/MacOS`: `reproducible_rpath` ставит
  `@executable_path`, и бандл, спрятавший dylib в `Contents/Frameworks`, выглядит собранным и не
  стартует. Состав этого не видит, кеш CMake видит.
- **Сам механизм двухступенчатый, и утверждается он целиком** (`release_dmg_rpath_lib.sh`, своим
  файлом: предмет здесь не содержимое тома, а связь внутри Mach-O, и читает её единственный в
  наборе `otool`). Исполняемый записывает библиотеку как `@rpath/libwgpu_native.dylib`
  (LC_LOAD_DYLIB) и сам же говорит, чем `@rpath` разворачивать (LC_RPATH). Сломай любую половину —
  бандл соберётся, состав, права и лицензии сойдутся, а `Library not loaded` увидит владелец, а не
  гейт; абсолютный rpath отбивается наравне с отсутствующим, потому что ведёт в каталог сборки.
  Фикстуры под это — настоящие Mach-O от `cc` (текстовым «бинарям» `otool` не скажет ничего, и они
  отбиваются ВСЛУХ: на не-Mach-O он отвечает «is not an object file» кодом НОЛЬ).
- **`Info.plist` читается PlistBuddy, а не грепом**, и утверждается по полям: точка входа, версия,
  коммит. Грep по XML принимает и файл, который LaunchServices не разберёт вовсе.
- Самопроверок **три, граница по предмету**, как у пар вертикалей 2 и 3, и каждая следующая
  зовётся ВНЕШНЕЙ командой, чтобы в логе стояло имя упавшего набора: `…_selftest.sh` ломает
  СОДЕРЖИМОЕ готового тома (13 опорных `pass`, 27 отбитых порч), `…_impl_selftest.sh` — то, чем том
  делается (6 и 8), `…_live_selftest.sh` — единственное место, где вообще запускается `hdiutil`
  (3 и 2). Подмена, которая ничего не подменила, читается как «утверждение её отбило», поэтому
  каждая сверяется с оригиналом через `declare -f`.
- **Пропавший каталог — не «нарушений нет».** У прав и у rpath счётчик осмотренных файлов: `find`
  по несуществующему каталогу молчит, цикл не выполняется ни разу, список нарушений пуст — и
  утверждение печатало бы `ok` про бандл без точки входа. Тот же класс, что правило `vacuous-gate`
  в `ci_lint.py`. Точка монтирования по той же причине сверяется ПОЛЕМ целиком, а не вхождением
  подстроки: «…/mnt» находится внутри «…/mnt1», и путь приводится к физическому — систему наш
  `/var/folders/…` знает как `/private/var/folders/…`.
- **Утверждение о следах монтирования проверяется на СМОНТИРОВАННОМ томе.** На каталоге, который
  никто не монтировал, `hdiutil info` молчит, и `assert_no_mount_left` проходил бы всегда — ровно
  поэтому живой цикл вынесен в свой файл, а не выброшен как медленный. Он же отбивает
  размонтирование-пустышку: гейт с ней печатает `PASS` и оставляет том в системе, а `git status`
  такого следа не видит.
- Фикстурные тома обоим файловым наборам строит ОДНА фабрика (`release_dmg_fixture_lib.sh`), и
  раскладывает она НАСТОЯЩИМ раскладчиком: собери набор том своей копией правил — и «утверждение
  отбило подмену» проверялось бы на томе иного устройства, чем тот, на котором оно проходит.
- Гейт идёт в `preflight.sh` после `check_release.sh` (ему нужен собранный `build-release`), а
  правила и самопроверки — в группе `preflight_release_rules.sh`. На Linux и Windows оба
  пропускаются ВСЛУХ кодом 0: `hdiutil` есть только на macOS, и молчаливый пропуск в общем прогоне
  читался бы как пройденный гейт. Шага в CI нет по той же причине.
- Установщик Windows закрыт следующим шагом вертикали — секция «Установщик Windows» ниже.

## Образ Linux — `scripts/check_release_appimage.sh`

```
bash scripts/release.sh --only linux --version v0.1.0    # рядом с .tar.gz кладётся ещё и .AppImage
bash scripts/check_release_appimage.sh                   # упаковать ДВАЖДЫ, сверить БАЙТЫ, осмотреть
bash scripts/check_release_appimage_selftest.sh          # правила на сломанных ФИКСТУРАХ AppDir
bash scripts/check_release_appimage_impl_selftest.sh     # подмены РЕАЛИЗАЦИЙ раскладки
bash scripts/check_release_appimage_pack_selftest.sh     # исход appimagetool и отсутствие инструмента
bash scripts/check_release_appimage_norm_selftest.sh     # что уезжает в СУММУ: время, владелец, права
bash scripts/check_release_appimage_runpath_selftest.sh  # связь внутри ELF на настоящих бинарях
```

`.tar.gz` — доставка тому, кто и так живёт в терминале; остальным на Linux пакет отдают одним
файлом, который скачали и запустили. Образ несёт тот же компонент `engine` (редактор, пекарь,
рантайм wgpu, семь лицензий и `version.txt`), `AppRun`, `.desktop` и значок.

- **Собирается ТЕМ ЖЕ прогоном в ТОМ ЖЕ контейнере**, что и архив: `release.sh` зовёт
  `extra_build`, а тот на линукс-хосте раскладывает AppDir **из уже установленного стейджа**.
  Второго списка файлов не появляется — он разъехался бы с `install_engine.cmake` молча.
- **Байты воспроизводятся, и это утверждается ПЕРВЫМ.** Здесь граница противоположна `.dmg`:
  squashfs зависит от содержимого, mtime, владельца и прав — и все четыре величины упаковщик
  выравнивает сам (mtime штампом коммита, той же величиной, что у архива; владельца — `-all-root`;
  права файлов и каталогов — явным `chmod`). Обещать меньше, чем формат даёт, — такая же неправда, как обещать
  больше. Содержимое осматривается СВЕРХ равенства сумм: равные суммы говорят, что упаковщик
  повторяем, и ничего не говорят о том, что внутри.
- **`appimagetool` пиннут СУММОЙ файла** в `scripts/release_linux.Dockerfile`, а не именем тега:
  ассеты релиза на GitHub переписываются, и «та же ссылка» через месяц отдаёт другой инструмент.
  Несовпадение суммы — отказ сборки образа.
- **Исход, а не код возврата.** `appimagetool` без иконки не создаёт файл и возвращает НОЛЬ,
  поэтому упаковщик утверждает существование образа, а `release_container.sh` — ещё раз, уже после
  выхода из контейнера. Иконка по той же причине обязательна и сверяется с `packaging/`. Проверок
  всё-таки ДВЕ: ненулевой код достоверен, его слушают первым — вместе со всем, что инструмент
  сказал, — и оставленный им ОБРУБОК удаляют, иначе отказ проезжал бы как успех (`-f` такой файл
  принимает, и `release_container.sh` тоже), а владелец не видел бы ни строки причины.
- **Инструмента нет — пропуск ВСЛУХ, а не падение.** `appimagetool` живёт в образе контейнера, а не
  в системе владельца, и безусловный вызов ронял бы на Linux весь `release.sh`, а с ним
  `check_release.sh` и релизный этап preflight. `extra_build` возвращает ноль, кладёт причину в
  `EXTRA_SKIP`, и `release.sh` печатает её там же, где печатал бы строку про воспроизводимость:
  молчаливый пропуск читается ровно как «образ собран».
- **Права и владелец проставляются ЯВНО, а не достаются от машины.** Перенаправление и `cp` без
  `-p` накладывают на новый файл umask, `mkdir -p` — её же на каталоги, а mksquashfs пишет в образ
  uid/gid владельца файлов: все три величины едут в СУММУ образа, и байт-равенство, которое гейт
  утверждает первым, стало бы свойством машины — в контейнере сборка идёт под root, на машине
  владельца нет. Два прогона гейта этого не видят по построению: они идут в одном шелле, от одного
  пользователя, с одной umask — тот же довод, ради которого для `.tar.gz` заведён
  `assert_pack_normalized`. Поэтому упаковщик выравнивает права файлов и каталогов `chmod`'ом, а
  владельца — опцией `-all-root`, названной ОДНОЙ строкой (`appimage_mksquashfs_opts`), которую
  читает и гейт: список аргументов, переписанный вторым местом, разъехался бы молча. Гейт сверяет
  права четырёх собственных файлов образа ЧИСЛОМ (`AppRun` 755, `.desktop`, значок и `.DirIcon`
  644), а не битом исполнения, и **читает готовый образ** `unsquashfs`: у `appimagetool --list` в
  ответ стоит «To be implemented», а `--appimage-extract` накладывает на распакованное umask
  распаковщика, то есть отвечал бы про машину, а не про образ. Читается образ СО СДВИГОМ (`-o`,
  величину называет он сам через `--appimage-offset`): AppImage — ELF-обёртка, к которой squashfs
  приклеен позади, и `unsquashfs` без сдвига видит начало ELF и отказывается. Найдено первым живым
  прогоном в контейнере — утверждение валило исправный образ; разбор ответа вынесен чистой функцией
  и проверяется без образа, потому что ошибиться в нём можно на любой машине.
- **Состав внутри образа — равенством множеств**, и ожидаемое считает та же `appimage_path`,
  которой раскладывал упаковщик, — общая ошибка обеих половин зелена по построению. Поэтому рядом
  стоят утверждения, ничего не знающие о раскладке: зеркало стейджа (мультимножество сумм плюс
  ровно четыре файла образа), лицензии с ЯВНО заданным подкорнем, имя рантайма из кеша CMake и
  права по каталогам. Каждое доказано подменой `appimage_path`, которая утверждение о составе
  ПРОХОДИТ.
- **`$ORIGIN` — линуксовая половина того же механизма, что `@executable_path` на macOS**
  (`cmake/determinism.cmake`), и утверждается она целиком, своим файлом
  (`release_appimage_runpath_lib.sh`, единственный в наборе `readelf`): исполняемый называет
  библиотеку в DT_NEEDED и сам же говорит, где её искать (DT_RUNPATH или DT_RPATH — какое поле
  напишет линкер, решает тулчейн). Абсолютный путь поиска отбивается наравне с отсутствующим: он
  ведёт в каталог сборки. Фикстуры под это — настоящие ELF от `cc`; не-ELF отбивается ВСЛУХ.
- **Пропавший каталог — не «нарушений нет»**: у прав и у runpath счётчик осмотренных файлов, иначе
  `find` по несуществующему `usr/bin` молчит и гейт печатает `ok` про образ без точки входа. Тот же
  класс, что правило `vacuous-gate` в `ci_lint.py`.
- Самопроверок **пять, граница по предмету**, и каждая следующая зовётся ВНЕШНЕЙ командой:
  `…_selftest.sh` ломает СОДЕРЖИМОЕ готового AppDir (14 опорных `pass`, 31 отбитая порча),
  `…_impl_selftest.sh` — то, чем AppDir делается (7 и 8), `…_pack_selftest.sh` — ВЫЗОВ ИНСТРУМЕНТА:
  разбор исхода `appimagetool` и ветка «инструмента нет» (5 опорных `pass`; порчи у него нет —
  предмет здесь реакция упаковщика на чужой исход, и подменяется этот исход заглушкой, а не файлом),
  `…_norm_selftest.sh` — то, что уезжает в СУММУ образа: выравнивание времени, права каталогов,
  разбор листинга на чужого владельца и разбор СДВИГА squashfs (8 и 5), `…_runpath_selftest.sh` —
  связь внутри ELF (3 и 7).
  Пятый набор отделён от четвёртого не длиной, а предметом: байт-равенство гейт утверждает первым,
  а его два прогона слепы к времени, владельцу и umask по построению — значит у этого утверждения
  свой позитивный контроль, и хвостом соседа он быть не может. Настоящий `appimagetool` набору про
  вызов не нужен и намеренно не зовётся: он подменяется заглушкой в `PATH` (`ok` / молчаливый ноль
  без файла / ненулевой код с обрубком), потому что предмет — реакция упаковщика на его исход, а не
  squashfs; сам `PATH` при этом чистится ПЕРЕБОРОМ каталогов, иначе в контейнере вертикали 2 ветка
  «инструмента нет» проверяла бы не то, что заявляет. Набор про ELF идёт **только на Linux** и
  говорит об этом вслух: `$ORIGIN` — линуксовое поле, и на macOS такой фикстуры не из чего сделать.
  Фикстуры файловым наборам строит ОДНА фабрика (`release_appimage_fixture_lib.sh`) НАСТОЯЩИМ
  раскладчиком.
- Гейт идёт в `preflight.sh` рядом с образом macOS, правила и самопроверки — в группе
  `preflight_release_rules.sh`. На macOS и Windows гейт пропускается ВСЛУХ кодом 0 (упаковщик
  линуксовый), и на Linux без `appimagetool` — тоже: инструмент живёт в образе контейнера, а не в
  системе владельца. Шага в CI нет: линукс-раннер собирал бы там пакет заново ради того же
  утверждения.

## Установщик Windows — `scripts/check_release_msi.sh`

```
bash scripts/release.sh --only windows --version v0.1.0   # рядом с .tar.gz едет ещё и .msi
bash scripts/check_release_msi.sh               # упаковать ДВАЖДЫ и сверить СОДЕРЖИМОЕ пакета
bash scripts/check_release_msi_selftest.sh      # правила на сломанном СОДЕРЖИМОМ пакета
bash scripts/check_release_msi_impl_selftest.sh # подмены РЕАЛИЗАЦИЙ раскладки и исходника
bash scripts/check_release_msi_pack_selftest.sh # выбор инструмента и разбор его ИСХОДА
bash scripts/check_release_msi_ci_selftest.sh   # утверждение о ПРИЕХАВШЕМ из CI установщике
```

`.tar.gz` — доставка тому, кто и так живёт в терминале; на Windows пакет ставят двойным щелчком по
установщику, и до этого шага такого пакета у нас не было вовсе. `.msi` несёт тот же компонент
`engine` (редактор, пекарь, рантайм wgpu, семь лицензий и `version.txt`), ярлык в меню «Пуск» и
штатную деинсталляцию.

- **Собирается ТЕМ ЖЕ прогоном на Windows-хосте**, что и архив: `release.sh` зовёт `extra_build`, а
  тот раскладывает пакет **из уже установленного стейджа** — ровно та симметрия, что у AppImage на
  линукс-хосте. Второго списка файлов не появляется: он разъехался бы с `install_engine.cmake`
  молча. Списка нет и в самой раскладке — каталог установки ВЫВОДИТСЯ обходом стейджа, а незнакомый
  путь есть ОТКАЗ: файл, добавленный в `install_engine.cmake` и не попавший в пакет, иначе
  неотличим от успеха.
- **Воспроизводится СОДЕРЖИМОЕ, а байты — нет**, и граница здесь та же, что у `.dmg`, и
  противоположная `.AppImage`. Выяснено ПРОГОНОМ, а не постулировано: два пакета из одного исходника
  совпали размером и разошлись ровно строкой 9 сводного потока — случайным package code. Время
  сборки (строки 12 и 13) отбрасывается по той же причине, хотя внутри одного прогона совпадает.
  Отбрасываются они ПОИМЁННО, а не таблицей целиком: в том же потоке живут платформа, язык и версия
  схемы, и простить их значило бы не проверять сводку вовсе. Гейт пакует дважды и сверяет **все
  таблицы пакета** плюс развёрнутое дерево. Код возврата `msiinfo` при этом слушается, а таблицы СО
  СТРОКАМИ считаются отдельно (19 из 35 на живом прогоне): у отсутствующей таблицы экспорт отвечает
  единицей, молчаливое пустое от неё неотличимо от таблицы без строк, и сверка «пустое против
  пустого» равняла бы два пакета, ни одного из которых не читала. Ноль таблиц со строками — отказ.
- **Два прогона обязаны быть ДВУМЯ прогонами** (`assert_msi_runs_distinct`). Сравнение пакета с его
  же копией зелено вакуумно, и единственная улика, отличающая копию от второй сборки, — тот же
  package code: он случаен, и совпасть у двух вызовов компилятора не может. Станет формат
  когда-нибудь детерминированным — это находка, а не тишина: гейт скажет об этом здесь.
- **Компиляторов ДВА, и это два ХОСТА, а не запасной путь.** Поставляемый пакет собирает **WiX v3**
  на раннере Windows — единственный, который там есть; фикстуры гейта собирает `wixl` из msitools на
  машине владельца, потому что WiX на macOS не существует. Оба читают ОДИН исходник
  (`packaging/like-nes.wxs.in`), поэтому фикстура проверяет тот же генератор, что и продакшн, а не
  свою копию правил. Совпадение ПОВЕДЕНИЯ двух компиляторов при этом ничем не доказано — доказано
  совпадение ВХОДА, а выход настоящего WiX осматривает `check_release_ci.sh` на пакете, приехавшем
  из прогона.
- **WiX пиннут версией и суммой** (`wix3141rtm`, sha256 в шаге workflow) — по тому же основанию, что
  `appimagetool`: ассеты релиза на GitHub переписываются, и «та же ссылка» через месяц отдаёт другой
  инструмент. Стережёт это `assert_ci_wix_pinned`, и у него ПЯТЬ отбитых фикстур: установки нет
  вовсе, `latest` вместо тега, сумма не сверяется, сумма стёрта и рядом лежит чужой 64-hex, сумма
  лежит и ни с чем не сравнивается. Последние две — находки ревью: ссылка искалась по ТОЧНОМУ
  адресу тега, поэтому чужая сумма где угодно в файле выдавалась за пин, а лежащая рядом со
  скачанным сумма без сравнения принимает любой файл.
- **Исход, а не код возврата.** `light` при отказе оставляет ОБРУБОК, который `[ -s ]` принимает
  наравне с готовым пакетом, поэтому упаковщик судит по ФАЙЛУ, обрубок удаляет, а ненулевой код
  слушает первым и печатает целиком — он достовернее и называет причину. Код 2 — «инструмента
  нет» — отдельный: msitools не стоят на раннере Windows, WiX не существует на macOS, и ни то, ни
  другое не есть поломка. `extra_build` в этом случае возвращает ноль и кладёт причину в
  `EXTRA_SKIP`, а `release.sh` печатает её там же, где печатал бы строку про установщик: молчаливый
  пропуск читается ровно как «пакет собран».
- **GUID выводится ИЗ КЛЮЧА, а не берётся случайным.** Компонент, сменивший GUID между версиями,
  Windows Installer считает ДРУГИМ компонентом — установка поверх оставляет старые файлы; случайный
  GUID вдобавок ломает сверку двух прогонов, которой держится весь релизный гейт. `UpgradeCode`
  один на линейку и не меняется НИКОГДА: по нему установщик узнаёт свою же прежнюю версию, чтобы
  снести её, — иначе версии копятся в списке программ, а деинсталляция снимает одну из копий.
- **Утверждения разведены по ПРЕДМЕТУ и по файлам**: `release_msi_check_lib.sh` читает пакет как
  СОДЕРЖИМОЕ (таблицы, воспроизводимость, зеркало стейджа), `release_msi_behavior_lib.sh` судит по
  тем же таблицам о ПОВЕДЕНИИ установщика — пользовательская установка, полнота удаления, линия
  обновления, версия, ярлык. Разрез сделан находкой бюджета длины: один файл упёрся в жёсткий
  порог, а он причиной не выкупается ни для кого.
- **Свои каталоги выводятся из таблицы Directory**, а не перечисляются списком: `RemoveFolder`
  утверждается на КАЖДОМ каталоге под корнем установки, и подъём по родителям находит их сам.
  Рукописный список разъехался бы с раскладкой молча — тот же класс, что правило `list-drift`.
- **Лог компилятора печатается и на УСПЕХЕ**: WiX не поднимает код возврата на ICE-предупреждениях,
  и пакет, собранный с жалобами, выглядел бы собранным молча.
- **Тихая установка — НЕ то же самое, что пользовательский корень.** `msiexec` решает, спрашивать
  ли повышение прав, по БИТУ 8 сводного потока («elevated privileges are not required»), а ставит
  этот бит КОМПИЛЯТОР по атрибуту `<Package InstallScope="perUser">`. Пакет с корнем в
  `LocalAppDataFolder` и без атрибута ставится в тот же каталог и всё равно поднимает UAC, а под
  `/qn` показать запрос некому — установка обрывается кодом 1603. Читается бит своей читалкой
  (`msi_wordcount`): в таблицах его нет вовсе, он живёт в сводном потоке. Утверждение
  (`assert_msi_silent`) стоит ДВАЖДЫ — на фикстуре, собранной здесь, и на установщике, приехавшем из
  CI: бит пишет компилятор, а компиляторов у одного исходника два, и совпадение их ВХОДА не есть
  совпадение поведения.
- **По ТАБЛИЦАМ проверяется ровно то, чего в развёрнутом дереве нет**: пользовательская установка
  (корень на `LocalAppDataFolder`, `ALLUSERS` не задано — не требовать администратора там, где можно
  без него), полнота деинсталляции (`RemoveFolder` на КАЖДОМ нашем каталоге плюс принадлежность
  каждого файла компоненту, входящему в Feature), линия обновления, `ProductVersion` и цель ярлыка.
  Состав, лицензии и штамп делятся с архивом (`assert_composition`, `assert_licenses`,
  `assert_stamp`), а зеркало стейджа не знает о раскладке ничего — подмена раскладки обязана валить
  его, а состав по `expected_files` она проходит.
- **Компонент вне Feature у wixl выпадает из пакета ЦЕЛИКОМ** (прогон показал дерево без единой
  лицензии), то есть порчу ловят ОБА утверждения. Проверка по таблице всё равно нужна: она не
  зависит от поведения компилятора, а компиляторов у одного исходника два.
- **Осматривается пакет msitools** (`msiinfo`, `msiextract`), которых на Windows нет вовсе: граница
  между «чем собрано» и «чем осмотрено» проходит здесь по МАШИНАМ. Оба пропуска идут ВСЛУХ кодом 0 —
  нет компилятора, нет msitools, — потому что молчаливый пропуск в общем прогоне preflight читался
  бы как пройденный гейт. Возврат каретки снимается в `msi_table`, а не в каждом сравнении:
  `msiinfo` печатает таблицы окончаниями CRLF, `\r` приезжает в ПОСЛЕДНЕЕ поле строки, и первым
  прогоном на этом разошлись три утверждения из десяти.
- **Стейдж гейт делает СЕБЕ САМ** фабрикой `ci_make_pkg` — той же, которой вертикаль 3 строит
  фикстурный пакет Windows: `--only windows` с машины владельца уходит в CI, настоящему стейджу
  Windows здесь взяться неоткуда, а своя копия правил раскладки означала бы осмотр пакета иного
  устройства, чем тот, что едет к людям.
- **Приехавший из CI установщик осматривается наравне с собранным здесь** (`assert_ci_msi`):
  отсутствие рядом с архивом, имя без тройки, нехватка редактора или рантайма, лицензия в нуль байт
  чужая тройка в штампе и пакет без `InstallScope` (тот спросил бы права под `/qn`) — семь отбитых
  фикстур. Там, где msitools не стоят, утверждение
  вырождается в «установщик доехал» и говорит об этом вслух. Шаг CI, зовущий `wixl` или
  `candle`/`light` сам, отбивается `assert_ci_no_second_packer` наравне с собственным `tar` — по
  ФОРМЕ ВЫЗОВА (имя, за ним флаг), иначе шаг установки WiX срабатывал бы на самом себе.
- Самопроверок **четыре, граница по предмету**, и каждая зовётся ВНЕШНЕЙ командой, чтобы в логе
  стояло имя упавшего набора: `…_selftest.sh` ломает СОДЕРЖИМОЕ готового пакета (17 опорных `pass`,
  14 отбитых порч), `…_impl_selftest.sh` — то, чем пакет делается: раскладку и исходник (4 и 19),
  `…_pack_selftest.sh` — ВЫЗОВ ИНСТРУМЕНТА: выбор компилятора и разбор его исхода (11 опорных
  `pass`; порчи у него нет — предмет здесь реакция упаковщика на чужой исход, и подменяется этот
  исход заглушкой в `PATH`, а сам `PATH` чистится ПЕРЕБОРОМ каталогов, иначе на машине владельца
  ветка «инструмента нет» проверяла бы не то, что заявляет), `…_ci_selftest.sh` — утверждение о
  ПРИЕХАВШЕМ пакете (1 и 7). Подмена, которая ничего не подменила, читается как «утверждение её
  отбило», поэтому каждая сверяется с оригиналом (`subbed` / `mutated`).
- Гейт и его самопроверки идут в группе `preflight_release_rules.sh`, а НЕ рядом с образами macOS
  и Linux в `preflight.sh`: тем нужен собранный `build-release`, а этому сборка не нужна вовсе —
  стейдж он делает себе сам фабрикой `ci_make_pkg`. Шага в CI нет: на раннере Windows нечем
  осматривать, а на прочих ОС нечем собрать поставляемый пакет; приехавший оттуда установщик
  осматривает `check_release_ci.sh` на машине владельца.

## Пакет Windows без VC++ Redistributable — `scripts/check_release_crt.sh`

```
bash scripts/check_release_crt.sh                   # гейт: сборки и Windows не требует
bash scripts/check_release_crt_selftest.sh          # пакет: синтетические фикстуры
bash scripts/check_release_crt_reader_selftest.sh   # читатель PE и якорь на настоящем рантайме
bash scripts/check_release_crt_wiring_selftest.sh   # проводка дерева: порядок include и копии списка
bash scripts/check_release_crt_named_selftest.sh    # app-local состав против импортов рантайма
```

Пакет, которому на чистой машине не хватает системного рантайма, выглядит собранным и не
запускается — а узнаёт об этом тот, кому его отдали. Гейт 4 спеки #20 требовал «диалог доустановки
VC++ Redistributable»; вертикаль 5 закрыла его иначе — **сняв предмет**, и отклонение записано в
ADR 0019 решениями 34-35, а не умолчано.

- **Половин у зависимости две, и меры разные.** НАШИ цели собираются со СТАТИЧЕСКИМ CRT
  (`cmake/msvc_runtime.cmake`) и не просят ничего; предсобранный `wgpu_native.dll` собран ЧУЖИМ
  тулчейном с динамическим и импортирует `VCRUNTIME140.dll` — она едет app-local рядом с ним
  (`cmake/msvc_redist.cmake`). UCRT (`api-ms-win-crt-*`, `ucrtbase.dll`) не едет СОЗНАТЕЛЬНО: с
  Windows 10 это компонент ОС, и таскать его значило бы подменять систему.
- **Утверждений тоже два, и второе не следует из первого.** «Каждая redist-DLL лежит рядом с
  просящим её бинарём» (`assert_crt_self_contained`) не видит, что просит её НАШ `.exe`: пока
  `vcruntime140.dll` в пакете есть, ссылаться на неё может кто угодно, и потеря
  `CMAKE_MSVC_RUNTIME_LIBRARY` была бы тихим возвратом к тому, что и так лежит. Поэтому рядом стоит
  `assert_static_crt`, и его фикстура — наш исполняемый с redist-импортом при ЖИВОМ файле рядом:
  утверждение о самодостаточности она ПРОХОДИТ.
- **Чужое опознаётся ПОИМЁННО** (`crt_is_foreign` — сегодня там одна строка, `wgpu_native.dll`), а
  не по расширению: наша будущая разделяемая библиотека обязана попадать под утверждение о
  статичности по умолчанию, а новый чужой бинарь — требовать осознанной записи. Опознавать «наше»
  по суффиксу `.exe` было бы той же ошибкой, что рукописный список исходников: первая же наша `.dll`
  уехала бы на динамическом CRT незамеченной. Файлы САМОГО redist, приехавшие app-local, чужие по
  определению и отсекаются тем же закрытым списком, а не вторым перечислением имён: требовать
  статического CRT от `vcruntime140.dll` бессмысленно, а без этой ветки настоящий пакет валил бы
  гейт на файле, который вертикаль в него и положила.
- **DLL ищется в каталоге ИСПОЛНЯЕМОГО**, а не рядом с тем, кто её просит: app-local поиск Windows
  идёт по каталогу ПРОЦЕССА. Сегодня и то и другое — один `bin/`, но после первого же переезда файла
  проверка «лежит где-нибудь в пакете» дала бы зелёный пакет, который не стартует; фикстура под это
  файл из пакета не удаляет, а поднимает этажом выше.
- **Список redist-имён ЗАКРЫТ** (`vcruntime*`, `msvcp*`, `msvcr*`, `concrt*`, `vccorlib*`, `mfc*`,
  `vcamp*`, `vcomp*`). Обратная форма — «всё, чего нет в системе» — потребовала бы перечислить DLL
  самой Windows, а тот список стареет с каждой её версией и молча превращал бы гейт в утверждение о
  вчерашней ОС. Цифра после имени обязательна: `msvcrt.dll` живёт в System32 с девяностых и
  redist'ом не является, а `msvcr120.dll` — является. Имя приводится к нижнему регистру: на диске
  лежит `vcruntime140.dll`, в таблице импортов стоит `VCRUNTIME140.dll`, и на macOS такая пара
  совпадает сама собой, а на Linux нет — утверждение проверяло бы платформу вместо пакета.
- **Читатель PE свой** (`scripts/pe_imports.py`), и он ЗАЯКОРЕН на настоящем `wgpu_native.dll` из
  выкачанной дистрибуции. Синтетические фикстуры (`scripts/pe_fixture.py`) доказывают, что
  утверждения умеют падать, но собственный генератор доказывает лишь то, что читатель понимает ЭТОТ
  генератор, а не формат Microsoft. Нет дистрибуции в дереве — пропуск ВСЛУХ.
- **Границей обхода служит КОНЕЦ СЕКЦИИ, а не `Size` из каталога данных.** Загрузчик Windows это
  поле не читает вовсе — он идёт до нулевого дескриптора, — а линкеры пишут туда и заниженное
  значение. Читатель, принявший `Size` за границу, вернул бы только первые имена и промолчал бы об
  этом: бинарь с динамическим CRT проехал бы как бинарь без единого redist-импорта. Фикстуры под
  это две (`--short-size` для каталога 1 и для каталога 13), и в них занижение реально: 20 байт
  вместо 60.
- **Отказ app-local меры мягкий вне релиза.** `cmake/msvc_redist.cmake` не находит нужного —
  `FATAL_ERROR` только при `LIKE_NES_RELEASE`, иначе строка статуса и пустой список: иначе любая
  MSVC-сборка падала бы на конфигурации, то есть релизная мера меняла бы условие коммит-гейта на
  единственной ОС, которую владелец проверить не может.
- **Порядок в `CMakeLists.txt` несущий**, как у `cmake/warnings.cmake`: рантайм есть свойство ЦЕЛИ,
  и цель, объявленная раньше нашего `include`, возьмёт динамический CRT, приведя в один образ вторую
  кучу. `assert_msvc_runtime_wired` читает это без сборки и без Windows — потеря строки иначе видна
  только на раннере, через полчаса и в чужом логе. Отсутствие в файле хоть одного
  `FetchContent_Declare` есть ОТКАЗ: сравнивать порядок не с чем, и «нарушений нет» тут означало бы,
  что гейт разучился читать дерево.
- **Закрытый список живёт в ДВУХ копиях** — glob-case в `release_crt_lib.sh` и regex в
  `cmake/msvc_redist.cmake`, по которому cmake решает, какие файлы класть рядом. Механической связи
  между ними нет, а расхождение молчит: cmake не положит файл, гейт не найдёт его, и увидит это
  только владелец на приехавшем пакете. Поэтому копии сверяются МЕЖДУ СОБОЙ
  (`assert_redist_list_mirrored`) — ровно форма `mirrors-group` из `ci_lint.py`, где внешнего
  эталона у списка тоже нет. Пустое с обеих сторон равно само себе, поэтому разбор, промахнувшийся
  мимо ОБОИХ файлов, есть отказ, а не «копии совпадают».
- **Пара копий вторая: ожидаемый состав против таблицы импортов.** Имя `like-nes/bin/vcruntime140.dll`
  в `expected_files` (`scripts/release_check_lib.sh`) написано РУКАМИ, и механической связи с тем,
  что рантайм на самом деле просит, не было — `list-drift` ровно там, где список эталона не имеет.
  `assert_redist_expected_named` сверяет их без учёта регистра, а ноль redist-импортов у настоящего
  `wgpu_native.dll` есть ОТКАЗ: пустое равно пустому, и предмет app-local меры исчез бы молча.
  Импорты забираются в переменную ДО фильтра — код возврата пайпа есть код ПОСЛЕДНЕЙ команды, и
  отказ читателя внутри `python3 … | crt_redist_lower` не виден вовсе (тот же класс уже чинили в
  `assert_crt_self_contained`); фикстура «таблица не прочитана» иначе падала бы по ЧУЖОЙ причине,
  и на первом прогоне падала.
- **Граница смешанного CRT, которую вертикаль СОЗДАЁТ, названа вслух** в шапке
  `cmake/msvc_runtime.cmake` и в ADR 0019 решением 41: наши цели уехали на `/MT`, предсобранный
  `wgpu_native.dll` остался на `/MD`, и в одном процессе живут две кучи. Безопасно это ровно потому,
  что через границу не проходит ВЛАДЕНИЕ — каждый объект wgpu освобождается его же `wgpu*Release`,
  отображённая память читается между `wgpuBufferGetConstMappedRange` и `wgpuBufferUnmap`, ни
  `FILE*`, ни дескрипторов CRT через границу не идёт, `stbi_image_free` зовётся на памяти
  вендоренного stb из НАШЕЙ сборки. Появится первый объект со свободным владением — решение
  пересматривается, а не дополняется. Гейту эта половина недоступна вовсе: обе кучи сходятся в
  одном процессе только на Windows, поэтому проверяет её владелец
  (`docs/owner-verification.md` §16, шаг 3: `editor_shell --gate6` пишет PNG).
- **Пропуск ВСЛУХ, а не молчаливый ноль**: пакета Windows на машине владельца нет — он собирается в
  CI, — поэтому в общем прогоне гейт печатает пять строк и `PASS`, прямо называя, чего он не
  осматривал. Те же два утверждения зовутся из `assert_ci_package` на ПРИЕХАВШЕМ из CI пакете — там
  бинари настоящие.
- Самопроверок **четыре, граница по предмету**, 40 контролей на дереве с выкачанной дистрибуцией, и каждая следующая зовётся
  ВНЕШНЕЙ командой, чтобы в логе стояло имя упавшего набора: `check_release_crt_selftest.sh` ломает
  ПАКЕТ (5 опорных `pass` и 8 отбитых порч — каталог без единого бинаря, наша `.dll` с динамическим
  CRT, app-local DLL, уехавшая из каталога исполняемого), `check_release_crt_reader_selftest.sh`
  кормит ЧИТАТЕЛЯ настоящими и синтетическими PE и держит якорь (3 и 10 — файл не PE, PE без
  таблицы, 32-разрядный образ, отложенные импорты обеих форм, заниженный `Size` в обоих каталогах),
  `check_release_crt_wiring_selftest.sh` ломает ДЕРЕВО (2 и 6 — `include` рантайма вырезан, уехал
  ниже первой зависимости, дерево без зависимостей вовсе; имя пропало из копии списка в шелле, в
  cmake, и разбор, не нашедший ни одной копии), `check_release_crt_named_selftest.sh` — вторую пару
  копий (2 и 4 — имя пропало из ожидаемого состава, лишнее имя в нём, рантайм без единого
  redist-импорта, нечитаемая таблица). **Дистрибуции в дереве нет — три кейса, которым нужен
  настоящий рантайм, пропускаются ВСЛУХ** (остаётся 1 и 2 у named-набора, у reader-набора — 2 и 9):
  утверждение без неё возвращает ноль пропуском, то есть опорный `pass` подтверждал бы ПРОПУСК, обе
  порчи получали бы тот же ноль, и набор падал бы по причине ОКРУЖЕНИЯ — неотличимо от честно
  сломанного утверждения, роняя весь этап preflight на свежем клоне (`build*` в `.gitignore`).
  Каталог дистрибуции внутри `build*` при этом назван ОДНИМ местом (`crt_dist_subdir`) — его ищет
  утверждение и по нему же строят фикстурные деревья оба набора; написанный руками в четырёх местах,
  он есть ровно `list-drift`: переезд FetchContent погасил бы одну копию и оставил другую.
  **Читатель PE в фикстуру копируется НЕ ОДНИМ ФАЙЛОМ**, и список его спутников выводится из него
  самого (`crt_copy_reader` в `release_crt_fixture_lib.sh`, общая фабрика обоих наборов): решение 23
  спеки #19 дало читателю соседний модуль переключения вывода, копировали по-прежнему только его
  самого, и запуск в фикстурном дереве умирал `ModuleNotFoundError`. Назвал это ОДИН кейс —
  якорь на настоящем рантайме, единственный из ждущих успеха; у named-набора обе порчи ждут ОТКАЗА
  утверждения, и чужой отказ читался бы там как «утверждение отбило порчу» — поэтому рядом с ними
  теперь стоит опорный `pass`, требующий, чтобы фикстурный читатель ЗАПУСКАЛСЯ.
  Каждое имя `assert_*`, которое набор зовёт, обязано
  быть ОПРЕДЕЛЕНО — незагруженная функция даёт код 127, а он ненулевой, и все ожидающие `fail`
  кейсы проезжали бы как «утверждение отбило подмену»: ровно так и вышло на первом прогоне, когда
  wiring-lib не был подключён.
- Гейт и его самопроверки идут в группе `preflight_release_rules.sh` рядом с установщиком Windows:
  сборки им не нужно. Шага в CI нет — на раннере Windows пакет собирается, но не осматривается, а
  приехавший оттуда проверяет `check_release_ci.sh` на машине владельца.

## Перед push — `scripts/preflight.sh`

Всё, что можно узнать про будущий прогон CI, не запуская CI: подпись DCO на коммитах ветки
(`scripts/check_dco.sh`) → статические правила дерева группой `preflight_tree_rules.sh` (линтер
workflow, инварианты `scripts/tree_invariants.sh` — тот же скрипт, что и шаги CI, — сверка копий
списка корней `scripts/check_tree_roots.py`, переключение вывода
`scripts/check_py_utf8.py`, бюджет длины `scripts/line_budget.py`, гейт документации
`scripts/check_docs.sh`, выбор bash `scripts/posix_bash_selftest.py` и гейт врезок
`scripts/check_docs_snippets.sh`, каждый со своей самопроверкой ПЕРЕД ним) → `actionlint` + `shellcheck` (severity `warning`) → `shellcheck` самих
гейт-скриптов → сборка в конфигурации CI → сборка полного набора опций → три проверки продуктов
сборки по одной (`scripts/check_goldens.sh debug|core|bundle`, тело Debug-этапа — отдельный
`scripts/check_debug_golden.sh`, а сверку `library.bundle` — `scripts/check_library_bundle.sh`:
голден физики в Debug, восемь голденов ядра, сверка `game.bundle` с исходниками — этап `bundle`
несёт ТРИ утверждения и требует собранного `build-ci`/`build-full`) → примеры документации
(`scripts/check_docs_examples.sh build-full` со своей самопроверкой перед ним: цели `doc_example_*`
живут в полном каталоге) → релизный пакет
(`scripts/check_release.sh`, собирается из уже собранного `build-full`) → образ macOS
(`scripts/check_release_dmg.sh`) → AppImage (`scripts/check_release_appimage.sh`) → сборка gcc,
если он установлен. Установщик Windows (`scripts/check_release_msi.sh`) и гейт CRT (`scripts/check_release_crt.sh`)
стоят НЕ здесь, а в группе `preflight_release_rules.sh` вместе с правилами: сборки им не нужно —
стейдж установщик делает себе сам, а CRT читает таблицы импортов. Этапы не
останавливают друг друга: один прогон обязан выдать все находки разом.

**Групп две, и признак у них один — «сборки и сети не нужно».** `preflight_tree_rules.sh` читает
дерево как ТЕКСТ, `preflight_release_rules.sh` — как будущий пакет. Первая появилась не по вкусу:
`preflight.sh` уже разрезали, когда он дорос до 297 строк при жёстком пороге 250, и два этапа
документации подняли его обратно за мягкий лимит. Лечится это декомпозицией по границе, которую
файл уже провёл для релиза, а не строкой в allowlist — следующий такой гейт дописывает строку в
группу.

**На Windows этап `actionlint` идёт без своей shellcheck-интеграции** (`-shellcheck=`). Не выбор
вкуса: actionlint кормит shellcheck через пайп и на git-bash не дожидается ответа никогда — прогон
1 сентября 2026 простоял час, накопив 0.9 с процессорного времени. Разведено врозь: без shellcheck
в `PATH` тот же вызов отдаёт вердикт мгновенно, с ним — не отдаёт вовсе, `-shellcheck=` при том же
`PATH` снова мгновенен, а сам shellcheck из stdin отвечает. Скрипты ВНУТРИ workflow остаются за CI,
где этап идёт на Linux; гейт-скрипты дерева проверяет следующий этап, и он на Windows работает.
Висящий гейт хуже падающего: падение читается как находка, а час тишины — как «ещё считает».

Сам `preflight.sh` держит **порядок и условия** этапов, а не их тела: проверки, доросшие до
собственного имени, вынесены в свои скрипты (`check_dco.sh`, `check_goldens.sh`,
`check_debug_golden.sh`, `check_library_bundle.sh`)
и зовутся как
внешние команды. По той же границе разошёлся и он сам, когда упёрся в бюджет длины: помощники
этапа (`stage`/`skip`/`stages_verdict`) живут в `preflight_stage_lib.sh`, а шесть релизных
правил, которым не нужна сборка, — в группе `preflight_release_rules.sh` с собственным вердиктом.
Лечится это декомпозицией, а не строкой в allowlist: именно `preflight.sh` стоит в разделе про
бюджет как пример файла, доросшего до 297 строк при жёстком пороге 250. Так каждую можно прогнать по одной, не выбирая между «весь preflight» и «руками из
истории шелла», и в логе стоит имя упавшей, а не «что-то из трёх разошлось».

Сверка бандла стоит после сборок, потому что сверяет их продуктом. `example_ugly_game/assets/game.bundle`
лежит в git готовым, а перепечь его ЦЕЛИКОМ негде, кроме машины владельца: текстурная секция тянет
`tint` и `basisu`. Поэтому `assetc --verify-game` перепекает секции, у которых пекарь — чистый
парсер (`input.txt`, `achievements.txt`), и сверяет их с тем, что лежит в бандле. До этого гейта
правка раскладки без перепекания проезжала молча, хотя на бандле стоят и игра-образец, и
sim-golden. Гейт несёт собственный позитивный контроль: испорченная копия таблицы обязана быть
отбита ТЕМ ЖЕ сравнением — иначе первая же опечатка в нём делает гейт вакуумно зелёным. Тот же
шаг гоняется в CI на трёх ОС.

Второе утверждение этапа — `framework_character_bundle_test`: он читает секцию `movement` из того же
бандла ЧИТАТЕЛЕМ и сверяет поля с `default_profile()`. Первым оно не заменяется: `--verify-game`
сравнивает байты с перепечённым текстом и переживает согласованную перестановку полей в пекаре и
читателе молча, а сверка полей — нет.

Этап подписи стоит первым и на полсекунды: job `dco.yml` — единственный, который срабатывает
**только на pull_request**, поэтому коммит без `-s` доживает незамеченным до самого раунда, а
чинится единственным способом — `git rebase --signoff` + `--force-with-lease`, то есть
переписыванием всех SHA ветки, после чего протухают ссылки на коммиты в ADR, теле PR и dev-log.
Критерий тот же, что у job'а (подпись совпадает с автором **или** коммиттером): локально строже
значило бы отбивать то, что CI пропускает.

`tree_invariants.sh` собирает четыре греп-гейта: условная компиляция по ОС, `argv` и окружение
только через швы (инвариант 2 спеки #12) и направление зависимостей подсистем (инвариант 1 спеки
#14). Каждый держит ПОЗИТИВНЫЙ КОНТРОЛЬ: сначала утверждает, что видит то, что обязано быть
(совпадения внутри шва, ≥ 15 найденных `main`, рёбра линковки), и только потом ищет нарушение —
греп-гейт без этого зелен вакуумно после первой же опечатки в пути. CI зовёт их по одному
(`… .sh seam|argv|env|deps`), чтобы в логе было названо сломанное; preflight — все разом.

**У направления зависимостей ДВЕ половины, и вторую до аудита #21 не проверял никто.** Первая —
подсистема не зависит от СЛОЯ `framework`; вторая — подсистема не читает заголовков ПОТРЕБИТЕЛЯ
(`tools`, `example_ugly_game`, `docs/examples`), и `engine/achievements/plugin_host_test.cpp`
включал `../../example_ugly_game/backend_host.hpp`: стрелка, развёрнутая вверх, в каталоге
подсистемы. Оба списка ВЫВОДЯТСЯ — подсистемы обходом `engine/*/`, потребители из `ROOTS_CODE`:
рукописный перечислял восемь подсистем при двенадцати в дереве, то есть ребро из
`engine/achievements`, `engine/hotreload`, `engine/core` и `engine/platform` не отбивалось ничем.
Ребро подсистема→подсистема при этом законно и не ловится: слои и потребители — не всё дерево.
Позитивный контроль у второй половины свой (тот же поиск по тому же корню обязан видеть включения
вообще), а фикстур у семейства не было вовсе — их завёл
`scripts/tree_invariants_deps_selftest.sh` (5 опорных `pass`, 10 отбитых порч). Что каждая половина
РАСШИРИЛА покрытие, доказано ПОДМЕНОЙ: копия гейта с прежним рукописным списком и копия с вырезанной
второй половиной обязаны свою порчу **пропустить**. Швы ОС, `argv` и окружение своего позитивного
контроля пока не имеют, и это сказано вслух в шапке набора.

Сам список корней дерева живёт в **двух копиях** — `ROOTS`/`ROOTS_CODE` в `tree_invariants.sh` и
`ROOTS` в `ascii_output_check.py`, — и внешнего эталона у него нет: «все каталоги репозитория» тут
неверно (`deps/`, `build*`, `docs/` под инварианты швов не попадают), а вывести одну копию из другой
нечем — файлы на разных языках и запускаются порознь. Значит копии сверяются МЕЖДУ СОБОЙ
(`scripts/check_tree_roots.py`) — ровно форма `mirrors-group` из `ci_lint.py` и та же мера, что у
пары списков redist-имён в гейте CRT. Расхождение молчит: корень, добавленный в одну копию, честно
проходит инварианты швов и остаётся вне ASCII-проверки, и узнают об этом по коду, который туда
положат ПОТОМ. Пустая копия — ОТКАЗ: разбор, промахнувшийся мимо обоих файлов, равняет пустое с
пустым. Самопроверка (`--selftest`, 6 кейсов) требует, чтобы порча РЕАЛЬНО меняла файл: подмена,
ничего не подменившая, читается как «утверждение её отбило».

Этап Debug стоит отдельно от двух сборок выше и собирает только цели на пути состояния
(`STATE_TARGETS` в `scripts/check_debug_golden.sh`, список обязан совпадать с Debug-шагом `ci.yml`):
вопрос у него не про предупреждения, а про то, что голден совпадает на `-O0` и на `-O3`. В целочисленной арифметике
расхождение между уровнями оптимизации — это UB, то есть право компилятора выкинуть проверку, а не
«погрешность» (инвариант 1 спеки #15 требует совпадения в Debug И Release). `build_check.sh`
принимает конфигурацию через `LIKE_NES_BUILD_TYPE` и **переконфигурирует каталог**, если тот собран
не ею: каталог, однажды сконфигурированный Debug'ом, иначе навсегда оставался бы им и молча
подменял бы релизный коммит-гейт.

Две конфигурации, потому что набор опций меняет состав целей: предупреждение внутри выключенной
цели (imgui, miniaudio, wasm, IDE) в headless-сборке не всплывает. Локально не проверяется и
остаётся за CI: **MSVC `/W4`**, поведение Windows-раннера и lavapipe/Vulkan на Linux.

Этап «Сборка gcc» на macOS **пропускается**: у gcc нет ObjC ARC для `.mm`, а заголовки Apple SDK
написаны на блоках. Обещать его после `brew install gcc` было неверно — там он не собирает дерево
вообще.

## Аудит чужим компилятором — `scripts/tu_sweep.py`

```
python3 scripts/tu_sweep.py build-sweep      # каталог сконфигурирован ЦЕЛЕВЫМ компилятором
```

Обходит `compile_commands.json` и компилирует каждый TU по одному. Нужен там, где чужой компилятор
не собирает дерево ЦЕЛИКОМ: сборка встаёт на первой упавшей цели и не даёт сказать про остальные
ничего, хотя несобираемость обычно локальна — на macOS gcc умирает на трёх файлах из ста семидесяти.
Независимая компиляция TU это разводит. Так найден `-Wstringop-overflow` в `tools/ide/game_child.cpp`
(разыменование nullptr), которого не видел ни один раннер.

`-Werror` из команд снимается: обход — аудит, а не гейт, и он обязан выдать ВСЕ находки TU, а не
первую. Гейт остаётся у `build_check.sh`. Пропущенные файлы печатаются поимённо — «пропущено молча»
и «находок нет» с одного взгляда неразличимы (то же основание, что у правила `vacuous-gate` в
`ci_lint.py`). Не в `checks.json`: требует каталога под другой компилятор, запускается руками.

## После push — `scripts/ci_watch.sh`

```
bash scripts/ci_watch.sh                   # прогоны HEAD
bash scripts/ci_watch.sh <sha>
bash scripts/ci_watch_selftest.sh          # вердикт: правила проверяются сломанными реализациями
bash scripts/ci_watch_wait_selftest.sh     # ожидание: опросы и последний взгляд
```

Ждёт, пока GitHub досчитает ВСЕ прогоны коммита, и печатает их job'ы построчно. Не гейт и не в
`checks.json`: требует сети и осмысленен только после push — то же место, что у `tu_sweep.py`.

Кодов возврата **три**, и третий — весь смысл файла: `0` все прогоны зелёные, `1` хоть один
красный, `2` **узнать не удалось**. Разделены они потому, что предыдущая версия наблюдателя —
инлайновый цикл в шелле — 22 августа напечатала `timeout` при двух зелёных прогонах часовой
давности, и читалось это как «CI не досчитал». Врала она тремя способами разом, и каждый закрыт:

| поломка | чем была | чем закрыта |
|---|---|---|
| разбор | `set -- $s` под zsh не разбивает строку на слова, совпадения со статусом не случалось НИКОГДА | файл зовётся через `bash <файл>` — капкан снят устройством, а не дисциплиной |
| сбой запроса | `gh run list` вернул `EOF`, переменная пустая, цикл считает «ещё идёт» | отказы считаются, пять подряд — код `2` со словами, один — строка в лог |
| охват | смотрела `--limit 1`, то есть один прогон из набора | ждёт все прогоны коммита, и сколько их — считает по триггерам, а не числом в коде |

Сколько прогонов ждать — **выводится из триггеров** `.github/workflows/*.yml` для тех событий,
которые видны в ответе GitHub. Первая версия держала это константой `2` («на push идут `ci` и
`dco`») и была неверна ровно на главном пути: `dco.yml` подписан ТОЛЬКО на `pull_request`, поэтому
push в ветку даёт ОДИН прогон, ожидание двух не сбывалось никогда, и наблюдатель сорок минут молчал
на зелёном коммите, отдавая «узнать не удалось». `release.yml` подписан на push с фильтром `tags:` и
подписчиком push'а ветки не считается. Форму `on:`, которую разбор не понял, наблюдатель называет
словом и отказывается числом: «не понял» и «подписчиков нет» дают одно и то же ожидание и расходятся
только в том, врёт оно или нет. Ручка `CI_WATCH_EXPECT_RUNS` осталась — но без дефолта.

Зелёный исход подтверждается **вторым опросом с тем же набором прогонов**. Число, выведенное из
событий, знает про уже зарегистрированные прогоны и ничего не знает про те, что появятся через
секунду: push в ветку с открытым PR порождает прогоны двух событий, и между ними есть щель, где
«все, кого вижу, зелёные» — правда про половину набора. Красный так не ждёт: красное красно сразу.

Коммит на входе разворачивается в **полный** sha: `gh run list --commit` сравнивает строку как
есть, поэтому короткий `7cc3ba9` находит ноль прогонов и выглядит как «прогонов нет». Тот же класс,
что ловит правило `vacuous-gate` в `ci_lint.py`, — и найден он живым прогоном, а не рассуждением.

Суждение о вердикте живёт отдельно от сети (`ci_watch_lib.sh`) и проверяется фикстурами без единого
запроса. Позитивный контроль двойной: сломанная фикстура обязана валить набор, и **сломанные
реализации** обязаны быть отбиты — набор, который их пропускает, выглядит ровно как честный. Их
пять: три на вердикт (всегда зелёный; игнорирует число прогонов; красный проигрывает
незавершённому) и две на счёт ожидаемого (константа `2`; разбор, не заметивший фильтра по тегам).
Счёт проверяется и на живом дереве — «на push подписан один workflow, на pull_request два» стоит
утверждением, а не комментарием.

Перед тем как сказать «узнать не удалось», наблюдатель **смотрит ещё раз** — двумя запросами
подряд, и если вердикт из них выходит, он его и отдаёт. Дедлайн мерится стенными часами, а узнаёт
наблюдатель что-либо только опросом, и до 2026-08-24 эти две величины ничем не были связаны: 24
августа он напечатал «УЗНАТЬ НЕ УДАЛОСЬ» на коммите `ed34c6d`, чей прогон досчитал зелёным за
двадцать минут до этого, без единой строки о сбое запроса, а ручной прогон того же файла на том же
коммите выдал `success` за два опроса. **Механизм, задавивший опросы, не установлен** — и выдумывать
его вместо улики хуже, чем не знать, — поэтому починка бьёт по обоим следствиям сразу: последний
взгляд отбирает у молчания право быть вердиктом, а строка «опросов сделано N из M» и предупреждение
«СМОТРЕЛ ОН МЕНЬШЕ ПОЛОВИНЫ ожидаемого» делают следующий такой случай утверждением о наблюдателе, а
не о CI.

Ожидание проверяется своим файлом — `ci_watch_wait_selftest.sh`, который зовётся из
`ci_watch_selftest.sh` внешней командой. Граница между ними по предмету, а не по счётчику строк:
вердикт — чистая функция от набора прогонов и проверяется фикстурами, а ожидание есть поведение
ЦИКЛА во времени, ради которого приходится подменять `gh` заглушкой и гонять самого наблюдателя
целиком. Позитивных контролей у него два: сломанные суждения о числе опросов (всегда «наблюдал»,
всегда «спал») обязаны быть отбиты, и **наблюдатель без последнего взгляда** — та же реализация с
вырезанной строкой `final_look` — обязан валить фикстуру, которую починенный проходит. Без второго
контроля фикстура зелена и на том наблюдателе, который врал.


## Коммиты

Conventional commits, английский: `feat(scope): …`, `fix(ci): …`, `docs: …`.
Без AI-подписей и `Co-Authored-By`. Не коммитить код, не прошедший линтер/типы/сборку.

## Push (переопределяет правило 11 глобального CLAUDE.md)

**`git push` в `dev` и фича-ветки — без спроса**, сразу после проверенного коммита. Решение
владельца от 2026-08-10: в этом репозитории единственный способ узнать про MSVC `/W4`, поведение
git-bash на Windows-раннере и lavapipe — прогон CI, а ожидание апрува на push просто отодвигает
находку на несколько часов, ничего не защищая. Проверенный коммит без прогона — это незаконченная
проверка, а не готовая работа.

Границы остаются: **push в `main` запрещён** (только merge из PR раунда), `--force`/`--force-with-lease`
по чужой истории — по-прежнему с явного разрешения, и правило 12 сильнее этого разрешения —
непроверенное не пушится, потому что не коммитится.
