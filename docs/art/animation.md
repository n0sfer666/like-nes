# Анимация: клетка, ключи, in-betweens, боксы

[← к пакету](README.md) · раскадровка — [clips.md](clips.md) · порядок шагов — [workflow.md](workflow.md)

## Клетка и пивот

| Параметр | Значение | Почему |
|---|---|---|
| Клетка кадра | **192×192** | крупный (135 px) с размахом руки и монах с выпадом помещаются без обрезки |
| Пивот | **низ-центр клетки**, точка (96, 192) | ставит движок сам, рисовать его не нужно |
| Линия земли | нижний ряд пикселей, y = 191 | подошвы стоящей фигуры касаются его во всех наземных кадрах, центр опоры — колонка 96 |
| Направление | лицом **вправо** | влево фигуру отражает движок вместе с боксами |
| Корневое движение | **нет** | шаг, бег, прыжок и отлёт двигает код; ступни остаются у пивота |
| Лист | 10 колонок, ширина 1920, **не больше 10 рядов (100 клеток)** | бейк отбивает сторону листа больше 2048 |

Клип занимает клетки **одного ряда** листа. Долгий кадр — это один рисунок в нескольких клетках
подряд ([clips.md](clips.md)). Пилотный монах — 60 клеток, рядовой — 32: каждый умещается в один
лист. Полный набор героя больше 100 клеток и делится на несколько листов, их чтение в движке
появится в В6 спеки #29.

## Ключевые позы — ChatGPT

**Референс:** model sheet персонажа и `style-ref.png`. Для сложной позы ещё и **манекен**: фигурка
из палок, нарисованная в Pixelorama на клетке 192×192 и экспортированная в PNG. Ракурс и угол
конечностей она задаёт точнее слов.

```text
Pixel art game sprite frames of the character from the attached model sheet, same design,
same proportions, same colours. Flat solid magenta background #FF00FF, no text.
Draw <N> poses in one row, all facing right, all with the same scale and the same ground line:
<POSE 1>; <POSE 2>; ...
Full body visible in every pose, nothing cropped. 1-pixel outline, stepped cel shading, warm
rim light from the left, cool blue shadows. No motion blur, no speed lines, no ground shadow.
```

Поза описывается фазой движения и положением конечностей, а не названием приёма. Плохо:
`a jab`. Хорошо: `weight on the front foot, front arm fully extended at shoulder height with an
open palm, rear hand guarding the chin, torso turned toward the viewer`.

За один запрос — **не больше 4 поз**, все из одного клипа. Позы разных клипов в одном запросе
расходятся по масштабу.

## Приёмка кадра

- [ ] тот же персонаж: лицо, борода или причёска, одежда, аксессуары (чётки, ленты, кинжалы, наручи);
- [ ] после сетки рост в стойке равен росту из [characters.md](characters.md) ±2 px, у
  приседа и наклона — по позе;
- [ ] наземный кадр стоит на нижнем ряду клетки, центр опоры — в колонке 96;
- [ ] руки и оружие на месте: число пальцев не проверяется, число кистей и кинжалов — да;
- [ ] только тона палитры, сменные части — в своих рампах;
- [ ] фигура целиком внутри клетки 192×192.

## In-betweens — Pixelorama

Генератор не держит соседние кадры одного движения. Промежуточные кадры дорисовываются руками.

1. Ключи раскладываются по кадрам клипа по раскадровке [clips.md](clips.md), пустые кадры между
   ними — будущие in-betweens.
2. **Onion skinning** включён (кнопка на таймлайне): виден предыдущий и следующий кадр.
3. In-between собирается **из частей ключей**, а не рисуется заново: голова и торс копируются из
   ближайшего ключа и сдвигаются по дуге. Конечность выделяется (**Lasso**) и поворачивается
   через **Effects → Transform → Rotate Image** с *Type: cleanEdge*, затем чистится по пикселю.
4. Удар держится на кадре сразу после активного (размазанный кадр, *smear*): рука вытянута на
   2–4 px дальше ключа, кисть растянута вдоль движения. Этот кадр заменяет промежуточные кадры
   хлёста.
5. Повтор вместо нового рисунка: долгий кадр — копия соседнего (правый клик по кадру →
   **Clone Frame**), у цикла ходьбы вторая половина — первая с поменянными ногами.

Цель — минимум рисунков при читаемом движении. Раскадровка в [clips.md](clips.md) уже посчитана
так: из 48 рисунков пилотного монаха ключей 24, остальное — in-betweens.

Предпросмотр клипа: поле **FPS** на таймлайне = 60 / тики клипа (3 тика — 20, 4 — 15, 6 — 10,
9 — 6.7), затем Play. Теги в `.pxo` (**New Tag**) нужны только для глаз: движок читает клипы из
`.sheet`.

## Боксы и события

Клипы, боксы и события лежат в текстовом файле `<персонаж>.sheet` рядом с листом. Формат целиком —
в руководстве движка [«Анимации в Aseprite»](../ru/guide/aseprite-animations.md#без-aseprite), раздел
«Без Aseprite». Строки `image`, `grid`, `clip` и `event` пилота уже готовы в
[clips.md](clips.md) §Раскладка листа. Руками дописываются только боксы:

```text
box|<клип>|<клетка>|<бокс>|<x>|<y>|<w>|<h>
```

**Клетка** считается от 0 внутри клипа. В Pixelorama номера кадров идут через весь проект с 1:
клетка = номер кадра − номер первого кадра клипа.

**Координаты** снимаются курсором: Pixelorama показывает пиксель под ним. Навести на левый
верхний пиксель бокса (`px1`, `py1`), затем на правый нижний (`px2`, `py2`):

```text
x = px1 − 96        y = py1 − 192        w = px2 − px1 + 1        h = py2 − py1 + 1
пример: ладонь strike1 на клетке 2 занимает пиксели от (150, 92) до (163, 101)
        → box|strike1|2|hit0|54|-100|14|10
```

`y` всегда отрицательный: бокс выше пивота. Бокс, вылезший за клетку, бейк отбивает с номером
строки.

| Бокс | Где | На каких клетках |
|---|---|---|
| `push` | ступни, ширина плеч, высота 8 px над линией земли (`y` = −8, `h` = 8) | на всех, кроме `down` и `thrown` |
| `hurt0` | голова и торс | на всех, кроме неуязвимых (`getup` 0–1, `dodge` 1–2) |
| `hurt1` | ноги от пояса до земли | там же, где `hurt0` |
| `hit0` | кулак, ладонь, стопа или клинок плюс 2 px | только активные клетки из [clips.md](clips.md) |
| `hit1` | второй бокс широкого удара (супер, размах крупного) | там же |

Бокс задаётся **на каждую клетку отдельно**: следующая клетка его не наследует. Нет строки — нет
бокса, выключать удар отдельным ключом не нужно. Клетки-повторы получают те же строки с другим
номером клетки.

**События** — строки `event|<клип>|<клетка>|<имя>`, одно событие на клетку. Имена из
[clips.md](clips.md) — предложение пакета: какие события читает игра, задаёт её код (В3 спеки #29).

## Приёмка клипа

- [ ] число клеток и тики совпадают с [clips.md](clips.md), порядок кадров в `.pxo` — с раскладкой;
- [ ] клип проигрывается в Pixelorama без скачка роста и без «плавания» ступней у пивота;
- [ ] бейк проходит, а `clip_dump` показывает `hit0` только на активных клетках
  ([workflow.md](workflow.md) §9);
- [ ] у цикла в строке `clip` стоит `|loop`, у разового клипа его нет;
- [ ] события стоят на клетках из [clips.md](clips.md).

## Дрейф

- *Кадр «толще» или «выше» соседних.* Не перерисовывать целиком: выровнять масштаб по росту
  головы и длине предплечья model sheet, лишнее срезать по контуру.
- *Генератор не даёт позу.* Приложить манекен и сократить запрос до одной позы. Не помогло —
  собрать позу из частей принятых кадров ([README.md](README.md) §Общие правила дрейфа).
- *Монах в ударе теряет рукав.* Рукав — отдельный слой в `.pxo`. Он копируется из ключа и
  поворачивается вместе с рукой.
