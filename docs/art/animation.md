# Анимация: ячейка, ключи, in-betweens, боксы

[← к пакету](README.md) · раскадровка — [clips.md](clips.md)

## Ячейка и пивот

| Параметр | Значение | Почему |
|---|---|---|
| Ячейка кадра | **192×192** | крупный (135 px) с размахом руки и монах с выпадом помещаются без обрезки |
| Пивот | слайс `pivot`, точка **(96, 180)** во всех кадрах | центр стопы на линии земли; 11 px ниже — запас под пыль и брызги |
| Линия земли | y = 180 | подошвы стоящей фигуры касаются её во всех наземных кадрах |
| Направление | лицом **вправо** | влево фигуру отражает движок вместе с боксами |
| Корневое движение | **нет** | шаг, бег, прыжок и отлёт двигает код; ступни остаются у пивота |
| Лист | 8 колонок, ширина 1536, **не больше 10 рядов (80 кадров)** | бейк отбивает сторону листа больше 2048 |

Пилотный набор монаха — 48 кадров, рядового — 29 ([clips.md](clips.md)): каждый умещается в один
лист. Полный набор героя больше 80 кадров и делится на несколько листов, их чтение в движке
появится в В6 спеки #29.

## Ключевые позы — ChatGPT

**Референс:** model sheet персонажа и `style-ref.png`. Для сложной позы ещё и **манекен**: фигурка
из палок в Aseprite на ячейке 192×192, экспортированная в PNG. Ракурс и угол конечностей она
задаёт точнее слов.

```text
Pixel art game sprite frames of the character from the attached model sheet, same design,
same proportions, same colours. Flat solid magenta background #FF00FF, no text.
Draw <N> poses in one row, all facing right, all with the same scale and the same ground line:
<POSE 1>; <POSE 2>; ...
Full body visible in every pose, nothing cropped. 1-pixel outline, stepped cel shading, warm
rim light from the left, cool blue shadows. No motion blur, no speed lines, no ground shadow.
```

Поза описывается фазой движения и положением конечностей, а не названием приёма. Плохо:
`a jab`. Хорошо: `weight on the front foot, front arm fully extended at shoulder height with an
open palm, rear hand guarding the chin, torso turned toward the viewer`.

За один запрос — **не больше 4 поз**, все из одного клипа. Позы разных клипов в одном запросе
расходятся по масштабу.

## Приёмка кадра

- [ ] тот же персонаж: лицо, борода или причёска, одежда, аксессуары (чётки, ленты, кинжалы, наручи);
- [ ] после сетки рост в стойке равен росту из [characters.md](characters.md) ±2 px, у
  приседа и наклона — по позе;
- [ ] наземный кадр стоит на линии земли, центр опоры — у пивота;
- [ ] руки и оружие на месте: число пальцев не проверяется, число кистей и кинжалов — да;
- [ ] только тона палитры, сменные части — в своих рампах;
- [ ] фигура целиком внутри ячейки 192×192.

## In-betweens — Aseprite

Генератор не держит соседние кадры одного движения. Промежуточные кадры дорисовываются руками.

1. Ключи раскладываются по кадрам тега по раскадровке [clips.md](clips.md), пустые кадры между
   ними — будущие in-betweens.
2. **Onion skin** включён: виден предыдущий и следующий ключ.
3. In-between собирается **из частей ключей**, а не рисуется заново: голова и торс копируются из
   ближайшего ключа и сдвигаются по дуге, конечности поворачиваются инструментом **Rotate** с
   алгоритмом **RotSprite** и затем чистятся по пикселю.
4. Удар держится на кадре сразу после активного (размазанный кадр, *smear*): рука вытянута на
   2–4 px дальше ключа, кисть растянута вдоль движения. Этот кадр заменяет промежуточные кадры
   хлёста.
5. Повтор вместо нового кадра: стойка в начале и в конце удара — одна и та же ячейка, у цикла
   ходьбы вторая половина — первая с поменянными ногами.

Цель — минимум кадров при читаемом движении. Раскадровка в [clips.md](clips.md) уже посчитана
так: из 48 кадров пилотного монаха ключей 24, остальное — in-betweens и повторы.

## Боксы и события

Слайсы и их правила описаны в руководстве движка
[«Анимации в Aseprite»](../ru/guide/aseprite-animations.md#боксы-удара-боксы-попадания-и-пивот).
Здесь — только как их ставить на бойцов пилота.

| Слайс | Где | Когда включён |
|---|---|---|
| `pivot` | точка (96, 180) | один ключ на кадре 0 листа |
| `push` | ступни, ширина плеч, высота 8 px над линией земли | всегда, кроме `down` и `thrown` |
| `hurt0` | голова и торс | всегда, кроме неуязвимых кадров (`getup` 0–1, `dodge` 1–2) |
| `hurt1` | ноги от пояса до земли | там же, где `hurt0` |
| `hit0` | кулак, ладонь, стопа или клинок плюс 2 px | только активные кадры, отмеченные в [clips.md](clips.md) |
| `hit1` | второй бокс широкого удара (супер, размах крупного) | там же |

Бокс выключается ключом **0×0** на кадре сразу после активного. Забытый выключающий ключ оставляет
удар активным до конца клипа: это первое, что проверяется на приёмке клипа.

**События** — user data тега, `<кадр>:<событие>`, кадр считается от 0 внутри тега. Имена из
[clips.md](clips.md) — предложение пакета: какие события читает игра, задаёт её код (В3 спеки #29).

## Приёмка клипа

- [ ] число кадров и длительности совпадают с [clips.md](clips.md);
- [ ] клип проигрывается в Aseprite без скачка роста и без «плавания» ступней у пивота;
- [ ] у ударов `hit0` включён только на активных кадрах и выключен ключом 0×0 после них;
- [ ] у тега задан повтор: цикл — без числа, разовый клип — **1** (любое другое число бейк отбивает);
- [ ] события в user data тега, кадры внутри тега.

## Дрейф

- *Кадр «толще» или «выше» соседних.* Не перерисовывать целиком: выровнять масштаб по росту
  головы и длине предплечья model sheet, лишнее срезать по контуру.
- *Генератор не даёт позу.* Приложить манекен и сократить запрос до одной позы. Не помогло —
  собрать позу из частей принятых кадров ([README.md](README.md) §Общие правила дрейфа).
- *Монах в ударе теряет рукав.* Рукав — отдельный слой в `.aseprite`. Он копируется из ключа и
  поворачивается вместе с рукой.
