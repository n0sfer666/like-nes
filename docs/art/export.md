# Экспорт: от картинки генератора к листу

[← к пакету](README.md)

Генератор отдаёт картинку «под пиксель-арт»: пиксели в ней разного размера, тонов сотни, край
фигуры размыт в фон. Этот файл делает из неё настоящий спрайт: ровная сетка, только тона
[мастер-палитры](style-bible.md), прозрачный фон, лист с тегами и слайсами.

## Хромакей

1. Картинка открывается в Aseprite как есть.
2. **Edit → Replace Color**: `#ff00ff` → прозрачный, допуск 20–30. Меньший допуск оставляет
   розовую кайму, больший съедает пурпурные и красные тона фигуры.
3. Остаток каймы — полупрозрачные и розоватые пиксели вдоль контура — снимается на шаге
   квантизации ([§Палитра](#палитра)) и чисткой контура.

## Сетка

Рост фигуры на картинке генератора произвольный, рост в игре задан
([characters.md](characters.md)). Масштаб считается по росту, а не по размеру пикселя картинки:

```text
масштаб, % = целевой рост / рост фигуры на картинке × 100
пример: монах 96 px, на картинке 610 px → 15.7 %
```

1. **Sprite → Sprite Size**, *Lock Ratio*, масштаб в процентах, метод **Bilinear**. Ближайший
   сосед на картинке без настоящей сетки рвёт контур и теряет тонкие детали.
2. Сразу после — квантизация в палитру ([§Палитра](#палитра)): она убирает промежуточные тона,
   которые принёс Bilinear.
3. **Чистка по пикселю.** Контур — ровно 1 px тоном `ink`, без «двойных» углов и разрывов. Глаза,
   кисти, пряжки и бусины проверяются отдельно: на этом росте деталь — 1–3 пикселя, и квантизация
   их чаще всего путает с соседним тоном.
4. Рост проверяется линейкой (**View → Show → Pixel Grid**): от подошвы до макушки в стойке —
   значение из таблицы ±2 px.

Фоны масштабируются так же, но по ширине: план — 640 px ([backgrounds.md](backgrounds.md)),
лишняя высота срезается сверху у неба и снизу у переднего плана.

## Палитра

Палитра пилота — [pilot.gpl](pilot.gpl): все рампы style bible по порядку, вариант A рядового,
имя тона — `<рампа>-<ступень>`, ступень 0 — самая тёмная.

1. **Palette → Load Palette** → `pilot.gpl`.
2. **Sprite → Color Mode → Indexed**, без дизеринга (*Dithering: None*). Каждый пиксель
   получает ближайший тон палитры.
3. Файл остаётся **индексным** на всём пути до экспорта: перекраска и проверка рамп работают
   с номером тона, а не с цветом.

Правка тона — правка палитры: тон меняется в таблице [style-bible.md](style-bible.md), затем в
`pilot.gpl` (строка с тем же именем), затем **Palette → Load Palette** в каждом `.aseprite`.
Номера тонов не сдвигаются, кадры перерисовывать не нужно. Новый тон добавляется **в конец** своей
рампы только вместе с новой строкой таблицы, удалять тона нельзя: номера всех следующих сдвинутся.

## Рампы

Сменная часть врага лежит целиком в своей рампе `swap-*`, и тона этой рампы нигде больше нет. По
ним перекрашивается вариант, поэтому протёкший тон — брак, а не мелочь.

**Протекло.** Квантизация отдала часть пикселей жилета в `shadow` или, наоборот, тон `swap-sash` —
коже. Чинится по маске части:

1. Часть выделяется (**Magic Wand** с *Contiguous* по жилету, добор **Lasso** с Shift).
2. **Edit → Replace Color** внутри выделения: чужой тон → тон своей рампы той же ступени
   (тёмный — в тёмный, светлый — в светлый).
3. **Select → Inverse**, и та же замена в обратную сторону: тона `swap-*` вне части уходят в
   рампу соседнего материала.

**Проверка.** **Select → Color Range** по каждому тону `swap-cloth` и `swap-sash`: выделение
попадает только на свою часть во всех кадрах.

**Три варианта рядового.** В индексном файле вариант — это 8 других строк палитры:

1. В палитре `.aseprite` тоны `swap-cloth-0..3` и `swap-sash-0..3` меняются на hex варианта B
   или C из [style-bible.md](style-bible.md) §Мастер-палитра.
2. Файл сохраняется копией (`bandit-b.aseprite`, `bandit-c.aseprite`) только для показа: в игре
   вариант перекрашивает движок, лист рядового один.

**Приёмка:** три варианта стоят рядом и различаются только одеждой и поясом; кожа, волосы и
контур у всех трёх одинаковы.

## Бесшовный слой

Движок повторяет слой фона по x, поэтому правый край продолжает левый.

1. **View → Tiled Mode → X Axis**: холст повторяется слева и справа, шов виден посередине.
2. Шов закрашивается прямо в этом режиме: кисть, проходящая край холста, рисует на другом его
   краю.
3. Линия горизонта, хребты и крыши на левом и правом краю стоят на одной высоте — иначе шов
   виден ступенькой при любой заплатке.

Тайлы 16×16 проверяются так же, но по обеим осям (**Tiled Mode → Both Axes**).

## Экспорт листа

Настройки **File → Export Sprite Sheet** — в руководстве движка
[«Анимации в Aseprite»](../ru/guide/aseprite-animations.md#экспорт-листа). Для пилота:

| Поле | Значение |
|---|---|
| Layout | *By Rows*, 8 колонок |
| Sprite | ячейка 192×192, без *Trim* (пивот считается от угла ячейки) |
| Output | PNG + JSON *Array*, *Tags* и *Slices* включены |
| Имя | `<персонаж>.png` и `<персонаж>.json`: `monk`, `bandit` |

Фон — один PNG на план, RGBA, имя `<часть>-<номер слоя>-<что>.png`: `village-1-mountains.png`.
Тайлсет — один PNG, тайлы 16×16 вплотную.

Исходники `.aseprite` и выгрузки до В6 спеки #29 лежат у владельца. В движок они попадают
вместе с бейком палитры и листов в В6.

## Лицензия и журнал генераций

Арт пилота — собственный арт игры: автор — владелец, лицензия **CC0-1.0**. Схема
`LICENSES.toml` сейчас описывает только чужие паки и требует у пака `url`. Запись собственного
пака с полем генератора добавляет В6.

До тех пор у каждого принятого файла ведётся строка журнала — она понадобится и для
`LICENSES.toml`, и для раскрытия ИИ-контента в карточке Steam:

```text
дата | файл | инструмент (ChatGPT Images, PixelLab, руками) | шаг пакета | что правлено руками
```

Пример: `2026-10-21 | monk.png | ChatGPT Images | characters.md §Монах + clips.md idle | контур,
борода, чётки`.
