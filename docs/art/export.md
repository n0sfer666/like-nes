# Экспорт: от картинки генератора к листу

[← к пакету](README.md) · порядок шагов — [workflow.md](workflow.md)

Генератор отдаёт картинку «под пиксель-арт»: пиксели в ней разного размера, тонов сотни, край
фигуры размыт в фон. Этот файл делает из неё настоящий спрайт: ровная сетка, только тона
[мастер-палитры](style-bible.md), прозрачный фон, лист клеток. Редактор — **Pixelorama 1.2.3**.

## Хромакей

1. Картинка открывается в Pixelorama как есть: **File → Open...**.
2. Инструмент **Select By Color**, на его панели *Tolerance* 20–30, клик по пурпурному фону.
   Меньший допуск оставляет розовую кайму, больший съедает пурпурные и красные тона фигуры.
3. **Edit → Delete** — фон стал прозрачным. **Select → Clear** снимает выделение.
4. Остаток каймы — полупрозрачные и розоватые пиксели вдоль контура — снимается на шаге
   квантизации ([§Палитра](#палитра)) и чисткой контура.

## Сетка

Рост фигуры на картинке генератора произвольный, рост в игре задан
([characters.md](characters.md)). Масштаб считается по росту, а не по размеру пикселя картинки:

```text
масштаб, % = целевой рост / рост фигуры на картинке × 100
пример: монах 96 px, на картинке 610 px → 15.7 %
```

1. **Project → Scale Image**: режим *Percentage*, замок пропорций включён, *Interpolation:
   Bilinear*. Ближайший сосед на картинке без настоящей сетки рвёт контур и теряет тонкие детали.
2. Сразу после — квантизация в палитру ([§Палитра](#палитра)): она убирает промежуточные тона,
   которые принёс Bilinear.
3. **Чистка по пикселю.** Контур — ровно 1 px тоном `ink`, без «двойных» углов и разрывов. Глаза,
   кисти, пряжки и бусины проверяются отдельно: на этом росте деталь — 1–3 пикселя, и квантизация
   их чаще всего путает с соседним тоном.
4. Рост проверяется по сетке (**View → Show Pixel Grid**) и координатам курсора: от подошвы до
   макушки в стойке — значение из таблицы ±2 px.

Фоны масштабируются так же, но по ширине: план — 640 px ([backgrounds.md](backgrounds.md)),
лишняя высота срезается сверху у неба и снизу у переднего плана (**Project → Crop to Selection**).

## Палитра

Палитра пилота — [pilot.gpl](pilot.gpl): все рампы style bible по порядку, вариант A рядового,
имя тона — `<рампа>-<ступень>`, ступень 0 — самая тёмная.

1. `pilot.gpl` перетаскивается в окно Pixelorama (или **File → Open...**) и появляется в списке
   панели **Palettes**. Выбрать её там.
2. **Effects → Color → Palettize**, область — все кадры. Каждый пиксель получает ближайший тон
   палитры, без дизеринга.
3. **Project → Color Mode → Indexed**. Файл `.pxo` остаётся **индексным** на всём пути до
   экспорта: перекраска и проверка рамп работают с номером тона, а не с цветом.

Правка тона — правка палитры: тон меняется в таблице [style-bible.md](style-bible.md), затем в
`pilot.gpl` (строка с тем же именем), затем в палитре проекта на панели **Palettes**. Номера тонов
не сдвигаются, кадры перерисовывать не нужно. Новый тон добавляется **в конец** своей рампы только
вместе с новой строкой таблицы, удалять тона нельзя: номера всех следующих сдвинутся.

## Рампы

Сменная часть врага лежит целиком в своей рампе `swap-*`, и тона этой рампы нигде больше нет. По
ним перекрашивается вариант, поэтому протёкший тон — брак, а не мелочь.

**Протекло.** Квантизация отдала часть пикселей жилета в `shadow` или, наоборот, тон `swap-sash` —
коже. Чинится по маске части:

1. Часть выделяется: **Magic Wand** по жилету, добор **Lasso** с Shift.
2. Внутри выделения — **Bucket** с *Fill area: Similar colors* и *Tolerance* 0: клик по чужому
   тону заменяет его тоном своей рампы той же ступени (тёмный — в тёмный, светлый — в светлый).
   Заливка не выходит за выделение.
3. **Select → Invert**, и та же замена в обратную сторону: тона `swap-*` вне части уходят в
   рампу соседнего материала.

**Проверка.** **Select By Color** с *Tolerance* 0 по каждому тону `swap-cloth` и `swap-sash`:
выделение попадает только на свою часть. Проверяется каждый кадр.

**Три варианта рядового.** В индексном файле вариант — это 8 других строк палитры:

1. В палитре проекта тоны `swap-cloth-0..3` и `swap-sash-0..3` меняются на hex варианта B или C
   из [style-bible.md](style-bible.md) §Мастер-палитра (двойной клик по тону на панели
   **Palettes**).
2. Файл сохраняется копией (`bandit-b.pxo`, `bandit-c.pxo`) только для показа: в игре вариант
   перекрашивает движок, лист рядового один.

**Приёмка:** три варианта стоят рядом и различаются только одеждой и поясом; кожа, волосы и
контур у всех трёх одинаковы.

## Бесшовный слой

Движок повторяет слой фона по x, поэтому правый край продолжает левый.

1. **View → Tile Mode → Tiled In X Axis**: холст повторяется слева и справа, шов виден на краю.
2. Шов удобнее чинить в середине: **Effects → Transform → Offset & Scale Image**, *Offset* по x —
   половина ширины (320), *Wrap around* включён. Шов переехал в центр холста.
3. Шов закрашивается, затем тот же сдвиг на 320 возвращает картинку на место.
4. Линия горизонта, хребты и крыши на левом и правом краю стоят на одной высоте — иначе шов
   виден ступенькой при любой заплатке.

Тайлы 16×16 проверяются так же, но по обеим осям (**Tile Mode → Tiled In Both Axis**, сдвиг 8 и 8).

## Экспорт листа

**File → Export...**, вкладка **Spritesheet**:

| Поле | Значение |
|---|---|
| Frames | *All frames* |
| Layers | *Visible layers* |
| Orientation | *Rows*, *Columns* 10 |
| Crop mode | *None*: клетка остаётся 192×192, движок считает пивот от её угла |
| Resize | 100 % |
| Export JSON data | выключено: клипы и боксы задаёт файл `.sheet` ([animation.md](animation.md)) |
| Имя | `<персонаж>.png`: `monk.png`, `bandit.png` |

Порядок кадров в `.pxo` = порядок клеток в листе. Его задаёт раскладка в [clips.md](clips.md);
переставленный кадр сдвигает все клипы за ним.

Фон — один PNG на план, RGBA, имя `<часть>-<номер слоя>-<что>.png`: `village-1-mountains.png`.
Экспорт — та же команда, вкладка **Image**. Тайлсет — один PNG, тайлы 16×16 вплотную.

Исходники `.pxo`, листы и `.sheet` до В6 спеки #29 лежат у владельца. В движок они попадают вместе
с бейком палитры и листов в В6.

## Лицензия и журнал генераций

Арт пилота — собственный арт игры: автор — владелец, лицензия **CC0-1.0**. Схема
`LICENSES.toml` сейчас описывает только чужие паки и требует у пака `url`. Запись собственного
пака с полем генератора добавляет В6.

До тех пор у каждого принятого файла ведётся строка журнала — она понадобится и для
`LICENSES.toml`, и для раскрытия ИИ-контента в карточке Steam:

```text
дата | файл | инструмент (ChatGPT Images, PixelLab, руками) | шаг пакета | что правлено руками
```

Пример: `2026-10-21 | monk.png | ChatGPT Images | characters.md §Монах + clips.md idle | контур,
борода, чётки`.
