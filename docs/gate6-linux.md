# Гейт 6 на Linux: X11 и Wayland — что делать дальше

Шпаргалка под конкретный случай: Nobara/Fedora с GNOME, в шестерёнке экрана входа только
«GNOME» и «GNOME Classic». Общее описание гейта — `docs/owner-verification.md`, раздел 1.

## Что уже доказано первым прогоном

`./build/editor_shell --gate6 gate6-x11.png` прошёл **все девять** содержательных проверок:
гизмо ловится там, где нарисовано, драг — одна транзакция undo, инспектор показывает новое
значение, Undo возвращает позицию, кадр не однотонный и уходит в swapchain этой сессии.

Вердикт `FAIL` поставила **одна** строка паспорта:

```
session   : XDG_SESSION_TYPE=wayland
glfw      : x11
```

Это XWayland: сессия Wayland, а окном управляет X11-бэкенд GLFW. Про Wayland такой прогон не
говорит ничего, и гейт валится именно поэтому — зелёная строка про непроверенный протокол хуже
красной. Так что не хватает **половины Wayland**, а не половины X11.

## Шаг 1. Половина Wayland — делается прямо сейчас, менять сессию не нужно

```sh
sudo dnf install wayland-devel wayland-protocols-devel libxkbcommon-devel
cmake -S . -B build-way -G Ninja -DCMAKE_BUILD_TYPE=Release -DLINUX_WAYLAND=ON
cmake --build build-way --target editor_shell
./build-way/editor_shell --gate6 gate6-wayland.png
```

Каталог сборки **отдельный** (`build-way`): опция меняет состав целей GLFW, и общий каталог
запомнил бы X11-only.

Паспорт обязан сказать `glfw : wayland` — тогда прогон честный. Если пакетов не хватает,
конфигурирование встанет на поиске `wayland-scanner`, до компиляции хоть одного файла: это
говорит пакет, а не дерево.

Окно без рамки и заголовка — не дефект: GLFW 3.4 рисует декорации через `libdecor`
(`sudo dnf install libdecor`), без него окно просто голое.

## Шаг 2. Половина X11 — почему шестерёнка её не предлагает

Экран входа показывает ровно то, что лежит в двух каталогах:

```sh
ls /usr/share/wayland-sessions/   # то, что вы видите: GNOME, GNOME Classic
ls /usr/share/xsessions/          # X11-сессии
```

Если второй каталог **пуст** — X11-сессии на машине нет вовсе, и переключать нечего. Свежая
Fedora (а с ней и Nobara) сессию «GNOME on Xorg» больше не собирает, поэтому в шестерёнке обе
записи — Wayland.

Заодно про `/etc/gdm3/custom.conf`: этого файла тут и не должно быть, `gdm3` — путь Debian/Ubuntu.
На Fedora конфиг лежит в `/etc/gdm/custom.conf`, но правка бесполезна: `WaylandEnable=false`
только прячет Wayland-сессии, а X11-сессию из ничего не создаёт. Итог — вход вообще без списка.

### Что делать: поставить любую X11-сессию

Гейт проверяет **наш бинарь под X11**, а не конкретный рабочий стол, поэтому подойдёт самый
лёгкий оконный менеджер — это ~10 МБ против пол-KDE:

```sh
sudo dnf install i3 xterm
```

Дальше:

1. **Выйти из сеанса** (Log Out, не перезагрузка).
2. На экране входа шестерёнка → в списке появилась **i3**. Выбрать, войти.
3. Первый запуск i3 спросит про конфиг — Enter (создать), затем выбрать модификатор (Win).
4. Проверить, что сессия та самая, и прогнать гейт:

```sh
echo $XDG_SESSION_TYPE     # должно быть: x11
cd ~/_dev/like-nes
./build/editor_shell --gate6 gate6-x11.png
```

Мини-справка по i3, чтобы не залипнуть: `Win+Enter` — терминал, `Win+Shift+Q` — закрыть окно,
`Win+Shift+E` — выйти из сессии (и вернуться на экран входа, где можно выбрать обычный GNOME).

Паспорт обязан сказать `session : XDG_SESSION_TYPE=x11` и `glfw : x11` — без строки про XWayland.

Чёрный вьюпорт под i3 — это драйвер, а не редактор: `vulkaninfo --summary | head`.

## Если X11-сессия не заводится

Такое возможно (например, в системе нет `xorg-x11-server-Xorg` — проверяется `rpm -q
xorg-x11-server-Xorg`). Тогда решение за владельцем, и оно записывается в ADR 0013 явно:
прогон под XWayland — это настоящий X11-протокол и полный X11-путь **клиента**, но не Xorg как
сервер сессии. Как доказательство «редактор работает по X11» он годится с оговоркой; как
доказательство «редактор работает в X11-сессии» — нет.

## Что прислать

- stdout обоих прогонов целиком (по одному на сессию — паспорт делает их различимыми);
- `gate6-x11.png` и `gate6-wayland.png`;
- по скриншоту экрана на каждую сессию, где **видно окно редактора** и терминал с выводом
  `echo $XDG_SESSION_TYPE` в кадре;
- одну строку про то, что гизмо слушается **настоящей мыши**, а инспектор показывает движение
  чисел: это единственные два факта, которых процесс о себе знать не может.
