# Первый запуск

[English](../../en/getting-started/first-run.md) · Русский

Дерево [собрано](build.md). Эта страница — кратчайший путь от сборки до картинки на экране плюс то,
как выглядят типовые отказы.

## Открыть редактор

```sh
./build/editor_shell          # Windows: build\editor_shell.exe
```

Все команды ниже написаны для POSIX-оболочки; на Windows developer prompt запускает те же бинари
из `build\` с суффиксом `.exe`, и каждый блок называет эту форму, а не оставляет её выводить
читателю.

Цель существует, только когда `PLUGIN_UI` равна `ON` (значение по умолчанию). Нет
`build/editor_shell` — дерево сконфигурировано headless; переконфигурируйте с `-DPLUGIN_UI=ON`.

## Запустить игру-образец

Образцов два, и они нагружают разные половины движка.

```sh
cmake --build build --target game_sidescroller
./build/game_sidescroller     # Windows: build\game_sidescroller.exe
```

`game_sidescroller` — образец про ассеты и звук: он загружает испечённый бандл, поэтому первые же
строки называют, что поднялось, и каждая из них сама по себе проверка —

```
[game] assets: baked bundle .../game.bundle (BC7 512x256)
[game] materials: on (3 pipeline(s), 0 fallback(s))
```

```sh
cmake --build build --target game_platformer
./build/game_platformer       # Windows: build\game_platformer.exe
```

`game_platformer` — образец про геймплей: окно 960x720 поверх вида 320x240 при скейле 3, уровень
640x240 — намеренно ШИРЕ вида, потому что камера, которой некуда ехать, ничего не доказывает про
свой кламп. Рисунка в нём нет вовсе, только плоские квады.

## Правка → сборка → hot-reload

Цикл, который водит редактор, целиком закрыт гейтом, и его можно прогнать самому:

```sh
./build/build_loop_test       # Windows: build\build_loop_test.exe
```

Он пишет `.cpp`, собирает его вашим компилятором и перезагружает, печатая `ide-build-loop: PASS`,
когда правка исходника доезжает до загруженного модуля без перезапуска хоста — тем же путём, каким идёт редактор, когда вы сохраняете файл игровой логики.

## Когда чего-то не хватает

Недостающие системные пакеты обязаны всплывать названной ошибкой, а не отказом линковки:

- **Нет драйвера Vulkan на Linux** → рендер сообщает, что адаптер не найден. Проверить —
  `vulkaninfo | head`; на headless-машине достаточно `mesa-vulkan-drivers` (lavapipe), чтобы
  появились пиксели.
- **Нет заголовков разработки X11** → GLFW падает на *конфигурации*, называя недостающий пакет.
- **`fatal error: GL/gl.h`** при сборке зависимости `glfw3webgpu` → поставить `mesa-libGL-devel` на
  Fedora/Nobara. Переконфигурация после установки не нужна — просто соберите снова.
- **`cl.exe` не найден** на Windows → оболочка не является developer prompt, см.
  [системные требования](prerequisites.md#windows-из-какой-оболочки).
- **`like-nes собирается только под 64 бита`** на Windows → это developer prompt, но
  32-разрядный. Откройте *x64 Native Tools* и удалите каталог сборки: его кеш помнит компилятор.
