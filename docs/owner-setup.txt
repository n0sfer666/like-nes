like-nes — прогон проверки на чистой машине
Шпаргалка для владельца. Подробности по гейтам — docs/owner-verification.md,
общая установка — docs/first-run.md.

Все команды ниже прогнаны на macOS: вывод, который в них обещан, — настоящий,
а не предполагаемый.

===========================================================================
1. ЧТО ПОСТАВИТЬ
===========================================================================

--- WINDOWS (чистая система) ---------------------------------------------

  1. Visual Studio (Community) или Build Tools, 2022 и новее
     — workload "Desktop development with C++" (приносит cmake и ninja)
     — ПРОВЕРИТЬ во вкладке "Individual components", что отмечен
       "Windows 11 SDK" (10.0.2xxxx). Без него нет rc.exe и mt.exe,
       и сборка падает сообщением, которое про SDK молчит — см. раздел 6.
     https://visualstudio.microsoft.com/downloads/
  2. Git for Windows (нужен и сам git, и его bash)
     https://git-scm.com/download/win
  3. Python 3 с python.org (галочка "Add python.exe to PATH")
     ВАЖНО: python3 из Microsoft Store не годится — это заглушка,
     она открывает магазин и ничего не исполняет.
  4. Драйвер видеокарты от вендора (DX12). Обычно уже стоит.

  Всё дальше — ТОЛЬКО из "x64 Native Tools Command Prompt for VS":
  в обычном cmd/PowerShell нет cl.exe, а в Git Bash нет окружения vcvars.
  Именно x64 Native, а не просто "Developer Command Prompt for VS" и не
  "Developer PowerShell": те по умолчанию дают 32-битный компилятор, а
  дерево 64-битное — конфигурирование остановится на этом с явной
  ошибкой. В меню Пуск ярлык лежит рядом, в папке Visual Studio 2022.

--- ARCH LINUX (чистая система) ------------------------------------------

  sudo pacman -S --needed base-devel cmake ninja git python \
      libx11 libxrandr libxinerama libxcursor libxi \
      vulkan-icd-loader vulkan-tools mesa

  Драйвер Vulkan под своё железо (один из):
      vulkan-radeon      # AMD
      vulkan-intel       # Intel
      nvidia-utils       # NVIDIA
      vulkan-swrast      # программный lavapipe, если железа/драйвера нет

  Звук (без него игра честно скажет "audio: off" и поедет дальше):
      sudo pacman -S --needed pipewire pipewire-pulse alsa-lib

  Только для нативного Wayland (гейт 6, вторая сессия):
      sudo pacman -S --needed wayland wayland-protocols libxkbcommon

--- MACOS (справочно, уже пройдено) --------------------------------------

  xcode-select --install
  brew install cmake ninja

===========================================================================
2. СБОРКА И АВТОМАТИЧЕСКИЙ ПРОГОН
===========================================================================

  git clone https://github.com/n0sfer666/like-nes.git
  cd like-nes
  cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
  cmake --build build

Linux / macOS:
  bash scripts/owner_check.sh

Windows (из x64 Native Tools Command Prompt):
  "C:\Program Files\Git\bin\bash.exe" scripts/owner_check.sh

Отчёт: build/owner-report-<os>.txt (Windows: build\owner-report-*.txt).
Прислать его целиком.

Windows: не открывать проект как папку в самой Visual Studio. Её CMake-
интеграция кладёт сборку в out\build\x64-Debug, а гейты ждут каталог build
в корне (иначе — BUILD_DIR=out\build\x64-Debug перед вызовом скрипта) и
конфигурацию Release. Командная строка выше — единственный проверенный путь.

===========================================================================
3. РУЧНАЯ ПРОВЕРКА — ИГРА
===========================================================================

Дальше пути в стиле Linux/macOS. На Windows: слэши обратные, бинарь с .exe,
переменные через отдельный `set VAR=значение` перед запуском.

--- A. Просто поиграть ----------------------------------------------------

  ./build/game_sidescroller

  Стартовые строки должны быть примерно такие (это уже проверка — каждая
  говорит, что подсистема поднялась):

    [game] assets: baked bundle .../game.bundle (BC7 512x256)
    [game] audio: on (SFX + music)
    [game] achievements: 5 defined, 0 unlocked, backend: local
    [game] WASD/arrows/LStick = move · gamepad: <бэкенд> · Esc = quit

  Управление: WASD или стрелки — движение, пробел или ЛКМ — огонь,
  геймпад: левый стик — движение, южная кнопка (A/X) — огонь. Esc — выход.

  На что смотреть, играя 3–5 минут:
    - враги стреляют и умирают, счёт растёт, босс появляется;
    - звук: выстрелы, взрывы, музыка — без заикания и хрипа;
    - тост достижения выезжает после первого убитого врага (First Blood);
    - кадр не рвётся, картинка не мерцает;
    - Esc закрывает окно и печатает "[game] window clean exit"
      (не "крестиком" — крестик тоже должен работать, проверь оба).

  Если жалуется на ассеты — LIKENES_ASSETS=<путь к example_ugly_game/assets>.

--- B. Достижения переживают перезапуск -----------------------------------

  LIKENES_SAVE_DIR=./saves-probe ./build/game_sidescroller
     → поиграть до тоста First Blood, выйти
  LIKENES_SAVE_DIR=./saves-probe ./build/game_sidescroller
     → строка старта теперь говорит "N unlocked", N > 0

  Windows:
     set LIKENES_SAVE_DIR=%CD%\saves-probe
     build\game_sidescroller.exe

  В каталоге ./saves-probe должен лежать achievements.save.
  Каталог временный — после проверки удаляй.

--- C. Достижения без сети (опционально, но дёшево) -----------------------

  Фейковый бэкенд умеет притворяться, что сети нет первые N запусков
  подключения: прогресс копится локально и досылается позже.

  Linux/macOS:
    LIKENES_SAVE_DIR=./saves-probe \
    LIKENES_ACH_PLUGIN=build/plugin_ach_fake.so \
    ACH_FAKE_OFFLINE=2 ./build/game_sidescroller

  Windows:
    set LIKENES_ACH_PLUGIN=build\plugin_ach_fake.dll
    set ACH_FAKE_OFFLINE=2
    build\game_sidescroller.exe

  Строка старта должна сказать "backend: plugin", а игра — работать так же.

--- D. Офскрин-рендер: демо-режим -----------------------------------------

  ./build/game_sidescroller --demo ./demo-out --frames 300

  Окна не открывает, пишет frame_0000.png … frame_0299.png и печатает
  "[game] demo wrote 300 frames to ...". Открой пару кадров глазами:
  это путь рендера в текстуру, которого живая игра не показывает.

--- E. Звук на живом железе (в CI не существует) --------------------------

  Во время игры воткни/выдерни наушники, переключи устройство вывода в ОС.
  Ожидание: звук либо продолжается на новом устройстве, либо честно
  замолкает — но игра не падает и не зависает.

--- F. Бейк ассетов байт-в-байт -------------------------------------------

  ./build/assetc --game example_ugly_game/assets ./rebake.bundle

  Должен напечатать:
    [assetc] bundle_hash = 0xa67f56b681aed040

  Это тот же хеш, что на macOS. Отличается — значит бейк не детерминирован
  между ОС, и это находка (пришли строку целиком).

===========================================================================
4. РУЧНАЯ ПРОВЕРКА — ГЕЙТЫ РАУНДОВ #13 и #14
===========================================================================

--- G. Редактор, X11 и Wayland (гейт 6, только Linux) ---------------------

GLFW по умолчанию собран только под X11, под Wayland-сессией такой бинарь
работает клиентом XWayland — поэтому сборки две и сессии две.

  cmake -S . -B build-way -G Ninja -DCMAKE_BUILD_TYPE=Release -DLINUX_WAYLAND=ON
  cmake --build build-way --target editor_shell

  echo $XDG_SESSION_TYPE   # должно печатать x11
  ./build/editor_shell
  echo $XDG_SESSION_TYPE   # должно печатать wayland
  ./build-way/editor_shell

В каждой сессии: вьюпорт рисует, клик в Hierarchy выделяет объект, гизмо его
двигает, числа в Inspector едут следом, Undo возвращает назад.
Скриншот каждой сессии: gate6-x11.png, gate6-wayland.png.

Чёрный вьюпорт → vulkaninfo --summary | head: нет устройства — это драйвер,
а не редактор.

--- H. Правка кода → пересборка → изменение видно (гейт 8) ----------------

  1. ./build/editor_shell — убедиться, что рисует
  2. ./build/game_sidescroller — посмотреть на фон
  3. в example_ugly_game/draw.cpp заменить
       a.clearValue = WGPUColor{0.02, 0.02, 0.07, 1.0}
     на
       a.clearValue = WGPUColor{0.25, 0.02, 0.05, 1.0}
     (рендер-сторона: sim-хеш не двигается, а глазом видно)
  4. cmake --build build --target game_sidescroller
  5. ./build/game_sidescroller — фон стал тёмно-красным
  6. git checkout example_ugly_game/draw.cpp  ← вернуть обязательно

Числа "best / median" из раздела про цикл в отчёте owner_check — тоже часть
этого гейта, они нужны фактом для Linux и Windows.

--- I. Живой ввод: пад (гейт 8 спеки #14) ---------------------------------

  cmake --build build --target framework_input_probe
  ./build/framework_input_probe example_ugly_game/assets/input.txt

  1. Воткнуть пад НА ХОДУ → строка
     pad 0 CONNECTED vid=… pid=… name="…" -> profile '…'
     Профиль должен соответствовать устройству; 'generic' у неизвестной
     модели — это работающий фолбэк, а не провал.
  2. Стик → move=(…) едет, в покое ровно (+0.00,+0.00). Южная кнопка и
     пробел → fire:# у обоих.
  3. Клавиша 1 → перебинд 'fire' → нажать клавишу, уже занятую другим
     действием → probe откажет и назовёт владельца → F заберёт силой.
  4. S — сохранить, Esc — выйти, запустить снова: первая строка
     "overlay loaded … N edit(s)". Потом X и S — вернуть чистый пресет.
  5. Выдернуть пад на ходу → "pad 0 DISCONNECTED -> ... 'generic'",
     клавиатура продолжает играть, ничего не залипает.
  6. ./build/game_sidescroller с падом — корабль летит по стику.

Linux, если пад не виден: sudo usermod -aG input $USER и перелогиниться.
Строка "input dev" в отчёте owner_check показывает, что увидел скрипт.

6. ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
===========================================================================

--- "The C compiler ... is not able to compile a simple test program" -----

Смотреть НЕ на первую строку, а на конец вывода. Если там

    --mt=CMAKE_MT-NOTFOUND
    RC Pass 1: command "rc /fo ..." failed ... no such file or directory

то компилятор ни при чём: rc.exe и mt.exe приносит Windows SDK, отдельный
компонент. Лечение:

  1. Visual Studio Installer → Modify → Individual components →
     отметить "Windows 11 SDK" → Modify.
  2. Удалить каталог сборки целиком (out\build\x64-Debug или build):
     в нём застрял кеш с CMAKE_MT-NOTFOUND, он переживёт установку SDK.
  3. В x64 Native Tools Command Prompt проверить: where rc и where mt
     должны печатать пути внутри C:\Program Files (x86)\Windows Kits\10\bin\
  4. Конфигурировать заново.

Строка "windows sdk :" в паспорте owner_check.sh показывает это же —
но она видна только после того, как сборка уже прошла, поэтому проверка
через where быстрее.

--- "like-nes собирается только под 64 бита" -----------------------------

Шелл 32-битный. "Developer Command Prompt for VS" и "Developer PowerShell"
дают по умолчанию x86-тулчейн (в путях видно bin\Hostx86\x86\cl.exe), а
предсобранный wgpu-native всё равно подставляет x86_64-библиотеку. Лечение:
закрыть шелл, открыть "x64 Native Tools Command Prompt for VS", удалить
каталог build (кеш помнит компилятор) и сконфигурировать заново.

Если гейта не было и сборка дошла до кода — она падает по-другому:
capture.cpp даёт "C4244: преобразование uint64_t в size_t" под /W4 /WX.
Причина та же, наш код тут ни при чём.

--- "cl.exe not found" / CMake берёт не тот компилятор -------------------

Шелл запущен не из x64 Native Tools Command Prompt for VS. Обычный cmd,
PowerShell и Git Bash окружения vcvars не имеют.

--- Игра не находит ассеты -----------------------------------------------

  LIKENES_ASSETS=<путь к example_ugly_game/assets>
  (Windows: set LIKENES_ASSETS=...)

--- Пад не виден на Linux ------------------------------------------------

  sudo usermod -aG input $USER   и перелогиниться.

--- Нет звука на Linux ---------------------------------------------------

Игра скажет "audio: off" и поедет дальше. Нужен pipewire/pipewire-pulse
(раздел 1). Проверить: pactl info
