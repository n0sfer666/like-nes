# ADR 0001: Язык ядра и базовая архитектура движка

- **Дата:** 2026-07-18
- **Статус:** **Accepted** — язык **C++** утверждён владельцем 2026-07-18. Архитектурные
  допущения (hot-reload, детерминизм+fixed-point, WebGPU-потолок) — **pending PoC (T4)**.
- **Контекст:** [`../specs/2026-07-18-language-and-core.md`](../specs/2026-07-18-language-and-core.md)

## Проблема

Столп №1 брифа — оптимизация (RAM/диск/CPU/GPU), заложенная в архитектуру. Столп №7 —
один язык логики, выбор которого **обусловлен оптимизацией**. Нужно выбрать язык ядра и
геймплея так, чтобы дать максимальный потолок эффективности КОНЕЧНОГО ПРОДУКТА (макс.
охват железа → макс. игроков). **Цель №1 — Steam-десктоп (Linux/macOS/Windows);** мобилки
через адаптеры/отложены, консоли позже. Порог входа/знакомость языка — **НЕ критерий** (язык выбирается только под скорость игр).
При паритете эффективности Rust≈C++ тайбрейк владельца — зрелость экосистемы + официальный
консольный SDK-путь (обе причины служат цели «максимум производительности и охвата платформ»).

## Решение

Ядро и геймплей — на **C++**. Геймплей компилируется в shared-lib (.so/.dll/.dylib) с
hot-reload через C-ABI (`extern "C"`), state целиком в host. Ядро: Archetype ECS (flecs),
детерминированный параллельный планировщик, fixed timestep, fixed-point симуляция,
арены/пулы, кастомный ассет-формат (mmap+стриминг), рендер на **Dawn (C++ WebGPU)** или
wgpu-native, HAL под консоли (офиц. C++ SDK-путь).

## Research verdict (2026-07-18, desk-research закрыт)

Полные данные: `~/wiki/dev/like-nes/benchmark/` (protocol/data/result).
23 подтверждённых claim'а, 2 опровергнуто, adversarial-верификация.

- **C#/NativeAOT — исключён доказательно:** GC остаётся даже при AOT → стуттер
  фрейм-тайма (паузы <1 мс … секунды), против «макс. охват железа».
- **Zig — исключён (на 2026):** не 1.0, движки экспериментальны, нет шиппнутых игр.
- **Rust ≈ C++ по чистому рантайму — ПАРИТЕТ.** Ни один не доказан эффективнее.
- **C++ выбран владельцем** при паритете эффективности: зрелая экосистема + официальный
  консольный SDK-путь (research: санкц. путь под Switch/PS/Xbox — именно C++). Язык выбран
  ТОЛЬКО под скорость/охват; знакомость языка — не критерий. Цена — потеря memory safety
  (митигация: sanitizers + дисциплина + арены с проверками в debug).
- **WebGPU-абстракция — достаточна** для Hollow-Knight-класса: нативные first-class
  бэкенды, кастомный пост-процессинг, оверхед ~5–10%. В C++ реализация — **Dawn** (тот же
  класс, что wgpu) или wgpu-native. Оговорка: 2D-освещение пишем сами; для топ-эффектов —
  нативный Vulkan через HAL как escape hatch.

## Почему не альтернативы

- **Rust** — паритет по эффективности с C++ + memory safety, но экосистема моложе и нет
  официального консольного пути; при равной эффективности владелец предпочёл зрелость C++.
- **Zig** — отличный контроль, но незрелая gamedev/GPU-экосистема на 2026 (исключён).
- **C#/NativeAOT** — лучшая эргономика, но GC → стуттер, противоречит столпу №1 (исключён).

## Условия финализации (validation gate)

Языковая часть — **Accepted**. Остаётся эмпирика по архитектуре (Proposed → подтверждается PoC):

1. ✅ **Desk-research** — выполнен (2026-07-18). Zig/C# отсеяны; Rust≈C++; C++ выбран владельцем.
2. **Walking-skeleton PoC** эмпирически закрывает 3 риска:
   - hot-reload roundtrip (замер latency, state в host не рушится, крэш-изоляция работает);
   - детерминизм + fixed-point (golden-hash после N тиков **идентичен на x86 и ARM**,
     т.е. Linux/Windows vs macOS Apple Silicon — всё десктоп-таргеты);
   - Dawn/WebGPU запускается на Steam-десктопе (Linux/macOS/Windows).
3. **T4** регресс-тест детерминизма зелёный.

Если PoC опровергнет допущение — соответствующая часть архитектуры пересматривается.

## Последствия

- Разработчик игры пишет геймплей на C++ в **fixed-point**, не в привычном f32
  (цена детерминизма — принято осознанно).
- **Memory safety потеряна** vs Rust: арены/пулы/unsafe реально небезопасны → обязательны
  ASan/UBSan в CI + дисциплина владения. Крэш-изоляция геймплея сложнее (SEH/сигналы, не
  `catch_unwind`).
- Движок бандлит пиннед **C++ toolchain** (clang + build-система) + Android NDK / iOS SDK
  для кросс-компиляции (влияет на IDE- и build-спеки).
- **Консоли — плюс:** официальный C++ SDK-путь снимает главный риск Rust; HAL всё равно
  закладывается сразу.
- Рендер — **Dawn (C++ WebGPU)** как база, нативный Vulkan как escape hatch (влияет на
  render-спеку #2).
