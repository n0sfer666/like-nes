# ADR 0003: Архитектура ассет-пайплайна (формат, mmap, стриминг, шейдер-кеш)

- **Дата:** 2026-07-19
- **Статус:** **Accepted** (2026-07-19) — validation gate закрыт: walking-skeleton asset-вертикаль
  PoC (T4) зелёная. Все 5 условий финализации выполнены (см. ниже + «Результат PoC» в спеке).
- **Контекст:** [спека #5](../specs/2026-07-19-asset-pipeline.md); наследует [ADR 0001](2026-07-18-language-and-core.md),
  [ADR 0002](2026-07-18-render-pipeline.md).

## Проблема

Спека #1 заложила «кастомный бинформат + mmap + стриминг», но не проверила PoC — а от ассет-подсистемы
зависят время загрузки, пик RAM/диска (столп №1) и два open-Q рендера (спека #2): кеш скомпилированных
шейдеров и выбор транслятора. Нужна архитектура формата/загрузки/стриминга, которая держит инварианты
детерминизма спеки #1 и не блокируется на выборе Dawn vs wgpu-native.

## Решения

| Аспект | Выбор |
|---|---|
| I/O | **гибрид**: mmap для резидента/мелкого (zero-copy) + явный async-I/O для крупных стримов; никогда не блокирует sim/render-поток |
| Компрессия | **кодек по классу ассета**: текстуры KTX2/basis→BC7/ASTC (сжато в VRAM); bulk zstd-блок→арена; audio opus/vorbis; hot/мелкое raw |
| Раскладка | **target-native**, zero-parse (mmap→reinterpret_cast, offset-указатели), per-platform bake; magic+fmt_version |
| Паковка | **бандлы/группы** — единица стриминга/резидентности/патча/hot-reload |
| Идентичность | **стабильный GUID** (ссылки) + **content-hash** (кеш-ключ + дедуп) |
| Детерминизм бейка | **байт-в-байт** (твёрдо) → golden-hash T4 + remote build-cache |
| Схема ECS | authoring = истина → сцены **rebake**; сейвы игрока → **версионированная миграция** |
| Версия формата | magic+fmt_version, **fail-hard → rebake** (ассеты производны) |
| Транслятор | **Tint** (с Dawn, C++) за интерфейсом `ShaderCompiler` — закрывает спека #1 open Q #5 (Dawn) + спека #2 open Q #5 |
| Шейдер-кеш | **два уровня**: backend-IR (наш, шипается) + Dawn pipeline-blob (локальный, ключ gpu+driver+ir-hash) — закрывает спека #2 open Q #1 |
| Варианты шейдера | **on-demand + variant-manifest** (только фактические material×technique×backend×defines) |
| Кеш offline/runtime | единый формат, два режима записи (редактор пишет на лету = тёплый кеш → релиз шипает) |
| Стриминг vs детерминизм | **готовность ассета = детерм. gate**; стрим/декомпрессия вне sim-потока; тайминг I/O не протекает в sim-hash |
| Резидентность | гибрид: явный request+refcount+pin + auto-hint; жёсткий бюджет → LRU-evict незапиненного |
| Безопасность | **trusted** (свои pak, checksum) / **validated** (мод/внешние, bounds-check offset'ов) |
| HAL/IO | асс­ет-I/O за **platform-частью HAL** (спека #1 open Q #2); desktop нативно, console/mobile позже |
| Авторинг | headless **CLI-бейкер** (`assetc`) — ядро; IDE оборачивает watch'ем |
| Ссылки из кода | **типизированные handle** через codegen-хедер (`AssetId<T>`) |
| Bake-кеш | инкрементальный локальный + **remote CAS сразу** (осознанно владельцем) |
| Ошибки ассетов | **placeholder**, никогда не crash; editor громко / shipped тихо |

## Ключевой tradeoff — детерминизм при недетерминированном I/O

Async-стриминг по природе недетерминирован по таймингу (диск, потоки), а сим спеки #1 обязана быть
бит-в-бит воспроизводима. Наивное «стримить и читать по готовности в тике» **сломало бы** инвариант #2.
**Решение:** готовность ассета — детерминированный gate: sim видит ready-set только в sync-точке тика,
а если ассет не готов — ведёт себя детерминированно (wait/placeholder по правилу). Стриминг и декомпрессия
физически живут на IO/worker-пуле, никогда не на sim-потоке. Тайминг диска не может возмутить sim-hash.
Это же сохраняет инвариант #3 («GPU не кормит сим»): нет GPU→CPU→sim readback.

> ⚠️ **Честно зафиксировано владельцу:** remote build-cache выбран «сразу», хотя фазирование
> (философия walking-skeleton спеки #2) советовало бы local-first + remote позже. Инфра remote CAS
> (транспорт/хранилище/auth) не спроектирована в деталях — open Q #1 спеки #5. Content-hash CAS
> спроектирован remote-ready, так что откат к «local сначала, remote инкрементально» дёшев.

## Условия финализации (validation gate) — ✅ ЗАКРЫТЫ 2026-07-19

Proposed → Accepted когда walking-skeleton asset-вертикаль (T4) закрывает главные риски
(все 5 зелёные, реализация `poc/asset/`, детали — «Результат PoC» в спеке #5):
1. `assetc` детерминированный bake: байт-golden-hash идентичен между прогонами/машинами (CPU-детерм.,
   в отличие от GPU-рендера спеки #2 — тут байтовый хеш корректен).
2. bundle → mmap-резидент zero-copy + async-стрим-путь → текстура/шейдер-IR в GPU; ASan/UBSan-чисто,
   без per-frame heap в load/submit-пути.
3. Шейдер: WGSL→Tint→backend-IR кеш + попадание; **асс­ет-PoC кормит render-PoC** (`poc/render/`
   потребляет реальный бейкнутый ассет) — валидирует шов asset→render и шейдер-кеш спеки #2.
4. hot-reload roundtrip ассета.
5. Детерминизм-гейт: замедленный I/O → тот же sim-hash (тайминг не протекает).

## Последствия

- Закрывает хвост спеки #1 (mmap/стриминг эмпирически) и два open-Q спеки #2 (Tint + шейдер-кеш).
- Разблокирует спека #1 open Q #2 (HAL-IO граница) и #3 (миграция схемы через rebake+save-migration).
- Console/mobile HAL-IO backend, native-Vulkan шейдер-путь, delta-патчинг Steam, node-редактор
  материалов и авторинг-UX — отдельные задачи/спеки позже (точки расширения готовы).
- Remote-cache инфра — отдельный трек (open Q #1).
