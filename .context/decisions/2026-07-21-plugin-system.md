# ADR 0006: Система плагинов + конфигурируемый интерфейс

- **Дата:** 2026-07-21
- **Статус:** **Proposed** — интервью пройдено (owner, 2026-07-21), дизайн зафиксирован; переходит в
  **Accepted** по закрытию validation gate (walking-skeleton plugin-вертикаль PoC, T4 — условия ниже).
- **Контекст:** [спека #6](../specs/2026-07-21-plugin-system.md); наследует
  [ADR 0001](2026-07-18-language-and-core.md) (детерминизм, fixed timestep, sim-hash, fix32,
  hot-reload shared-lib, SEH/сигнал-изоляция host↔lib, детерм. граф систем),
  [0002](2026-07-18-render-pipeline.md) (render-graph, GLFW-окно), [0003](2026-07-19-asset-pipeline.md)
  (asset-codec-по-классу), [0004](2026-07-19-audio-subsystem.md) (audio-шины),
  [0005](2026-07-20-input-system.md) (`InputSource` HAL).

## Проблема

Движок позиционируется как «завод по сборке игры»: студия/соло-разработчик должен расширять и
переконфигурировать его под продукт, не форкая ядро (столп №6). Все подсистемы (#2–#5) уже имеют
точки расширения, но нет **единого механизма** подключения стороннего кода и нет **конфигурируемого
данными интерфейса** (столпы №6, №3). При этом два жёстких инварианта ядра нельзя нарушить:
детерминизм симуляции (плагин, трогающий sim, не должен возмущать sim-hash или вносить зависимость от
порядка загрузки) и изоляция сбоев (крэш плагина не роняет редактор). Плюс расширяемость должна
покрывать два очень разных класса кода: доверенный first-party (нужен native-перф) и недоверенный
marketplace (нужна песочница). Наивный «один dlopen-хук» провалил бы либо перф, либо безопасность,
либо детерминизм.

## Решения

| Аспект | Выбор |
|---|---|
| Граница (2 борта) | **trusted → native C-ABI shared-lib** (прямой ECS/HAL, zero-cost, hot-reload; переиспользует host↔lib seam #1) · **untrusted → WASM-sandbox** (wasmtime/WAMR за HAL; linear-memory изоляция; host-функции = единственный выход) |
| Реестр | единый **`ExtensionPointRegistry`**: типизированная регистрация 6 видов швов — ecs-system · render-pass (#2) · asset-codec (#5) · input-source (#4) · audio-bus (#3) · ui-panel |
| Порядок/детерминизм | регистрация = **чистая функция от манифеста**; порядок исполнения sim-систем-плагинов — из **детерм. графа зависимостей**, НЕ из порядка dlopen/инстанциации |
| Манифест | декларативный `plugin.toml`: id, версия, требуемая версия API движка, зависимости плагинов (топосорт), объявленные ext-points, запрошенные **capabilities**, config-схема, ui-панели |
| Capability-модель | WASM-гость видит ТОЛЬКО импортированные host-функции из манифеста (нет импорта → нет доступа: ни FS/сети, ни host-памяти вне контракта); native — доверенный (модель документирована, не форсится) |
| Детерминизм guest | WASM-гость на **fix32** → native-плагин ≡ WASM-плагин той же логики по sim-hash |
| Конфиг-интерфейс | декларативная config-схема (данные, не код) + **минимальный живой докируемый UI-shell** (панели из `ui-panel`-манифестов, GLFW-окно #2); полный IDE-редактор = спека #7 |
| Изоляция | native: **SEH (Win) / сигнал-изоляция (*nix)** на границе (seam #1); WASM: **trap** в песочнице; сбойный плагин → пометка failed + выключение, host жив |
| Жизненный цикл | load (разрешение манифеста + версий + capability-политики) → register → activate → [hot-reload swap] → deactivate → unload |

## Ключевой tradeoff — единый механизм для двух классов кода

Расширяемость движка должна одновременно дать **native-перф доверенному коду** и **безопасность
недоверенному**, не жертвуя детерминизмом. Один борт этого не даёт: чистый native — небезопасен для
marketplace; чистый WASM — платит маршалингом на каждом sim-швe (трение со столпом №1). **Решение —
два борта за одним реестром:** `ExtensionPointRegistry` типизирует ЧТО расширяется, а КАК код
исполняется (native C-ABI vs WASM) — деталь загрузчика. Оба борта регистрируются одним манифестом и
подчиняются одному детерм. контракту (fix32 + граф-порядок). Тем самым: (а) trusted-путь zero-cost
(прямой C-ABI вызов, hot-path без маршалинга); (б) untrusted заперт в linear memory + capability-
импортах; (в) детерминизм — свойство контракта, а не борта: native≡WASM по sim-hash — это и гейт, и
доказательство, что песочница не ломает воспроизводимость. Изоляция сбоев переиспользует уже
доказанный seam #1 (сигнал/SEH), WASM добавляет trap-границу поверх.

## Условия финализации (validation gate) — открыты, Proposed

Proposed → Accepted, когда walking-skeleton plugin-вертикаль (T4) закрывает главные риски
(реализация `poc/plugin/`, детали — «Результат PoC» в спеке #6):

1. **Детерминизм:** golden sim-hash воспроизводим run-to-run/cross-machine; (а) sim-плагин реально
   влияет на hash (H_with ≠ H_without → гейт ловит регресс), (б) H_with НЕ зависит от порядка загрузки
   плагинов (топосорт по зависимостям, НЕ по dlopen), (в) native-плагин ≡ WASM-плагин той же логики.
   ASan/UBSan-чисто.
2. **Изоляция:** крэш (null-deref) в native-плагине ловится на границе (сигнал/SEH) → плагин failed +
   выключен, host и остальные плагины живы.
3. **Hot-reload:** hot-swap плагина без рестарта host; host-owned state переживает swap.
4. **Шов (реестр реален):** ≥1 плагин через `ExtensionPointRegistry` реально драйвит существующую
   подсистему сквозным примером (min: ecs-system в детерм. графе + asset-codec-регистрация).
5. **WASM-sandbox:** untrusted WASM-плагин исполняется в песочнице; выход за границы (OOB linear-memory
   / вызов незаявленного capability) → trap, host жив, host-память не тронута.
6. **Live (owner HW, macOS):** hot-reload swap + WASM escape-тест + UI-shell (докируемые панели из
   манифестов) на реальном окне (GLFW #2).

## Последствия

- Унифицирует уже существующие точки расширения (#2–#5) под один реестр + манифест → сторонний код
  подключается единообразно, без форка ядра (столп №6).
- Даёт расширениям тот же детерм.-контракт, что ядру: sim-плагин = система в детерм. графе на fix32 →
  готовит netplay/rollback (#11) для модов, не только для базовой игры.
- Два борта (native/WASM) = основа для marketplace: first-party native-перф + недоверенный WASM в
  песочнице; подпись/политика песочницы/semver-эволюция API — follow-up.
- Минимальный UI-shell (панели из манифестов) закладывает архитектуру редактора (#7): IDE = набор
  ui-panel-плагинов над этим же реестром, а не монолит.
- Выбор WASM-runtime (wasmtime vs WAMR), полный live-прогон каждого из 6 ext-point, Win/Linux live
  изоляция, marketplace-инфра, полноценный IDE (#7) — отдельные задачи/спеки (точки расширения готовы).
