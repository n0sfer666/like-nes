# Спецификация #19: README и документация на двух языках (en — главный, ru)

- **Дата:** 2026-07-26
- **Статус:** **Draft** — раунд не начат. ADR пишется при закрытии раунда.
- **Наследует:** [#11](2026-07-26-repo-layout.md) (`docs/` в корне),
  [#13](2026-07-26-desktop-dev-parity.md) (инструкции старта на трёх ОС проверены),
  [#9](2026-07-25-licensing.md) (лицензии и атрибуция — часть публичного лица проекта),
  [#14](2026-07-26-framework-input.md)–[#18](2026-07-26-materials-shaders.md) (то, что документируем).
- **Уровень проверки:** **T2/T3** — примеры из документации компилируются и запускаются в CI;
  сквозной проход «новичок по инструкции» — вручную.

## Контекст

В корне репозитория **нет `README.md`**. Единственная документация — `.context/` на русском, и это
рабочие материалы владельца, а не документация для пользователя движка. Свободный движок под
`MIT OR Apache-2.0` (#9) без README — это проект, которым нельзя воспользоваться.

Решение владельца: два языка, **английский — главный**. Английский главный не по престижу, а по
следствию: он определяет структуру, и русский обязан ей соответствовать, а не жить своей жизнью.

## Ключевые решения (owner)

| # | Развилка | Решение |
|---|---|---|
| 1 | Языки | **en — источник истины, ru — перевод.** Правка сначала в en; ru догоняет. Расхождение структуры — ошибка сборки документации, а не повод для рассуждений. |
| 2 | Формат | **Markdown в репозитории**, статический сайт — опционально и позже. Документация обязана читаться прямо на хостинге репозитория. |
| 3 | Публичное vs внутреннее | **`docs/` — для пользователей движка, `.context/` — для разработки движка.** Границу не размываем: спеки и ADR остаются внутренними, но публично объясняются в разделе «архитектурные решения» ссылками. |
| 4 | API-референс | **Из заголовков, генерацией** (Doxygen или аналог, решение в ADR), а не вручную: ручной референс устаревает на первой же правке сигнатуры. Прозаические руководства — вручную. |
| 5 | Примеры в тексте | **Компилируемые.** Фрагменты кода извлекаются из реальных собираемых файлов; «примерный код» в документации запрещён. |

## Требования

### Функциональные

- **`README.md` (en) + `README.ru.md`:** что это, для кого, чем отличается (детерминизм,
  оптимизация, свободная лицензия), скриншот/гиф игры-образца, быстрый старт на трёх ОС,
  ссылки на документацию, лицензия, статус проекта (честный: движок в разработке).
- **Структура `docs/{en,ru}/`, зеркальная по файлам:**
  - `getting-started/` — установка и сборка на macOS/Linux/Windows, первый запуск редактора,
    запуск игры-образца;
  - `tutorial/` — «первая игра»: от пустого проекта до играбельного персонажа на тайлмапе с
    анимацией, звуком и достижением; каждый шаг — рабочий код;
  - `guide/` — по подсистемам: ECS и тик, ассеты и бейк, ввод и перебинды (#14), физика (#15),
    контроллер и тайлмапы (#16), спрайты/анимации/камера/частицы (#17), материалы и шейдеры (#18),
    аудио, плагины, достижения, сборка и релиз;
  - `architecture/` — инварианты движка (детерминизм, границы слоёв, изоляция сбоев) и почему они
    такие; ссылки на ADR;
  - `reference/` — сгенерированный API-референс;
  - `contributing/` — как собрать, как гонять гейты, DCO, стиль коммитов (перенос и англизация
    `CONTRIBUTING.md`);
  - `faq/` и `troubleshooting/` — типовые сбои сборки на каждой ОС с точными сообщениями.
- **Переключатель языка** — явная ссылка в шапке каждого документа на его пару.
- **Проверка синхронности:** CI сверяет, что множества файлов `docs/en` и `docs/ru` совпадают, и
  что у каждого ru-документа записан хеш/версия en-исходника, от которого он переведён;
  расхождение → предупреждение с точным списком отставших файлов (и ошибка — для README и
  getting-started, которые не имеют права отставать).
- **Компилируемость примеров:** каждый фрагмент кода в руководствах ссылается на файл в
  `docs/examples/`, который собирается в CI; текст вставляет фрагмент по маркеру, а не копией.
- **Документация не врёт про платформы:** каждое утверждение «работает на X» опирается на гейт из
  #12/#13; неподдержанное честно помечено как «в разработке».

### Нефункциональные (инварианты)

1. **en — источник.** Правка руководства без правки en невозможна (ru ссылается на версию en).
2. **Ни один пример не «псевдокод».** Всё, что выглядит как код движка, компилируется.
3. **Инструкция старта проверена на чистой машине,** а не «должна работать».
4. **`.context/` не публикуется как документация** и не является предпосылкой для чтения `docs/`.

## Гейты приёмки (T2/T3)

| # | Гейт | Критерий |
|---|---|---|
| 1 | Структура зеркальна | CI: множества файлов en/ru совпадают; README и getting-started не отстают по версии |
| 2 | Примеры собираются | все файлы `docs/examples/` компилируются и запускаются в CI на 3 ОС |
| 3 | Фрагменты актуальны | извлечение фрагментов по маркерам; отсутствующий маркер — ошибка сборки документации |
| 4 | Ссылки живы | проверка внутренних ссылок и путей; битых нет |
| 5 | **Сквозной старт** | на чистой машине/контейнере каждой ОС: пройти getting-started дословно → редактор открыт, игра-образец запущена. Расхождение с текстом = дефект документации |
| 6 | Туториал воспроизводим | «первая игра» проходится по шагам с нуля; итоговый проект собирается и играбелен |
| 7 | Лицензионная часть | README и docs корректно излагают `MIT OR Apache-2.0` и атрибуцию третьих сторон (#9) |

## Не входит в скоуп

- Сайт документации, поиск, версионирование по релизам — после первого публичного релиза.
- Локализация на другие языки: структура позволяет добавить, но обязательства нет.
- Локализация самого движка/редактора (интерфейс) — отдельная тема.
- Видео-туториалы.
