  `scripts/check_release_appimage.sh` пакует ДВАЖДЫ и первым утверждает БАЙТ-равенство: здесь

## Контекст

Сегодня есть `scripts/package.sh`: собирает `.app` на macOS и tarball на Linux, проверяет
самодостаточность. Это **бандл игры**, а не установка **движка**, и Windows в нём нет вовсе.

Требование владельца: движок должен устанавливаться максимально просто. Если ему нужно что-то,
чего на компьютере нет, — он говорит об этом, пользователь подтверждает, недостающее
доустанавливается, и только потом ставится сам движок. Скрипт сборки релизов запускается **только
на macOS** — под другие платформы его оптимизировать не нужно.

Здесь есть неустранимая физика: собрать нативный Windows-инсталлятор на macOS нельзя честно
(нужен MSVC и подписание). Поэтому скрипт — **оркестратор**, а не универсальный кросс-компилятор.

## Ключевые решения (owner)

| # | Развилка | Решение |
|---|---|---|
| 1 | Роль скрипта | **Оркестратор на macOS.** macOS-пакет собирается локально; Linux — в контейнере на той же машине; Windows — задачей в CI-матрице (#8 уже её имеет) с последующим скачиванием артефакта. Одна команда — все три пакета в `release/`. |
| 2 | Форматы | macOS — `.dmg` с `.app`; Windows — установщик + переносимый `.zip`; Linux — `.tar.gz` + AppImage. Переносимый вариант есть всегда: пользователь не обязан устанавливать. |
| 2а | Чем собирается установщик Windows | **WiX/MSI** (решение владельца 2026-09-04, Inno Setup отклонён). MSI — родной формат политик и корпоративной раскатки, и штатная деинсталляция (гейт 7) достаётся от установщика, а не пишется руками. Реализовано шагом C вертикали 4: `packaging/like-nes.wxs.in`, WiX v3 на раннере Windows, `wixl` из msitools для фикстур гейта. |
| 2б | Что воспроизводится у `.dmg` | **Содержимое образа, а не его байты** (решение владельца 2026-09-04). `hdiutil` пишет в UDIF время сборки и UUID: два `create` из одного каталога дают разные и сумму, и размер. Гейт пакует дважды и сверяет манифест смонтированного тома; обещать байт-равенство образа значило бы обещать то, чего формат не даёт. |
| 3 | Зависимости | **Спросить и доустановить, никогда молча.** Экран «нужно X, потому что Y», явное согласие, затем установка. Отказ — это валидный ответ: инсталлятор объясняет, что не будет работать, и выходит без изменений в системе. |
| 4 | Привилегии | **Повышение прав — только на конкретный шаг доустановки** и только после согласия. Установка самого движка — в пользовательский каталог, без администратора, если это возможно на данной ОС. |
| 3а | Зависимость Windows от VC++ Redistributable | **Снята внутри пакета, а не доустанавливается** (вертикаль 5, 2026-09-05). Наши цели — статический CRT; `VCRUNTIME140.dll`, которую просит предсобранный `wgpu_native.dll`, едет app-local рядом с ним; UCRT — компонент ОС с Windows 10. Решение 3 на Windows тем самым остаётся БЕЗ ПРЕДМЕТА: спрашивать нечего и доустанавливать нечего. Это отклонение от спеки, а не выполнение её буквы, и записано оно именно так — ADR 0019, решения 34 и 35. Для macOS и Linux решение 3 в силе. |
| 4а | Привилегии на Windows | **Их не требуется вовсе** (вертикаль 5). Шага доустановки не осталось, а сама установка идёт под `/qn` без UAC — это даёт БИТ 8 сводного потока, который компилятор пишет по `InstallScope="perUser"`, а не корень в `LocalAppDataFolder`. Инвариант «не требовать администратора там, где можно без него» усилился: мест, где нельзя, не осталось. |
| 4б | Тихий режим | **Родной для формата, а не свой флаг.** Спека просила `--yes`/`--silent` у инсталлятора; у MSI это `msiexec /qn` с логом `/l*v`, и писать поверх него свою обёртку значило бы делать вторую точку отказа ради своего имени флага. Утверждается тем же битом 8 — и на фикстуре, собранной здесь, и на установщике, приехавшем из CI. |
| 5 | Источники зависимостей | **Только официальные, пиннутые по версии и проверяемые по контрольной сумме/подписи.** Скачал-и-запустил из непроверенного источника — недопустимо (это же требование проверяет аудит #21). |
| 6 | Каталоги релизов | **`release/`, `dist/` — в `.gitignore`.** В репозиторий не попадает ни один собранный пакет. |

## Требования

### Функциональные — скрипт сборки (macOS-only)

- Одна команда собирает пакеты под три ОС в `release/<версия>/`; частичный запуск (только macOS,
  только Linux) — флагом.
- Версия берётся из тега (как `release.yml` в #8), в пакет кладётся штамп версии, коммита и
  целевой тройки.
- Linux-пакет собирается в контейнере на той же машине; отсутствие Docker/Podman — внятное
  сообщение с инструкцией, а не падение.
- Windows-пакет: запуск задачи CI по тегу, ожидание, скачивание артефакта, проверка контрольной
  суммы. Недоступность CI — внятное сообщение; сборка Windows-пакета локально на macOS **не
  заявляется** как возможная.
- Итог печатает таблицу: пакет, размер, контрольная сумма, что внутри; формируется файл
  контрольных сумм на весь релиз.
- Идемпотентность: повторный запуск на том же теге даёт те же артефакты (опирается на
  воспроизводимость сборки #8, гейт 1).

### Функциональные — установка движка

- **Проверка окружения перед установкой:** наличие GPU-драйвера с нужным API (Vulkan/Metal/D3D12),
  системных библиотек (X11/Wayland на Linux), рантаймов (VC++ Redistributable на Windows),
  тулчейна для разработки игр на движке (компилятор — движок компилирует игровой код, это его
  рабочий цикл), свободного места.
- **Диалог доустановки:** список недостающего с объяснением «зачем» и объёмом загрузки; согласие;
  установка; повторная проверка; затем установка движка. **На Windows этот пункт снят вертикалью 5**
  (решение 3а): доустанавливать нечего, пакет самодостаточен.
- **Тихий режим** (`--yes`/`--silent`) для автоматизации — с тем же набором проверок и полным
  логом того, что было установлено. **На Windows он родной для формата** (решение 4б): `msiexec /qn`
  и лог `/l*v`.
- **Установка движка:** бинарники редактора и инструментов, заголовки и библиотеки для сборки игр,
  шаблон проекта, игра-образец опционально, 7 файлов лицензий (#9), ярлыки/ассоциации — по
  соглашениям ОС.
- **Пользовательские данные** — в каталогах данных ОС (как `LIKENES_SAVE_DIR`, #10), не рядом с
  установкой.
- **Удаление:** штатная деинсталляция, не оставляющая ни файлов установки, ни записей в системе;
  пользовательские проекты и сохранения — не трогает и говорит об этом.
- **Обновление поверх** предыдущей версии не ломает существующие проекты.
- **Первый запуск после установки** открывает редактор с загруженной игрой-образцом или шаблоном.

### Нефункциональные (инварианты)

1. **Ничего не устанавливается без явного согласия.** Отказ оставляет систему нетронутой.
2. **Ни одной загрузки из непиннутого/непроверенного источника.** Каждый внешний артефакт — с
   зафиксированной версией и проверкой целостности.
3. **Не требовать администратора там, где можно без него.**
4. **Пакет самодостаточен** (наследуется из #8): после установки движок работает без ручной
   доводки путей и без интернета.
5. **Ни один релизный артефакт не попадает в git.**
6. **Отказ на любом шаге не оставляет систему в половинчатом состоянии:** установка либо
   завершена, либо откачена.

## Гейты приёмки (T3)

| # | Гейт | Критерий |
|---|---|---|
| 1 | Сборка релиза одной командой | на macOS: три пакета в `release/`, таблица и контрольные суммы напечатаны |
| 2 | Воспроизводимость | повторный прогон на том же теге → идентичные контрольные суммы |
| 3 | **Чистая macOS** | установка на систему без тулчейна: недостающее названо, согласие запрошено, доустановлено, движок установлен, редактор открылся |
| 4 | **Чистая Windows** | то же на чистой Windows: пакет НЕ требует VC++ Redistributable (несёт `vcruntime140.dll` рядом с рантаймом, наши бинари — статический CRT) и ставится под `/qn` без прав администратора. Машинная половина — `scripts/check_release_crt.sh` и бит 8 сводного потока; живая — §16 `owner-verification.md`, пункт P `owner-setup.txt` |
| 5 | **Чистый Linux** | то же на чистом дистрибутиве (контейнер/VM): X11/Wayland-зависимости, драйвер Vulkan |
| 6 | Отказ пользователя | отказ от доустановки → внятное объяснение, система не изменена (сверка состояния до/после) |
| 7 | Деинсталляция | после удаления не остаётся файлов установки; проекты пользователя целы |
| 8 | Обновление | установка новой версии поверх старой: проект, созданный до обновления, открывается и собирается |
| 9 | Лицензии в пакете | все 7 файлов присутствуют в каждом из трёх пакетов (регресс #9) |

## Не входит в скоуп

- Нотаризация macOS и подпись Windows-инсталлятора: требуют платных сертификатов владельца.
  Скрипт **готовит** к подписанию и оставляет явный шаг; в #8 это уже помечено как gated follow-up.
- Публикация в Steam/магазины (в #8 есть gated-путь через `steamcmd`), автообновление движка,
  пакетные менеджеры (Homebrew, winget, AUR) — после первого публичного релиза.
- Мобильные и консольные пакеты.
- Установка на Linux от имени root в системные каталоги: целимся в пользовательскую установку.

## Риски

| Риск | Митигация |
|---|---|
| Windows-пакет нельзя собрать на macOS честно | Решение 1: оркестрация через CI; ограничение названо прямо, а не замаскировано «кросс-сборкой» |
| Автоустановка зависимостей — идеальный вектор атаки | Решения 4/5 + отдельное внимание аудита #21: пиннутые источники, проверка сумм, минимум привилегий, никаких `curl | sh` |
| Проверка «чистой системы» после первой же установки перестаёт быть чистой | Гейты 3–5 гоняются на одноразовых VM/контейнерах со снапшотом |
| Дистрибутивов Linux много, зависимости разные | Целимся в две основные LTS-базы (deb/rpm), AppImage закрывает остальное; список поддерживаемого фиксируется явно |
| Оркестратор станет вторым CI | Скрипт не собирает Windows сам и не дублирует матрицу #8 — он её вызывает |
