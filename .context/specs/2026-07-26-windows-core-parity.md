# Спецификация #12: Windows-паритет ядра движка

- **Дата:** 2026-07-26
- **Статус:** **Draft** — раунд не начат. ADR пишется при закрытии раунда.
- **Наследует:** [#11](2026-07-26-repo-layout.md) (пишем уже в новую раскладку),
  [#5](2026-07-19-asset-pipeline.md) (`mmap`-загрузка), [#3](2026-07-19-audio-subsystem.md),
  [#6](2026-07-21-plugin-system.md) (загрузчик, крэш-изоляция), [#1](2026-07-18-language-and-core.md)
  (hot-reload host).
- **Уровень проверки:** **T4** — паритет доказывается тем, что golden-хеши Windows совпадают с
  POSIX, а гейты перестают быть помеченными POSIX-only.

## Контекст

Столп кроссплатформенности заявлен, CI гоняет три ОС — и это создаёт иллюзию готовности. По факту
на Windows собирается **подмножество** движка. В `CMakeLists.txt` пятнадцать блоков
`if(NOT WIN32)`; под них уходят:

- **ассет-пайплайн целиком** (`asset_core`, `assetc`, все asset-гейты) — причина в комментарии
  самого CMake: «POSIX-only (fork/execvp bake-tools, mmap загрузка)»;
- **аудио целиком** (`audio_core`, микшер, все audio-гейты);
- **hot-reload host** — то есть основной цикл разработки игры;
- **транскодер текстур** (`basis_transcoder`, `asset_gpu`, `asset_render`);
- **крэш-изоляция плагинов** — POSIX-сигналы; SEH заявлен в `architecture.md` как инвариант №4 и в
  комментарии CMake помечен «Windows SEH — follow-up»;
- в CI **24 шага** несут пометку POSIX-only.

Формулировка задачи владельца — «не делать игру под платформу, а **запустить движок и
разрабатывать** на платформе». Значит целевое состояние: разработчик на Windows клонирует репозиторий,
собирает, печёт ассеты, запускает игру, правит код и видит hot-reload — ровно как на macOS.

Этот раунд идёт **до** фреймворк-слоя (#14–#18) намеренно: иначе весь новый код фреймворка будет
писаться в POSIX-предположениях и retrofit обойдётся дороже, чем паритет сейчас.

## Ключевые решения (owner)

| # | Развилка | Решение |
|---|---|---|
| 1 | Компилятор Windows | **MSVC — основной, clang-cl — для санитайзеров.** MSVC определяет ABI Windows и консольный путь (#1); ASan в CI гоняется clang-cl, где инструментарий зрелее. |
| 2 | Форма портирования | **Абстракции, а не `#ifdef` по коду.** Три места ввода платформы: `platform_io` (маппинг файла), `platform_process` (запуск процесса), `platform_module` (загрузка библиотеки). `#ifdef` живёт только внутри них. |
| 3 | Изоляция сбоев | **SEH-фрейм на границе host↔lib** — симметрично POSIX-сигналам. Инвариант №4 архитектуры не имеет платформенных оговорок: крэш плагина не роняет редактор ни на одной ОС. |
| 4 | Hot-reload на Windows | **Copy-to-temp перед загрузкой.** Windows держит загруженный DLL залоченным, пересборка поверх невозможна — загружаем копию, оригинал остаётся свободным для компилятора. |
| 5 | Уровень проверки | **T4** — паритет = те же golden-хеши и те же гейты. Любой гейт, который на Windows «пропускается», паритетом не является. |

## Требования

### Функциональные

- **`platform_io`:** `CreateFileMapping` + `MapViewOfFile` как Windows-путь zero-copy загрузки
  бандла; `IoCaps{mmap=true}` на Windows честен. Выравнивание страниц и гранулярность маппинга
  (64 КБ на Windows против 4 КБ) не должны ломать zero-parse-раскладку бандла #5 — если ломают,
  правится **формат**, а не рантайм, и это меняет golden-хеш осознанно, с перепечёнными эталонами.
- **`platform_process`:** запуск дочерних процессов (`CreateProcessW`) взамен `fork`/`execvp` —
  нужен пекарю (`assetc` дёргает инструменты), build-loop'у и Play-spawn (последние — #13).
- **`platform_module`:** `LoadLibraryW`/`GetProcAddress`/`FreeLibrary` за тем же интерфейсом, что
  `dlopen`; сюда же — copy-to-temp политика hot-reload и корректная выгрузка.
- **Аудио на Windows:** `audio_core` собирается; устройство — WASAPI через miniaudio; RT-safety
  гейт (без аллокаций и блокировок в колбэке) гоняется на Windows.
- **Крэш-изоляция:** SEH-фрейм (`__try`/`__except` либо векторный обработчик, решение —
  в ADR) на вызовах в загруженный модуль; сбойный плагин/система отключается, процесс живёт.
- **Игра-образец собирается и запускается на Windows** — из бандла, с ассетами, со звуком.
- **Юникод-пути:** пути ОС на Windows — UTF-16; движок внутри работает в UTF-8, конвертация —
  только в платформенном слое. Путь с кириллицей/пробелами обязан работать (типовой профиль
  пользователя `C:\Users\Пётр\`).

### Нефункциональные (инварианты)

1. **Golden-хеши идентичны на трёх ОС.** Windows-путь не «свой вариант поведения», а тот же
   алгоритм на другой системной ручке.
2. **`#ifdef` не расползается.** Вне `engine/platform/*` условной компиляции по ОС нет — в конце
   раунда это проверяется грепом, а не обещанием.
3. **Ни один гейт не деградирует до warning.** Гейт либо гоняется на трёх ОС, либо явно и с
   обоснованием помечен в спеке как одноплатформенный (таких после раунда быть не должно).
4. **Отсутствие POSIX-эмуляции.** Ни MSYS, ни Cygwin, ни WSL: движок собирается нативным MSVC на
   чистой Windows.

## Гейты приёмки (T4)

| # | Гейт | Критерий |
|---|---|---|
| 1 | Ассет-пайплайн на Windows | `assetc` печёт бандл; синтетический byte-golden `0xf2255dc74fbdb6bc` совпадает с POSIX; zero-copy подтверждён (нет per-frame heap) |
| 2 | Аудио на Windows | mix-golden `0x2cf5b5597afa3241` совпадает; RT-safety гейт зелёный; живой вывод звука на реальном устройстве (owner-HW или VM с аудио) |
| 3 | Плагины на Windows | determinism-golden `0x7ad0493f0f2ddf47` совпадает; все 6 ext-point регистрируются; загрузка/выгрузка DLL без утечки хендлов |
| 4 | **SEH-изоляция** | плагин с намеренным нарушением доступа: процесс-хост выживает, плагин помечен мёртвым, состояние консистентно — зеркально POSIX-гейту |
| 5 | Hot-reload на Windows | правка → пересборка → swap **без остановки хоста**; state остаётся в хосте; залоченный DLL не мешает компилятору |
| 6 | Игра-образец на Windows | sim-golden `0x32a094e89eacf2f2` совпадает; игра запускается из бандла и играбельна |
| 7 | Санитайзеры на Windows | ASan (clang-cl) на ассет/аудио/плагин-путях — чисто |
| 8 | Юникод-пути | сборка, бейк и запуск из каталога с кириллицей и пробелом в имени |
| 9 | CI без POSIX-only | в `ci.yml` не остаётся шагов, пропускаемых на Windows по причине «пока нет пути» |

## Не входит в скоуп

- IDE, IPC, Play-spawn, build-loop — это #13 (там своя платформенная поверхность: shmem, watcher,
  парсер диагностик MSVC).
- Инсталляторы и релизные пакеты Windows — #20.
- ARM64-Windows: собирать не мешаем, гейтом не делаем (нет железа для честной проверки).

## Риски

| Риск | Митигация |
|---|---|
| Гранулярность маппинга 64 КБ ломает zero-parse раскладку #5 | Проверить в начале раунда, до остального: если формат надо менять — это меняет три golden-хеша и должно быть решено ADR'ом явно |
| MSVC иначе раскладывает битовые поля/структуры → едет golden | Бандл и sim уже POD+fix32 и совпадают в существующих гейтах; при расхождении — фиксировать раскладку явно (`#pragma pack`/static_assert на размеры), а не подгонять эталон |
| SEH и C++-исключения конфликтуют (`/EHa`) | Изоляция локализована на границе модуля; решение по режиму исключений фиксируется в ADR с замером стоимости |
| Нет живой Windows-машины у владельца | Гейты 1–3, 5, 7–9 автоматизируются в CI; для гейта 2 (звук) и 6 (играбельность) нужен ручной прогон — либо VM, либо явно отложить эти два гейта как owner-HW follow-up (**решить до старта раунда**) |
