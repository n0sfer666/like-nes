# Спецификация #29: Пилот новой игры — фэнтези-боевые искусства, арт-пайплайн, тюнинг баланса

- **Дата:** 2026-10-19
- **Статус:** **Черновик** — интервью владельца закрыто 2026-10-19 (пять раундов, решения ниже).
  Следующий шаг — В1 (пакет промптов `docs/art/`), владелец генерирует арт параллельно с В2–В5.
- **Решение:** [ADR 0021](../decisions/2026-10-19-pilot-game.md) — новая игра, Neon Rumble остаётся
  стендом гейтов, SDK даёт только абстракции (жанровое — в игре), константы абстракций —
  параметрами с прежними дефолтами.
- **Отменяет в [#23](2026-10-01-beatemup-game.md):** сеттинг «киберпанк, CC0-паки», «без оружия и
  спецприёма», зону 384×216 как единую для всех игр, раунд #28 «игра Neon Rumble». Движковые раунды
  #24–#27 остаются в силе.
- **Наследует:** [#24](2026-10-01-content-pipeline.md) (Aseprite JSON, Tiled, параллакс, инвентарь
  лицензий, бюджет ассетов, SDK), [#25](2026-10-05-brawl-framework.md) (`LNFT`, цепочки, захват,
  ИИ, камера, хотсит), [#26](2026-10-15-ui-mobile-saves-music.md) (тач, UI), [#5](2026-07-19-asset-pipeline.md)
  (hot-reload по `platform::Watcher`), [#13](2026-07-21-ide-editor.md) (редактор `tools/ide`).
- **Уровень проверки:** **T4** на разборе `brawl/` (хеши rumble, строки sdk-game и crossplay
  неподвижны) и читателе `.tune` (fuzz, отказы, перезагрузка на границе
  тика); **T2** на бейке пилота и панели; **T3/владелец** — игра на живом железе, арт на глаз.

## Контекст

Владелец прошёл 12 окон brawl из `docs/owner-verification.md` (§22–§28, вся B3, §30–§33, §35):
технически всё зачёт, вдвоём на клавиатуре и паде. Замечания:

| Замечание | Причина в коде |
|---|---|
| Тайлы и текстуры негодны | CC0-киберпанк не держит стиль; владелец меняет сеттинг |
| Прыжок низкий | `jump_vy 6`, `gravity 0.5` → пик 36 px при фигуре ~90 px, в воздухе 0,4 с |
| Бросок хватает всех в боксе | `sweep()` (`engine/framework/brawl/hit_collect.cpp:84-89`) пушит `HitEvent` на каждую цель захвата; `tear_grabs()` рвёт только конфликт двух захватчиков |
| Отброс ломает цепочку | `jab knock_x 1`, `cross 1.5` — звено выносит цель за досягаемость следующего |

Разведка (`.context/notes/art-and-tuning-research.md`): `viewport_fit(screen, zone)` уже принимает
зону, но поводок камеры фреймворка зовёт `VIEW_ZONE` (`stage_step.hpp:16`); боец — один `sheet`,
лист ≤ 2048 по стороне; палитрового свопа, супера, финишера, лестницы в belt, лазания, подбора и
броска предметов, дропа из ящиков, косметической живности в движке нет. Баланс rumble наполовину в
данных (`.fighter`), наполовину в константах игры и фреймворка. Плагинная панель (`EXT_UI_PANEL`)
рисует виджеты из манифеста без привязки к данным.

## Ключевые решения (владелец, 2026-10-19)

| Тема | Решение |
|---|---|
| Игра | Новая, `games/pilot/` (рабочее имя, переименование после пилота). Пишется **с нуля на абстракциях SDK**, код rumble не копируется. Свой цикл драки, прыжок, захват, цепочки, ИИ |
| SDK | **Только абстракции, без жанра** (правило `CLAUDE.md`, правило 7 `engine/framework/README.md`). В SDK: физика, расписание систем, корутины и циклы, клипы, реплей и откат, камера с политиками, тайлмап, параллакс, ввод и тач. Не в SDK: `brawl/`, контроллер персонажа `character/`, жетоны атаки `ai/` |
| Neon Rumble | Поведение не меняется: стенд гейтов. Жанровый код `brawl/` переезжает в неё, общее остаётся абстракцией SDK; её `bundle.hash`, строки sdk-game и crossplay-хеши — доказательство, что переезд логику не сдвинул |
| Жанр и сеттинг | Beat'em up про боевые искусства в фэнтези. Pixel art уровня современных детальных 2D-экшенов и поздней 16-битной классики; названия игр и художников в промпты не ставятся |
| Зона | 640×360, целый масштаб; бойцы ~100–110 px. Зона — настройка игры, у rumble остаётся 384×216 |
| Герои | Дед-монах (~96 px, сухой, чуть сгорблен), девушка с кинжалами в модном корейском стиле (~102 px), русский кикбоксёр (~114 px). Кинжалы — её стиль боя, не предмет |
| Клипы героя | Ходьба, бег, прыжок, получение удара, сбит/упал, бросок, удар, супер, удар с разбега, добивание лежачего с разбега, лазание по лестнице/верёвке, удар с лестницы/верёвки, бросок предмета, подъём предмета (+ обязательные клипы `archetype.cpp`) |
| Враги | Два рядовых (ходят, бьют), прыгун (ходит, бьёт, прыгает, бегает), крупный (бьёт, бросает); все падают и получают удары. Рост ~104 / ~100 / ~135 px |
| Варианты врагов | Шейдер палитры в движке: indexed-арт, отдельный ramp на каждую сменную часть |
| Супер | Шкала ци копится ударами; шкала в HUD и аура |
| Предметы | Только метательные: камни, горшки, кунаи, еда-лечение. Дроп из ящиков — еда и метательное |
| Этап | Один: горная дорога к монастырю — деревня → бамбуковая роща → верёвочный мост → ворота храма |
| Планы | 4 задних (небо; дальние горы в тумане; склоны с соснами; ближний — дома, бамбук) + игровая дорога + 1 передний |
| Тон | Тёплый рассвет/закат в горах: охра, золото, синеватые тени, туман |
| Живность | Птицы на деревьях взлетают при драке, ящерицы на камнях уползают, зверь прячется в кустах. Чистая косметика вне симуляции, читает состояние |
| Пайплайн арта | ChatGPT Images — style bible, model sheets, ключевые позы, фоны по плану; PixelLab — анимация; Aseprite — сборка и экспорт. Пакет промптов с чек-листами — `docs/art/` |
| Пилот арта | Монах + рядовой враг (с палитровыми вариантами) + один экран фона. Арт описан на всё сразу, механики — раундами |
| Лицензия | CC0, автор — владелец, пометка об ИИ-генерации в `LICENSES.toml` (раскрытие для Steam) |
| Файлы баланса | `games/pilot/tuning/<тема>.tune`, стиль `.fighter`: `ключ \| значение \| min..max step s \| описание`; запекаются в бандл |
| Объём выноса | Всё: константы пилота — в `.tune` с первого коммита; константы абстракций SDK — параметрами с прежними дефолтами |
| Панель | Панель редактора `tools/ide`, строится из самих `.tune`: вкладка на файл, слайдер + поле на ключ. ABI плагинов не меняется, ключи не дублируются |
| Применение | Вживую на границе тика + кнопка «рестарт волны». В режиме тюнинга (`--tuning-dir`) запись реплея и сеть выключены |
| Сохранение | Панель пишет прямо в `.tune` в репо; история — `git diff`. Перепин хешей пилота — при коммите значений |
| Бросок | Захват — код пилота: одна цель, ближайшая по \|dx\|, затем seq. Rumble сохраняет свой захват всех целей в боксе |
| Прыжок и отброс | Стартовые значения пилота: прыжок ~2× выше, звенья цепочки без отброса; дальше владелец крутит на панели |

## Вертикали

Каждая вертикаль — PR `dev` → `main`, как в #26.

### В1. Пакет промптов `docs/art/`

Файлы: style bible (палитра-ориентир, свет, контур, детализация на 640×360, запреты), model sheets
трёх героев и четырёх врагов с ростом и сменными частями, раскадровка всех клипов (позы-ключи на
клип, число кадров, тайминг, pivot, где хитбокс), фон по планам на хромакее, тайлы дороги и
моста, пропсы (ящики, метательное, еда), живность. На каждый шаг — промпт, что приложить
референсом, чек-лист приёмки (рост, базовая линия, руки и оружие на месте, палитра) и что
делать при дрейфе. Отдельно — экспорт: квантизация в indexed с ramp на сменную часть, PixelLab,
Aseprite (Array + Tags + Slices, By Rows, 8 колонок, слайсы `hit0..3 hurt0..3 push pivot`, user
data `кадр:событие`).

**DoD:** пакет в репо, порядок шагов от style bible до пилота; владелец прошёл шаги пилота.

### В2. Разбор `brawl/`, `character/` и жетонов `ai/`

Инвентарь: каждый файл — абстракция (хитбоксы и их геометрия, стоп-кадр, буфер ввода, глубина
belt, тело на полосе) или жанр (бойцы `LNFT`, цепочки, захват, реакции, волны, арены, секции,
жетоны, контроллер персонажа). Абстракции остаются в SDK, их константы — параметрами с прежними
дефолтами (зона поводка камеры вместо `VIEW_ZONE`); жанр переезжает в `games/neon-rumble/` и в
игру, которая держит контроллер персонажа. `cmake/sdk_headers.cmake`, документация SDK en/ru и
гейт `sdk-game` — по новому составу. Crossplay-сценарии жанра идут за своей игрой.

**DoD:** `bundle.hash` rumble, строки `sdk_game_run.sh`/`sdk_game_coop.sh` и все crossplay-хеши
неизменны; в установленном SDK нет жанровых заголовков (гейт по списку запрещённых имён с
сломанной фикстурой); инвентарь с решением по каждому файлу — в спеке раунда.

### В3. Каркас `games/pilot/` на заглушках

Своя цель CMake на `find_package` установленного движка, зона 640×360, один экран этапа серыми
блоками, монах и рядовой враг прямоугольниками-заглушками с хитбоксами, хотсит клавиатура + пад,
стартовые прыжок и цепочка. Цель в Makefile, CI и `check_sdk_game.sh`; запись в
`owner-verification.md`.

**DoD:** игра собирается против SDK на трёх ОС, бот-прогон headless детерминирован; владелец:
прыжок и цепочка ощущаются, бросок берёт одного.

### В4. `.tune`: формат, бейк, живая перезагрузка

Читатель через `platform::read_text` (fs-seam), fuzz-цель, отказы со строкой; бейк в бандл;
`--tuning-dir` — `platform::Watcher`, применение на границе тика, реплей и сеть выключены; команда
«рестарт волны». Темы: бойцы, враги и ИИ, волны, управление, камера, предметы, супер.

**DoD:** битый файл — отказ с номером строки, игра продолжает на прежних значениях; правка файла
меняет поведение в следующем тике; без `--tuning-dir` бандл и хеш те же, что из бейка.

### В5. Панель тюнинга в редакторе

Вкладка на `.tune`, слайдер + поле на ключ (диапазон и шаг из файла), «сохранить», «сбросить к
файлу», «рестарт волны». Пишет те же файлы, что читает игра.

**DoD:** новый ключ в файле появляется на панели без пересборки; сохранение меняет только
значение в своей строке (остальной файл байт-в-байт).

### В6. Арт пилота в движке

Несколько листов на бойца, шейдер палитры (indexed + ramp на часть) с вариантами рядового,
4 + 1 планов параллакса, монах и рядовой из пакета В1, лицензии CC0.

**DoD:** голден квадов и палитры; бюджет 30 МиБ; владелец на глаз: стиль, читаемость, варианты.

### Дальше (спеки раундов пишутся перед стартом)

Шкала ци и супер; подбор и бросок предметов, ящики с дропом; лестница и верёвка в belt, удар с
них; финишер по лежачему; девушка и кикбоксёр; прыгун и крупный; косметическая живность; этап
целиком (4 части); переименование игры.

## Риски

| Риск | Ответ |
|---|---|
| ИИ не держит кадры одного персонажа | Ключевые позы по 1–4 за запрос с референсом model sheet, in-betweens — PixelLab; чек-лист приёмки в В1. Монах — худший случай (рукава, борода, чётки) |
| Лист 2048 не вмещает бойца ~110 px | Мульти-лист в В6 |
| Тюнинг ломает реплей и откат | Режим тюнинга выключает реплей и сеть; без `--tuning-dir` — только бейк |
| Разбор `brawl/` сдвигает rumble | Хеши rumble, sdk-game и crossplay — гейт В2 |
| Пилот пишет заново то, что умеет rumble | Цена правила «SDK без жанра»; общее, что понадобится обеим играм, поднимается абстракцией в SDK, а не копируется |
| Масштаб «всё сразу» | Арт описан целиком, механики идут вертикалями; пилот — один герой, один враг, один экран |
