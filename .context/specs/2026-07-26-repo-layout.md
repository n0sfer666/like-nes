# Спецификация #11: Реорганизация репозитория (движок ≠ игра-образец)

- **Дата:** 2026-07-26
- **Статус:** **Draft** — раунд не начат. ADR пишется при закрытии раунда.
- **Наследует:** [#8](2026-07-23-build-deploy.md) (игра-образец, бандлы, `scripts/package.sh`,
  `release.yml`), [#9](2026-07-25-licensing.md) (файлы лицензий в бандлах — пути ломаются переездом),
  [#10](2026-07-25-achievements.md) (бейк манифеста в `assetc --game`).
- **Уровень проверки:** **T3** — механический переезд без изменения поведения; доказательство —
  побитовое совпадение всех golden-хешей и зелёный CI на 3 ОС.
- **Блокирует:** #12–#21. Все последующие раунды пишут код в новую раскладку.

## Контекст

Весь код живёт в `poc/` — включая игру-образец `poc/game/` (47 файлов). Имя `poc` было честным на
раунде #1, но после десяти закрытых спек оно врёт: это не прототип, а движок. Хуже другое — игра
лежит **внутри** дерева движка и собирается тем же `CMakeLists.txt` (644 строки, один файл на все
таргеты). Из-за этого:

- граница «движок / игра на движке» не проверяема: игра свободно включает внутренние заголовки
  подсистем, и никто этого не замечает;
- потребитель движка не видит, что именно ему нужно взять, а что — пример;
- корень репозитория засорён: в git **закоммичены** ~20 санитайзерных бинарников
  (`asset_test_san`, `ide_*_san`, `input_*_san`, `plugin_*_san`, `audio_*_san`) и артефакты
  `audio.bundle`, `syn.bundle`. Это мусор от локальных прогонов гейтов, попавший в историю.

Раунд — механический: ни одна строка логики не меняется. Ценность в том, что после него граница
движка становится физической (директория + отдельный CMake-таргет), а не устной договорённостью.

## Ключевые решения (owner)

| # | Развилка | Решение |
|---|---|---|
| 1 | Раскладка | **`engine/` + `tools/` + `example_ugly_game/` в корне.** `poc/` исчезает как имя. Одна игра-образец, без `examples/`-множественности — второй пример появится, когда будет что показывать (#16/#17). |
| 2 | Граница движок/инструменты | **Рантайм и инструменты разъезжаются.** `engine/asset/` — рантайм-чтение бандла (`bundle_view`, `asset_manager`, `platform_io`); `tools/assetc/` — пекарь (`assetc_main`, `bakers`). Сегодня они в одной директории, и это скрывает, что пекарь в игру не линкуется. |
| 3 | Тесты | **Остаются рядом с модулем** (`engine/audio/audio_golden_main.cpp` и т.д.). Вынос в `tests/` — отдельное решение отдельного раунда; смешивать его с переездом значит потерять доказуемость «диff чисто механический». |
| 4 | CMake | **Разбить по таргетам:** корневой `CMakeLists.txt` + `CMakeLists.txt` в каждом модуле. 644 строки в одном файле — уже неподдерживаемо, а переезд всё равно переписывает каждый путь. |
| 5 | История git | **`git mv`, без переписывания истории.** `git log --follow` продолжает работать; rewrite ради удаления бинарников из истории не делаем (см. «Не входит в скоуп»). |

## Требования

### Функциональные

- **Целевое дерево:**

```
like-nes/
├── CMakeLists.txt              # только add_subdirectory + общие опции
├── cmake/                      # ← poc/cmake (тулчейны, хелперы)
├── engine/
│   ├── core/                   # ← poc/src (fixed.hpp, license.hpp, determinism_test)
│   ├── asset/                  # ← poc/asset минус пекарь (рантайм-чтение)
│   ├── render/  audio/  input/  plugin/  achievements/  hotreload/
│   └── framework/              # пусто; наполняется в #14–#18
├── tools/
│   ├── assetc/                 # ← poc/asset/{assetc_main,bakers}.*
│   └── ide/                    # ← poc/ide
├── platform/                   # ← poc/{ios,android,mobile}
├── example_ugly_game/          # ← poc/game (включая assets/ и packaging/)
├── scripts/                    # ← poc/scripts
└── .context/  .github/  docs/  # docs/ создаётся в #19
```

- **Корень чист:** в git не остаётся ни одного собранного бинарника или `.bundle`. `.gitignore`
  дополняется правилами, закрывающими санитайзерные артефакты (`*_san`, `*_tsan`, `*.bundle`)
  и релизные каталоги (последнее — договорённость #20).
- **Игра-образец собирается отдельным таргетом** и линкуется только с публичными таргетами движка.
  Включение внутреннего заголовка подсистемы из `example_ugly_game/` — ошибка конфигурации, а не
  вопрос дисциплины: у модулей движка публичные `target_include_directories` содержат только то,
  что предназначено потребителю.
- **Все потребители путей обновлены:** `.github/workflows/{ci,release,dco}.yml`, `scripts/*.sh`,
  `scripts/gen_rust_notices.py`, `packaging/*.in`, установочные правила лицензий (#9), пути к
  `game.bundle`, `.serena/`, `CONTRIBUTING.md`, `CLAUDE.md`, ссылки в `.context/`.
- **Имя `poc` не встречается** ни в одном отслеживаемом файле, кроме исторических записей
  `.context/notes/*-poc.md` и текстов закрытых спек (их не переписываем — они фиксируют прошлое).

### Нефункциональные (инварианты — нарушение = баг)

1. **Ни один golden-хеш не меняется.** Переезд файлов не может изменить поведение; если хеш
   поехал — это не переезд, а правка, и её надо найти.
2. **Ни один гейт не исчезает.** Число шагов CI до и после совпадает; шаг, который «временно
   отключили, чтобы позеленело», — провал раунда.
3. **Воспроизводимость сборки (#8, гейт 1) сохраняется** — сборка дважды из разных путей
   по-прежнему даёт байт-идентичные артефакты.
4. **Самодостаточность бандлов (#8/#9) сохраняется:** `.app`, tarball и папка по-прежнему
   стартуют из чужого `cwd` и содержат все 7 файлов лицензий.

## Гейты приёмки (T3)

| # | Гейт | Как проверяется |
|---|---|---|
| 1 | Дерево соответствует целевому | `git ls-files` не содержит путей `poc/`; корень содержит только описанные каталоги и файлы |
| 2 | **8 golden-хешей целы** | `0xa213fe659921c9fb` (ядро), `0xf2255dc74fbdb6bc` (asset), `0x2cf5b5597afa3241` (audio mix), `0x4c6429af58bde01e` (input), `0x7ad0493f0f2ddf47` (plugin), `0x2de54a36e54e0684` (IDE scene), `0x32a094e89eacf2f2` (game sim), `0xe728fef199e87fc9` (achievements) |
| 3 | CI зелёный на 3 ОС | `ci.yml` целиком, без изъятых шагов; сравнение списка шагов до/после |
| 4 | Корень очищен | бинарники и `.bundle` удалены из индекса (`git rm --cached`), `.gitignore` не даёт вернуться: повторный локальный прогон гейтов не порождает изменений в `git status` |
| 5 | Граница движок↔игра | попытка включить внутренний заголовок подсистемы из `example_ugly_game/` не компилируется (проверяется одним намеренно сломанным TU локально, в репозиторий не коммитится) |
| 6 | Паковка жива | `scripts/package.sh` собирает `.app` на macOS, tarball на Linux; smoke-запуск из чужого `cwd` проходит |
| 7 | Релизный путь жив | `release.yml` проходит dry-run (без публикации) с новыми путями |

## Не входит в скоуп

- **Переписывание git-истории** (`filter-repo` для выпиливания бинарников из прошлых коммитов) —
  ломает все существующие клоны и ссылки на коммиты в спеках. Бинарники удаляются из рабочего
  дерева и индекса; вес истории — отдельное решение владельца.
- Вынос тестов в `tests/`, смена системы сборки, разбиение модулей на под-библиотеки —
  архитектурные правки, не переезд.
- Публичный `install()`-интерфейс движка как SDK (заголовки + `like-nesConfig.cmake`) — это #20.

## Риски

| Риск | Митигация |
|---|---|
| Переезд «заодно чинит» пару мелочей — и хеш едет | Правило раунда: любая правка, кроме пути, делается **отдельным коммитом до или после** переезда, не внутри |
| `game.bundle` — бинарный ассет, `git mv` его теряет/портит | Гейт 6 запускает игру из бандла; плюс сверка sha256 файла до/после |
| Windows-специфика путей в CI (обратные слэши, MSVC env) | Гейт 3 гоняет все три ОС; правки CI делаются одним проходом, не «сначала Linux» |
| Потеря `git log --follow` на переименованных файлах | Только `git mv`, без удаления+добавления; переезд отдельным коммитом, без правок содержимого |

## План работ

1. Удалить из индекса собранные артефакты, дополнить `.gitignore` — **отдельный коммит**.
2. `git mv` по целевому дереву — **отдельный коммит**, без единой правки содержимого файлов.
3. Разбить `CMakeLists.txt` на корневой + per-module; выделить `tools/assetc`.
4. Обновить CI, скрипты, паковку, документы контекста.
5. Прогнать гейты 1–7, записать verify-state, независимое ревью, коммит.
