# Вертикаль 2 спеки #19 — примеры собираются, фрагменты берутся из них

## Что закрывается

- **Гейт 2**: все файлы `docs/examples/` компилируются и ЗАПУСКАЮТСЯ в CI на трёх ОС.
- **Гейт 3**: фрагменты в тексте извлекаются по маркерам; отсутствующий маркер — ошибка.
- Решение 5 спеки: «примерного кода» в документации нет, всё показанное — из собираемого файла.

## Устройство

Маркеры в источнике:

    // docs:begin(<имя>)
    ...
    // docs:end(<имя>)

Врезка в `.md`:

    <!-- snippet: docs/examples/<файл>#<имя> -->
    ```<язык>
    <тело>
    ```
    <!-- /snippet -->

Без `#<имя>` берётся файл целиком (так вставляется ожидаемый вывод `.out`).

**Источник фрагмента обязан лежать в `docs/examples/`.** Тогда «показанный код собирается и
запускается» доказано гейтом 2 для КАЖДОГО источника, а не заявлено. Путь в произвольный
исходник дерева выглядел бы честнее, но проверять было бы нечем.

## Находки, которые обязаны быть отбиты

Механизм врезок (`docs_snippets_lib.sh`):
1. источника нет в дереве; 2. источник вне `docs/examples/`; 3. маркера нет в источнике;
4. маркер открыт и не закрыт; 5. маркер объявлен дважды; 6. тело врезки разошлось с источником;
7. открывающий комментарий без `<!-- /snippet -->`; 8. между ними нет fenced-блока;
9. ноль врезок во всём дереве — ОТКАЗ (vacuous-gate).

Гейт примеров (`check_docs_examples.sh`):
10. ноль примеров — отказ; 11. у примера нет `.out`; 12. пример не собран;
13. пример упал ненулевым кодом; 14. вывод разошёлся с `.out`;
15. `.out` есть, а примера с таким именем нет (протухший голден).

## Синхронизатор

`scripts/docs_snippet_sync.sh` переписывает тела ВСЕХ врезок из источников. Массовость здесь
безвредна, в отличие от `docs_stamp.sh`: тело врезки выводится из источника механически,
подтверждать нечего, а штамп перевода — акт подтверждения человеком.

## Инварианты дерева

`docs/examples` добавляется в корни `tree_invariants.sh` и `ascii_output_check.py`: пример,
обходящий шов `platform::Args`, УЧИТ обходить шов. Рукописный список корней ровно поэтому и
проверяется — новый корень с кодом молча остался бы непроверенным.

## Прогресс

- [x] примеры + CMake-цели (`fixed_point`, `schedule_order`, GLOB → `doc_example_<имя>`)
- [x] механизм врезок + гейт + самопроверка (24 контроля)
- [x] гейт сборки/запуска + самопроверка (14 контролей)
- [x] руководства en/ru, использующие врезки (`guide/tick-and-schedule`, `guide/determinism`)
- [x] корни инвариантов, CI, preflight, checks.json, CLAUDE.md, .context

Синхронизатор написан на python (`docs_snippet_sync.py`), а не на шелле, как задумывалось выше:
разбор врезок и так живёт в `docs_snippets_lib.py`, и вторая реализация тех же маркеров разъехалась
бы с первой молча.

Каталог сборки гейт и его самопроверка берут аргументом: preflight даёт `build-full`, CI — `build`.
Прибитое умолчание молча пропускало бы в CI единственный кейс на настоящих бинарях.

## Ревью: что добавилось сверх плана

- **Голый фенс языка КОДА вне врезки — находка.** Без этого решение 5 держалось дисциплиной: гейт
  сверял врезки и молчал про блок, написанный руками рядом. Список языков кода закрытый
  (`cpp`, `c`, `cc`, `h`, `hpp`), опорный `pass` на ` ```sh ` стоит рядом с порчей.
- **Маркер без врезки — находка** (обратное направление): переименованная врезка оставляла в
  примере мёртвый `docs:begin`, молча описывающий вчерашний текст. Файл, показанный целиком,
  освобождает все свои маркеры.
- **Префикс каталога проверяется после нормализации**: `docs/examples/../../engine/…` открывался.
- **Маркеры источника разбираются всегда**, а не только для именованной врезки: незакрытый
  `docs:begin` в файле, показанном целиком, забирает тело до конца файла.
- **Язык фенса против расширения источника**: `.cpp` под ` ```text ` рендерится без подсветки.
- **Список корней сверяется между копиями** — `scripts/check_tree_roots.py`, форма `mirrors-group`.
- **Самопроверки в CI переставлены ПЕРЕД гейтами** (три пары): сломанное правило молчит неотличимо
  от чистого дерева.
- **`newline="\n"` в синхронизаторе**: на Windows он переписал бы концы строк всего документа.
