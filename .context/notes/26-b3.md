# #26 В3: мобильные геймпады и хаптика

## В3а: backend отдельно от GLFW

`input_gamepad` содержит только native source и зависит от input_core. Desktop input_native
содержит GLFW-пумп и тянет input_gamepad транзитивно: интерфейс make_gamepad_source и прежние
имена desktop backend сохранены. Apple source один для macOS/iOS; имя iOS задаёт CMake,
старым standalone-примерам оставлен прежний macOS default. GameController/CoreHaptics/Foundation
приходят через input_gamepad; iOS mobile shell экспортирует его зависимость через SDK.
Android получает отдельный NDK backend следующим блоком В3б ниже.

`sdk_game_gamepad.sh` проверяет closure input_gamepad + engine на отсутствие GLFW/input_native,
линкует реальный native source из установленного SDK и запускает его на desktop (init/poll,
безопасные invalid slot/rumble, имя backend). Под iOS только настоящая cross-сборка/линковка:
наличие пада и тактильный отклик этим не доказываются. Fixture идёт в sdk-game на desktop и iOS.
Обход раскрывает LINK_ONLY и держит циклы; самопроверка3 good/4 bad на настоящем CMake-правиле
отвергает прямые/косвенные оконные зависимости, включая PRIVATE-ребро статики.

## В3б: Android source и мобильная игра

input_gamepad теперь есть в Android SDK. NDK AInputEvent даёт кнопки/оси без JNI: Gamepad,
Joystick и DPAD только подтверждённого gamepad-паспорта; remote/keyboard/touch не захватываются.
Оси насыщаются до fix32, Y уже вниз, Z/RZ либо RX/RY выбираются по MotionRange; аналоговые
и цифровые триггеры объединяются независимо, как key/hat у DPAD. Слоты различают physical id,
reported id карантинит повторное использование до отдельного poll отключения: Lobby видит Lost.

JNI-инвентарь100ms обнаруживает тихий unplug; VID/PID/name читаются один раз на подключение.
Ошибка инвентаря освобождает held и отключает пад; после восстановления нужен обычный reclaim.
JNIEnv берётся у текущего native-потока через AndroidVm, отсоединяется только собственное
соединение. Общая библиотека покрывает обе ABI-сигнатуры AttachCurrentThread (JDK/NDK).
Android pad rumble идёт через InputDevice/Vibrator/VibrationEffect, clamp1..255, cancel,
нечисловые значения и отсутствие мотора безопасны. Suspend/teardown отменяют только ещё
действующий эффект этого клиента. VIBRATE уже был в манифесте.

MobileRumble опрашивает GamepadSource перед Hotseat на iOS/Android; demo не читает hardware.
CPU fixture11 режимов: native pad даёт тот же hash, что эквивалентный touch; unplug61 оставляет
сцену на60 и ставит паузу. Прежние9 режимов/хешей сохранены. NDK host fixture использует настоящий
source/InputEngine/Lobby/PadRegistry и NDK headers с моком событий/паспортов ОС.
JNI mock47 exception paths+VM ownership+negative NewStringUTF; настоящая JVM с -Xcheck:jni
исполняет android_pad_device.cpp против моделируемых Android классов: имена/ids/ranges,
ошибки, bounded arrays,50 native thread attach/detach и ABI long/int у вибрации.
Это не настоящий Android framework или доказательство работы моторов.

Контроли при разработке: 6 production-мутантов (reuse slot, lost DPAD/digital trigger,
Y inversion, held после JNI failure, wrong Vendor getter) отвергнуты. Строгая cross-сборка
Android x86_64/arm64, свежие SDK packages и gamepad-only closure проверяются этим блоком.
Нативная проверка доступного macOS GameController сообщила0 extended pads; host haptics0.
Живые кнопки/моторы и Android emulator остаются долгом, сенсорный iOS-критерий закрыт владельцем.

Основание API: [InputDevice](https://developer.android.com/reference/android/view/InputDevice),
[Android controller input](https://developer.android.com/games/sdk/game-controller/controller-input).
Дальше: общий haptic::pulse, Phone и вне-симуляционный декор HitEvent; В3 ещё не закрыта.
