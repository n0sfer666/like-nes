# #26 В3: мобильные геймпады и хаптика

## В3а: backend отдельно от GLFW

`input_gamepad` содержит только native source и зависит от input_core. Desktop input_native
содержит GLFW-пумп и тянет input_gamepad транзитивно: интерфейс make_gamepad_source и прежние
имена desktop backend сохранены. Apple source один для macOS/iOS; имя iOS задаёт CMake,
старым standalone-примерам оставлен прежний macOS default. GameController/CoreHaptics/Foundation
приходят через input_gamepad; iOS mobile shell экспортирует его зависимость через SDK.
Android пока не содержит этой цели: его backend будет отдельным следующим шагом.

`sdk_game_gamepad.sh` проверяет closure input_gamepad + engine на отсутствие GLFW/input_native,
линкует реальный native source из установленного SDK и запускает его на desktop (init/poll,
безопасные invalid slot/rumble, имя backend). Под iOS только настоящая cross-сборка/линковка:
наличие пада и тактильный отклик этим не доказываются. Fixture идёт в sdk-game на desktop и iOS.
Обход раскрывает LINK_ONLY и держит циклы; самопроверка3 good/4 bad на настоящем CMake-правиле
отвергает прямые/косвенные оконные зависимости, включая PRIVATE-ребро статики.

Дальше: Android gamepad events/metadata/hotplug, подключение источников к мобильной игре,
phone/pad pulse и вне-симуляционный декор HitEvent. Физические gamepad/haptics требуют железа;
симулятор обязан корректно оставаться без haptic engine.
