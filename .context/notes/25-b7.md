# Спека #25, В7 — состояние раунда

Вход — `dev` после merge PR #57 (`41ae8d5`). Спека — §В7, строка гейтов В7: «загрузка уровня из
бандла; респаун у чекпоинта = голден», сломанная фикстура «битое имя уровня — краш вместо возврата».

Решения владельца 2026-10-12 (до кода):

- **Стек сцен** — `framework::scene::SceneStack` фиксированной ёмкости 4. Сцена = `{Schedule,
  user, rollback}` (флаг: в сессии отката или вне её, меню — вне). `push`/`pop`/`replace` копятся
  и применяются в начале следующего тика, не посреди шага. Стек в снапшот и хеш не входит.
  Затемнение — счётчик кадров у игры, декор вне хеша.
- **Меню в Neon Rumble** — минимальное текстовое, шрифтом титров: уровень / `--wave` / титры,
  строка ошибки загрузки над пунктами. Меню → уровень — `replace`.
- **Загрузка уровня** — `framework::scene::load_level(bundle, name, Level&, LoadError&)`:
  `LNTM` + `LNVL` + `LNOB` уровня по имени, `LNCL` + `LNFT` — бойцы, на которых ссылаются
  `spawn.kind`; нет бойца — отказ с текстом. Ошибка — строка в фиксированном буфере, фреймворк в
  stderr не печатает. `rumble::Level` переезжает во фреймворк. Сломанные фикстуры: битое имя,
  нет таблицы, битый `LNOB`, неизвестный `kind`.
- **Прогресс** — `LevelProgress{int16_t checkpoint = -1}`: `order` последнего взятого. Взят, когда
  `x` живого игрока на опоре пересёк `x` точки; засчитывается только больший `order`, назад не
  откатывается. Зачищенные волны — существующий `StageWaves.cleared` (В6), без дубля. Свой
  `progress_hash` в хеше сессии. Смерть — факт `Death{EntId}` от фреймворка в тике `hp > 0 → ≤ 0`;
  респаун у чекпоинта — код игры (Neon Rumble `--wave`), `level1` получает два `checkpoint`.
- **Неуязвимость при респауне** (находка В6д, тик 750) — в В7: `Body::guard`, тики
  неуязвимости, ставит игра, `collect_hits` такие цели пропускает, поле в снапшоте и хеше тела
  ВСЕГДА (не только при ненулевом). Цена — перепин голденов brawl, crossplay и строк `--wave` в
  том же коммите.

Принято без вопроса (владелец может развернуть до кода подкоммита):

- Переполнение стека и `pop` пустого — отказ с кодом, стек не меняется; две команды в одном тике
  применяются по порядку подачи.
- Headless обходит меню: `--level <имя>` выбирает уровень; сбой загрузки печатает строку
  `menu: <ошибка>` и завершает прогон с кодом 0 — путь «возврат в меню» судится headless, окно меню
  — ручной гейт.
- `guard` уменьшается в той же стадии, что `hitstop` (клипы, шаг 8 порядка тика).
- В7а: отказ считается в момент подачи по проектной глубине (стек + очередь), а не при применении —
  код возврата доходит до вызывающего синхронно. `replace` пустого — `Empty`; сцена без собранного
  `Schedule` — `BadScene`; очередь — 8 команд за тик, девятая — `QueueFull`. `run(Tick)` =
  `apply()` + расписание ВЕРХНЕЙ сцены; нижние стоят. Сессия отката — забота игры по `top()->rollback`.
- Команды стека из rollback-сцены (находка ревью В7а): стек и очередь вне снапшота, поэтому система
  rollback-сцены, позвавшая `replace` изнутри расписания, подаст команду заново на каждом ресиме, и
  команда из предсказанного тика применится, даже если коррекция этот тик отменила. Правило: rollback-
  сцена команд из своих систем не подаёт — их подаёт код игры по ПОДТВЕРЖДЁННОМУ тику (факт «уровень
  пройден» / «загрузка не удалась» читается из состояния после подтверждения). В7д закрепляет тестом.

Уровень проверки: T4 (голдены + сломанные фикстуры на трёх ОС) + T3 владельцем (окно меню и
респауна, новый § runbook). Score ≥ 60 (несколько модулей, перепин голденов) — ревью обязательно.

DoD В7: стек сцен и загрузка уровня — в SDK, include-seam чист; сбой загрузки в игре — текст в
меню, не краш (headless и окно); респаун у чекпоинта с `guard` = голден; прогресс и `guard` в
снапшоте, у каждого — фикстура с забытым полем; CI зелёный × 3 ОС, crossplay зелёный.
