# #26 В4: сейвы — состояние

## В4а: общий атомарный writer

save::write_atomic — фасад framework_save, поставляемый SDK. Единственная реализация находится
ниже в platform::write_atomic: achievements/rebind используют тот же примитив, без зависимости
подсистемы достижений от framework. Файловые форматы и ach::write_atomic/temp_path_for сохранены.
Путь обязан иметь одного писателя; temp остаётся <path>.tmp. Пустой путь и embedded NUL
отказывают до open: NUL иначе обрезал бы .tmp и усёк сам целевой файл.

Stale temp удаляется с проверкой ошибки до открытия: символьная/жёсткая ссылка на сейв
иначе усекла бы старый inode. Это воспроизвёл независимый reviewer; добавлена настоящая
регрессия обеих ссылок с observer hardlink старого inode. Windows без symlink privilege
пропускает только symlink, hardlink остаётся обязательным. Протокол также проверяет отказ удаления.

Порядок: fwrite → sync_file → fclose → replace_file → sync_dir_of. До replace ошибки сохраняют
цель и убирают temp. sync_dir_of теперь bool; отказ после replace сообщает неподтверждённую
долговечность каталога (новый целый файл уже видим), откат к старому не выдумывается.
POSIX sync_dir_of корректно обрабатывает родительский корень / и сообщает open/fsync/close failures.
Windows сохраняет MoveFileExW WRITE_THROUGH, sync_dir_of — true. Apple sync_file через
fcntl(F_FULLFSYNC), без слабого fsync fallback; Linux/Android по-прежнему fsync.
Реализации выбирает CMake, sync_file(nullptr) безопасно отказывает на всех платформах.

Протокольный тест на настоящем fwrite/tmpfile проверяет порядок/bytes и stale-remove/open/sync/replace/dir
отказы. Файловый тест проверяет UTF8, большой→короткий/пустой, stale temp, NUL и плохой parent.
ASan/UBSan положительный и4 отказанных мутанта (нет sync, игнорирование file/dir sync failures,
нет удаления stale temp). Прежний writer дополнительно отвергается настоящим filesystem link-тестом.
Существующие rebind/state/crash/hot-reload тесты перепроверяются. Первый crash прогон12/12 intact,
9 replaced,11 mid-write; повтор12/12 intact,6 replaced,10 mid-write. Build-loop и CPU asset hot-reload PASS. GPU material_hot_reload недоступен: wgpu не нашёл adapter;
его файловая подготовка прошла до запроса GPU. GPU/нативный watcher не объявляются проверенными.
Native FSEvents недоступен процессу даже при повторе с escalation: platform_watch_test падает на
ожидании native backend; forced polling проходит. Это ограничение проверки, не заявленный PASS.
