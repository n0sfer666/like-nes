# #26 В4: сейвы — состояние

## В4а: общий атомарный writer

save::write_atomic — фасад framework_save, поставляемый SDK. Единственная реализация находится
ниже в platform::write_atomic: achievements/rebind используют тот же примитив, без зависимости
подсистемы достижений от framework. Файловые форматы и ach::write_atomic/temp_path_for сохранены.
Путь обязан иметь одного писателя; temp остаётся <path>.tmp. Пустой путь и embedded NUL
отказывают до open: NUL иначе обрезал бы .tmp и усёк сам целевой файл.

Stale temp удаляется с проверкой ошибки до открытия: символьная/жёсткая ссылка на сейв
иначе усекла бы старый inode. Это воспроизвёл независимый reviewer; добавлена настоящая
регрессия обеих ссылок с observer hardlink старого inode. Windows без symlink privilege
пропускает только symlink, hardlink остаётся обязательным. Протокол также проверяет отказ удаления.

Порядок: fwrite → sync_file → fclose → replace_file → sync_dir_of. До replace ошибки сохраняют
цель и убирают temp. sync_dir_of теперь bool; отказ после replace сообщает неподтверждённую
долговечность каталога (новый целый файл уже видим), откат к старому не выдумывается.
POSIX sync_dir_of корректно обрабатывает родительский корень / и сообщает open/fsync/close failures.
Windows сохраняет MoveFileExW WRITE_THROUGH, sync_dir_of — true. Apple sync_file через
fcntl(F_FULLFSYNC), без слабого fsync fallback; Linux/Android по-прежнему fsync.
Реализации выбирает CMake, sync_file(nullptr) безопасно отказывает на всех платформах.

Протокольный тест на настоящем fwrite/tmpfile проверяет порядок/bytes и stale-remove/open/sync/replace/dir
отказы. Файловый тест проверяет UTF8, большой→короткий/пустой, stale temp, NUL и плохой parent.
ASan/UBSan положительный и4 отказанных мутанта (нет sync, игнорирование file/dir sync failures,
нет удаления stale temp). Прежний writer дополнительно отвергается настоящим filesystem link-тестом.
Существующие rebind/state/crash/hot-reload тесты перепроверяются. Первый crash прогон12/12 intact,
9 replaced,11 mid-write; повтор12/12 intact,6 replaced,10 mid-write. Build-loop и CPU asset hot-reload PASS. GPU material_hot_reload недоступен: wgpu не нашёл adapter;
его файловая подготовка прошла до запроса GPU. GPU/нативный watcher не объявляются проверенными.
Native FSEvents недоступен процессу даже при повторе с escalation: platform_watch_test падает на
ожидании native backend; forced polling проходит. Это ограничение проверки, не заявленный PASS.

## В4б: контейнер LNSV

save_format.hpp/encode_record/decode_record поставляются SDK. Wire v1:24 байта — LNSV4,
container u16, slot-version u16, body-length u32, writes u64, CRC32 u32; всё little-endian по полям.
CRC32 IEEE covers header без CRC-поля и всё body. Framing/CRC проверяются до классификации
версии: битый version не даёт FutureContainer. container0/slot-version0 — Corrupt, slot65535 и
uint64 max допустимы на уровне формата. Счётчик overflow будет отказывать на уровне store.
Читатель zero-copy и не выделяет память; body span живёт, пока исходные байты валидны.
Encoder допускает body из старого out, отказ сохраняет out. Ограничение тела16MiB задано
MAX_BODY_SIZE, чтобы файловая загрузка слота была ограниченной до выделения памяти.

Независимый byte-golden посчитан struct.pack+zlib.crc32, не текущим encoder. Unit проверяет
каждый одиночный bitflip header/CRC/body, все усечения, trailing bytes, resealed giant length,
версии0/65535, full counter, empty/max body, невыравненный буфер и self-alias encode.
Fuzz save добавлен последним, прежние индексы сохранены; full Release20 целей320000 случаев,
save16000/1181 accepts. Scoped ASan/UBSan использует настоящий run_target/seeds/index19,
результат тот же.4 semantic mutants (нет CRC/length, CRC без header, unchecked future) отвергнуты;
unsafe declared-length mutant пойман ASan heap-buffer-overflow во время обхода body.
SDK fixture линкует настоящий codec и writer из свежего prefix, сохраняет/читает контейнер.
Удалённый CI, полный ASan остальных читателей и реальные мобильные файловые системы тут не заявлены.

## В4в: Backend и выбор копии

SDK экспортирует Backend/read/write/list/move_new, LocalBackend и select_record. Корень только
абсолютный, отказ его создания не переходит в cwd. Read требует явный предел, TooLarge оставляет
ограниченный prefix для чтения counter; Missing отличается от IO Error. Ключи канонические
lowercase ASCII a-z/0-9/._-, до128 байт, без DOS-имён, конечной точки и суффикса .tmp.
Последний зарезервирован атомарным writer: reviewer воспроизвёл потерю независимого progress.tmp
при записи progress. Теперь такие ключи отвергаются, list скрывает служебные/неканонические имена;
case-insensitive FS не получает uppercase-алиасов. Другие файлы каталога не удаляются.

move_new делает exclusive copy, sync_file/close/sync_dir новой копии, затем удаляет исходник.
До удаления любой Error сохраняет источник; занятый backup не перезаписывается. Последний
sync_dir удаления — best effort: backup уже долговечен, crash может вернуть исходник, но не
потерять обе копии. После успешного unlink возвращается Moved, а не ложный Error с обещанием
сохранённого исходника. Одного ключа касается один сериализованный писатель, межпроцессного CAS нет.

Выбор проверяет framing/CRC и берёт max counter без часов; равные разные образы дают Conflict,
равные идентичные — одну копию, конфликт старых версий не заслоняет более новую. Fake-backend
тест использует две независимые копии и проверяет неизменность обеих. Файловый тест запускается
только в новом scratch-каталоге, проверяет UTF8 root, bounded/exact/empty reads, невалидные ключи,
соседний файл, зарезервированный temp, existing backup и отказ корня. Протокольный move-тест
проверяет8 фаз, включая ошибки file/dir sync и unlink. SDK fixture исполняет настоящий backend
из свежего prefix, exclusive move и выбор одинаковых копий.

Scoped ASan/UBSan (включая используемые platform FS sources, без смешивания instrumented STL
с обычным archive) проходит для selection/backend/move.7 production-мутантов отвергнуты:
меньший counter, потерянный Conflict, старый Conflict поверх нового counter, temp-алиас,
перезапись backup, отсутствие file sync и игнорирование dir sync. Types/lint, fresh SDK
Release/Debug/iOS/Android x86_64 и отдельная Android ARM64 сборка framework_save проходят.
Реальное выполнение LocalBackend здесь проверено на macOS, не на мобильных FS или Windows.

## В4г: слоты, миграции и карантин

SDK save_slots.hpp даёт load/store overloads с явным Backend. Slot — lowercase a-z/0-9/_/-,
до63 байт, без DOS-имён и точек (карантин не может алиасить другой slot). Весь slot со всеми
backup-ключами сериализует вызывающий. Invalid (цепочка/параметры) не делает IO; Error — IO
или overflow, не Corrupt. Non-success очищает body, quarantine возвращает ключ. Global facade
с полным путём будет добавлен с save::dir в следующей части.

load ограничен MAX_BODY_SIZE+24. CRC/framing перед Future, oversized physical record — Corrupt.
Карантин: .bad, .vN.k.bak, .vN.k.pre, первый свободный k; move_new никогда не перезаписывает backup.
До callbacks миграции исходник уже в .pre; chain начинается с version-1, задана полностью до
текущей версии. false/oversized body → MigrateFailed с пустым output и целым .pre. Ошибка publish
тоже сохраняет .pre; текущий slot может уже быть видимым после отказа sync_dir (контракт writer).
Прямая store отказывает на corrupt/future/иной версии canonical slot до явной load-обработки.

Новая запись берёт max raw writes из полных24-байтных LNSV header canonical slot и только его
канонических quarantine names +1. CRC/длина/версия при этом не фильтруют: reviewer и регрессия
поймали сброс после bitflip slot-version1→0; такой header всё ещё читаем. Неполный/без magic
header счётчика не даёт, max uint64 отказывает до backup/write. Нечитаемый backup/list — отказ,
соседний slot или похожее неканоническое имя не влияет. Часы не используются.

Проверки: fake roundtrip/empty/version chain1→3 и2→3, failed/oversized migration, future slot65535
и container2, повторный карантин/свободная дырка k, corrupted/oversized header counter, overflow,
IO failures и no-IO invalid calls. Настоящий LocalBackend в scratch-root проверяет .pre bytes,
два .bad и counter72. Доступ к настоящим пользовательским сейвам тестам не нужен.

Scoped ASan/UBSan проходит fake slots и actual LocalBackend со всеми используемыми platform FS
sources.7 mutants отвергнуты: reset/zero-version filter/wrap counter, chain с нулевого индекса,
игнорирование ошибки миграции, Future без backup, прямая перезапись другой версии.
Types/lint, fresh SDK Release/Debug/iOS/Android x86_64 и отдельная ARM64 framework_save сборка PASS;
fixture из установленного SDK исполняет настоящий slot roundtrip. Mobile FS/Windows/remote CI
не исполнялись здесь, реальные пользовательские данные не переносились.

## В4д1: каталог от оболочки и системное окно записи

platform_save.hpp поставляется SDK. set_save_dir до game init принимает только абсолютный путь
без NUL; explicit invalid/empty остаётся пустым override, не OS/cwd fallback. nullptr override
означает, что оболочка путь не выбирала. Setter не делает IO, создание/проверка остаются
LocalBackend/framework facade. iOS выбирает NSApplicationSupportDirectory (не Documents/Files),
Android — internalDataPath. До подключения global facade старый consumer path ещё используется.

mobile::Game::save отделён от suspend: Android PAUSE cancel+pause без записи; SAVE_STATE пишет
синхронно до post_exec_cmd acknowledgement, STOP повторяет. Это подтверждено исходником
пиннутого native_app_glue и host-test настоящего android_lifecycle.cpp с настоящими NDK enum.
Окно/поверхность по-прежнему живут отдельно, DESTROY не подменяет нужное системное окно записи.
Шутер перенёс pump/save достижений из suspend в save; shutdown также вызывает save.
У Neon Rumble/bench пока нет persistent data: save no-op, мир матча не сериализуется.

iOS pause даже без поверхности делает cancel/suspend и синхронный save под beginBackgroundTask,
end после записи. При отказе grant — немедленная best-effort запись, не отложенная до dealloc.
Expiration invalidates task до end: host-модель поймала UAF при освобождении callback внутри end
до последнего обращения к captures. Исправление проходит ASan/UBSan. Модель исполняет настоящий
persistence.mm, настоящий Foundation и узкий UIKit double: grant/refusal/expiry/repeat, порядок
pause/begin/write/end. Это не live UIKit/проверка поведения ОС при реальном убийстве приложения.

3 iOS mutants (нет write, end до write, освобождение callback до invalidation) отвергнуты.
Android lifecycle проходит ASan/UBSan;3 mutants (write в PAUSE, нет SAVE_STATE, нет STOP) отвергнуты.
platform-save unit, types/lint и fresh SDK Release/Debug/iOS/Android x86_64 PASS; настоящие shell+
shooter consumers с новым save собраны отдельно для iOS-sim и Android ARM64 без warnings.
STOP не получает ожидания ОС: это best-effort повтор, гарантия acknowledgement относится к SAVE_STATE.

## В4д2: global facade и legacy consumers

save::init/dir/file_path/load/store/migrate_legacy поставляются SDK. Root policy и повтор
подготовки сохраняют intended root после отказа; Invalid проверяется до directory recovery IO.
Global quarantine — абсолютный путь. Legacy — durable exclusive move известных имён;
существующее назначение сохраняет обе копии. [LIKENES_SAVE_DIR](../decisions/2026-11-02-save-directory-override.md)
остаётся desktop override; shell (даже empty) приоритетнее. Relative/unusable не даёт fallback.

Reviewer поймал P2: перебор env/OS/exe мог забрать OS-профиль в изолированный override.
Игра выбирает один прежний источник: env, иначе OS, exe только если OS-root не определён;
источник фиксируется до первой попытки init и повторяется после восстановления каталога.
Actual game_save_paths_test моделирует A/B/C и доказывает отсутствие даже обращения к OS/exe
при явном env, проверяет имена всех4 controls-файлов. Desktop offscreen demo.cpp не вызывает
init_save_paths и не читает/переносит настоящий профиль. Это не обещание отсутствия persistence
в историческом mobile shooter --demo. Все FS-фикстуры здесь только scratch-root, env контролируется
до первой попытки; настоящий HOME/default OS root тесты не создают.

Probe S пересчитывает путь вместо cached empty. Поздно найденный не загруженный профиль
сначала сохраняется exclusive move в controls_probe.txt.k.pre, затем явное S пишет текущие
настройки. Real RebindStore/FS test: bad parent → repair с old profile и занятым backup0 →
current saved + original bytes в backup1, repeat без лишнего backup. Между backup и publish
при ошибке оригинал остаётся в .pre, новая попытка продолжит сохранение.

ACH late attach реализован по [решению владельца](../decisions/2026-11-02-achievements-late-recovery.md):
original backup до merge, saturating lifetime sum + union unlocks, unknown/corrupt отказ перезаписи.
AchievementStore — в игре, uses только публичные LocalBackend и ach::LocalStore::read. Tracker
не заменяется: Delivery references валидны. attached устанавливается до publish: false после
видимого replace не приводит к повторному merge. Reviewer поймал отсутствующий в old stat:
restore меняет только присутствующие IDs; теперь перед late restore known counters сбрасываются
в0, затем добавляется session. Unlock flags сохраняются. Over-carry snapshot отказывается до
restore/backup/write, original не усекается. Обычная первичная загрузка не складывает повторно.

LocalStore::read отделяет проверенный snapshot от применения к Tracker; единый checkedreader
отличает Missing от IO, проверяет close, empty/NUL/негодный parent. platform::parent_dir — общий
pure syntax helper с native separators/root/UNC/drive-relative semantics, exe_dir использует его.
GameState вынесен без изменения полей/порядка/defaults из flecs-header в game_state.hpp:
реальный consumer regression собирается и в headless IDE_POC=OFF без ненужного ECS/GPU.
Combat и observer golden остались32a094e89eacf2f2.

Проверки: actualGameAchievements + реальный каталог, sourceB → shellC после initial отказа,
13/1150/7 counters, unknown records/union/retroactive threshold, first-free original backup,
repeat/new deltas/restart, partial/empty oldstats, saturation. BadCRC/future/empty/overcarry
не меняются; operator repair позволяет сохранить накопленную session. Test-only adapter вокруг
настоящего atomicwriter инъецирует false ДО publish и ПОСЛЕ настоящего replacement; обе попытки
с последующим retry сохраняют ровно одну сумму и один original backup.

Полностью инструментированная ASan/UBSan сборка relevant save/ACH/probe/path/policy consumers
и зависимостей проходит.5 ACH mutants отвергнуты: missing-old double, omitted backup,
unsupported overwrite, lifetime replacement вместо sum, повторный merge видимого собственного
образа после false. Restored positive проходит. Ранее проверены5 root/legacy mutants и2 probe
mutants. Crash повтор:12/12 intact,8 replaced,10 mid-write. Реальные мобильные FS, kill/background
на устройстве, Windows execution и удалённый CI здесь не заявлены. Fresh SDK Release/Debug/iOS-sim/Android x86_64, отдельные настоящие shooter consumers
iOS-sim/Android ARM64, types/lint проходят без warnings. Финальное staged review фиксируется
при завершении коммита.

## Дальше

В4 реализована локально; далее В5 (строки/UI/сетка ввода). В3/V4 не закрывают остающиеся
ручные проверки устройств. Новые пользовательские форматы и реальные файлы не переносились тестами.
[Равные counters](../decisions/2026-11-02-save-conflict.md) сохраняют обе разные копии с Conflict;
[move_new](../decisions/2026-11-02-save-backend-quarantine.md) не перезаписывает и сохраняет
исходник на Error. Публикация и удалённый CI этим локальным результатом не подменяются.
