# Пин wasmtime C-API (аудит #21 A·3·9)

```
bash scripts/fetch_wasmtime.sh               # положить C-API в deps/ со сверкой sha256 и штампом
bash scripts/check_wasmtime_pin.sh           # гейт, этап preflight_tree_rules.sh (без сети)
bash scripts/check_wasmtime_pin.sh --live    # плюс настоящая загрузка для этой машины, руками
```

WASM-гейт спеки #6 (`plugin_wasm_test`, `plugin_wasm_host_test`) в CI не ходит — `PLUGIN_WASM=OFF`
во всех конфигурациях `ci.yml`, а C-API лежит в `deps/` вне git. До A·3·9 конфигурация брала
`GLOB deps/wasmtime-*-c-api`, а документ качал архив голым `curl`: любая версия рядом молча
линковалась в песочницу untrusted-плагинов.

- Версия и суммы — один файл [`cmake/wasmtime.sha256`](../../cmake/wasmtime.sha256) в формате
  `sha256sum`, его читают и конфигурация, и скрипт. Суммы сняты 2026-09-25 с ассетов релиза
  bytecodealliance/wasmtime v26.0.0 (`x86_64|aarch64` × `linux|macos`).
- Тройка — `like_nes_wasmtime_triple` из `CMAKE_SYSTEM_NAME`/`CMAKE_SYSTEM_PROCESSOR` (на macOS —
  из `CMAKE_OSX_ARCHITECTURES`, универсальная сборка даёт `arm64+x86_64` и пина не находит).
  Сравнение с файлом сумм — точное, не регексом: `+` в тройке был бы квантификатором.
- Непиннутая тройка (Windows — у wasmtime там `.zip`, формат сумм и распаковка его не берут;
  универсальная сборка) — одна строка `STATUS … не пиннут — gate #5 пропущен`, не отказ и без
  подсказки про fetch: `fetch_wasmtime.sh` на ней отказывает. Пиннутая тройка без каталога —
  `STATUS … не найден в deps/ — gate #5 пропущен (bash scripts/fetch_wasmtime.sh)`; обе строки
  печатает `like_nes_wasmtime_dir`, а не её потребитель (ревью A·3: раньше на Windows шли обе).
- В `deps/` каталог `wasmtime-*`, которого нет в файле сумм, → `FATAL_ERROR` с его именем. Сверенный
  каталог ДРУГОЙ пиннутой тройки (fetch с `WASMTIME_TRIPLE` под Rosetta) не мешает, несверенный —
  отказ «не сверен». Файл-архив рядом не в счёт (`IS_DIRECTORY`).
- Штамп `deps/<имя>/.sha256` пишет только fetch после сверенной распаковки. Пиннутый каталог без
  штампа или с чужой суммой → `FATAL_ERROR … не сверен с пином`, fetch на нём тоже отказывает, а
  не говорит «уже в deps/». Без штампа имя каталога не доказывало бы ничего: распакованный руками
  архив чужой сборки носил бы то же имя.

Кейсы (20): три тройки, пустой deps/ (с подсказкой), пин со штампом найден, без штампа, с чужим
штампом, чужая версия, чужая версия рядом с пином, сверенная соседняя тройка (одна и рядом с
пином), несверенная соседняя, пин без заголовка, архив-файл рядом, непиннутая платформа и
отсутствие на ней подсказки про fetch; fetch — архив с чужой суммой, `--from` без файла,
несверенный каталог, незнакомая тройка. `--live` сверх того проверяет, что конфигурация принимает
штамп, записанный настоящим fetch. На Windows пути в probe-файл идут через `cygpath -m`, а кейсы
fetch задают `WASMTIME_TRIPLE` явно. Негативный контроль: на HEAD-поведении (GLOB) — 5 FAIL, fetch
без проверки штампа — 1 FAIL, функция до ревью A·3 (соседняя тройка отказ, подсказка у
потребителя) — 4 FAIL.

Смена версии: новые суммы с ассетов релиза в `cmake/wasmtime.sha256` одним коммитом, перепрогон
раздела Q `docs/owner-setup.txt`. Каталог старой версии в `deps/` после этого валит конфигурацию —
так и задумано.
