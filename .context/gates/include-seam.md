# Заголовки чужих целей — голым уникальным именем — `scripts/check_include_seam.py`

```
python3 scripts/check_include_seam.py             # блокирующий гейт, в checks.json
python3 scripts/check_include_seam.py --selftest  # правила проверяются сломанными фикстурами
```

Находка 13 аудита #21: 95 подключений `#include "../../engine/…"` поднимались выше своей цели в
чужую, и ещё 21 шло каталогом (`achievements/bake.hpp`, `graphics/sprite.hpp`) через `-I`
родительского каталога (`engine`, `engine/framework`). Путь обходит граф целей — файл собирается, даже если ребро `target_link_libraries`
убрали, и узнают об этом на линковке или при переезде каталога. Пути стояли не из прихоти: у
подсистем были ОДНОИМЁННЫЕ заголовки (17 имён: `registry.hpp`, `sim.hpp` ×3, `engine.hpp`,
`world.hpp` …), и голое имя разрешалось бы порядком `-I`, то есть молча брало бы чужой файл.
Решение владельца — префикс подсистемы в имени (`audio_engine.hpp`, `ach_state.hpp`,
`physics_world.hpp`) и оба правила гейтом; порознь они бессмысленны.

- **Правило 1 — путь не уходит из подсистемы.** Подсистема — ближайший каталог с `CMakeLists.txt`;
  у файла без такого предка (`platform/mobile`) — его каталог: корневой `CMakeLists.txt` целью
  подсистемы не является. Путь с `..` судится относительно файла. Путь с каталогом без `..` законен,
  только если файл по нему лежит у самого подключающего или у корня его подсистемы
  (`ipc/seqlock.hpp`, `compile/diagnostics.hpp` из `tools/ide/editor`); найденный где-то ещё в
  дереве — находка, при любом `-I`, которым он собрался бы (`engine/core/fixed.hpp`,
  `graphics/graphics_sprite.hpp`). Пути, которого в дереве нет, — сторонняя библиотека
  (`backends/imgui_impl_wgpu.h`). `\` в пути читается как `/`: MSVC его принимает. Вложенная
  цель — своя подсистема: `engine/framework/physics` → `../x.hpp` уже межцелевой. Внутри подсистем законных `../`
  осталось 14 (`engine/plugin/plugins/*` → `plugin_api.h`, `tools/ide/editor/*`).
- **Правило 2 — базовые имена `.h`/`.hpp`/`.inl` уникальны по дереву без учёта регистра:** на
  macOS и Windows `Scene.hpp` находится по `#include "scene.hpp"`. Исходники (`.cpp`) не судятся —
  их по имени не подключают.
- **Комментарии снимаются перед поиском** (`scripts/cpp_text.py`): директива в блочном
  комментарии не подключение, а `/* … */ #include` на одной строке — подключение. Путь берётся из
  исходника — кодовая половина гасит литерал.
- **`<…>` не судится**: системные и сторонние заголовки.
- **Обход берёт файлы у git вместе с ненаписанными в индекс**, признак обхода — ПЯТАЯ копия
  `ROOTS`/`EXTS`, сверяется `check_tree_roots.py`.
- **Пустой обход — ОТКАЗ**: меньше 60 файлов, меньше 10 `CMakeLists.txt` (без корней подсистем
  каждое законное `../` стало бы находкой), меньше 300 разобранных подключений (регулярка
  директивы сломана).
- Самопроверка — **28 контролей**: 14 порч (подъём в соседнюю подсистему, через корень дерева, путь
  от корня, из вложенной цели к родительской, файл без своей цели, пробелы вокруг `#`, подъём,
  вернувшийся в чужой каталог, каталог через `-I` родителя и через `-I engine`, обратный слеш,
  блочный комментарий перед директивой, одноимённые `.hpp`, имена, различные регистром,
  одноимённые `.inl`), 9 чистых входов, опорный кейс охранников и три их порчи, обход в настоящем
  git-репозитории. Одиннадцать мутантов правил (владелец = корень, `..` всегда внутри, регистр,
  без снятия комментариев, без поиска `CMakeLists.txt`, без `.inl`, без поиска по дереву, свой путь
  всегда/никогда, без `\`, без снятия `/* */` на строке) — все краснят набор.
- **Позитивный контроль на дереве:** гейт на HEAD до исправления (`f478152`) — FAIL, 133 находки
  (95 подъёмов, 21 каталог через `-I` родителя, 17 одноимённых имён); после — PASS. Сырых `-I` на
  родительские каталоги (`engine`, `engine/framework`) в CMake не осталось.

Межцелевые рёбра, которые подъём прятал, заведены явно: INTERFACE-цель `asset_hash` (заголовочный
`hash.hpp` без zstd) для плагинов, достижений, материалов, IDE и света; `ach_plugin` → `plugin_core`
PUBLIC, `audio_core`/`input_core` → `asset_hash` вместо сырого `-I engine/asset`. Мобильные
оболочки (`platform/android`, `platform/ios`) с 2026-09-28 — подкаталоги корня (`LIKE_NES_MOBILE`):
`-I` приходят теми же целями, что на десктопе, через `game_core_target` из
`example_ugly_game/game_sources.cmake`. CI их не собирает — сборку и линковку держит
`scripts/xcompile_verify.sh` на macOS-хосте. Ручные шаги `.github/workflows/ci.yml` компилируют мимо CMake, и их `-I` перечислены
руками — переименование или новое ребро требует правки там же.
