# Игра против поставленного SDK (спека #24, В1, В4, В5а, В5б, В6б; спека #25 В5б — `--wave`, В9д — `--coop`; спека #26 В1д — мобильная половина)

```
bash scripts/check_sdk_game.sh          # префикс и сборки игры во временном каталоге
bash scripts/check_sdk_game.sh --keep   # то же, префикс и игра остаются в build-sdk-work/
```

Предмет — **поставленный префикс**, а не дерево. Внутри дерева игре видны все заголовки и все цели,
и забытый в [`cmake/sdk_headers.cmake`](../../cmake/sdk_headers.cmake) заголовок или библиотека
проявились бы только у игрока. Гейт:

1. конфигурирует и собирает `build-sdk-release` (`like_nes_sdk` + `assetc`) и `build-sdk-debug`
   (`like_nes_sdk`) с `-DAUDIO_MINIAUDIO=OFF -DPLUGIN_UI=OFF -DPLUGIN_WASM=OFF -DIDE_POC=OFF`;
2. ставит компонент `sdk` из обоих в ОДИН префикс (`lib/like-nes/` и `lib/like-nes/debug/`);
3. собирает `games/neon-rumble` через `find_package(like-nes 0.1 REQUIRED CONFIG)` в Release и
   Debug (`cmake --fresh`) и запускает `--headless --frames 480` (до В2г — 60, до В3а — 180, до В3г — 240, до В3е — 360). Утверждение — rc 0 **и** строки
   `neon-rumble: headless run ok, 480 frames` и `neon-rumble: library.bundle <N> bytes`: бандлы рядом
   с exe кладёт `like_nes_bake`, рантайм wgpu — `like_nes_add_game`. С В4г спеки #25 ещё
   `neon-rumble: pad backend <имя>` — бэкенд пада этой ОС (`sdk_pad_backend`): `input_native` едет
   в SDK под `like-nes::window`, а без вызова из игры линкер выбросил бы архив, и гейт был бы
   пустым. Контроль: убранный вызов `report_pad_backend()` и чужое имя в `sdk_pad_backend` — оба
   `FAIL …: the native pad backend of this OS is not linked from the prefix`. С В5б ещё две строки сводки:
   `level level1 40x21 tile 16, 2 visual layer(s), 1 texture(s) 384x256` (с В8а — `6 visual
   layer(s), 16 animated tile(s), 5 texture(s) 384x256 128x128 128x312 144x124 493x209`: небо, два
   плана города, вывеска; число анимированных тайлов — `anims` уровня) — игра открыла
   `game.bundle` маппингом, прочитала таблицу `visual` (`raw_table`) и тайлсет сырым RGBA8
   (`raw_rgba8`), — и `frame 960x540 scale 2: <N> sprite(s), <M> run(s), 0 unknown, 0 rejected,
   0 dropped` — кадр окна прошёл `draw_layer` и `layer_quads` из поставленных заголовков и целиком лёг
   в квады. Числа спрайтов и прогонов не пинятся (их судит голден в дереве), только ненулевые; нули
   отказов пинятся: чужой guid текстуры, источник за краем текстуры или нехватка буферов — находка.
   С В7б (уровень вырос до 40×21) ещё три строки пинятся целиком: `viewport 960x540 scale 2, visible
   480x270, zone 96,54 768x432, shown 0,0 960x540, 4 strip(s)` и `viewport 300x200 scale 1, …,
   cropped` — `viewport_fit` из поставленного заголовка (до В7б его в SDK не было), — и `bounds

## Мобильная половина (спека #26, В1д, [`scripts/sdk_game_mobile.sh`](../../scripts/sdk_game_mobile.sh))

Идёт после десктопной: бандлы мобильной игры печёт `assetc` десктопного префикса
(`-DLIKE_NES_HOST_PREFIX`), а `game.bundle` пакета побайтно (`cmp`) равен бандлу `game-Release` —
один манифест и один `assetc`. Префикс — свой на платформу, Release, ставится в пустой каталог
(`<OUT>/prefix-ios-sim`, `<OUT>/prefix-android-x86_64`; под `--keep` — в `build-sdk-work/`); игра
собирается через `-Dlike-nes_DIR` (тулчейн NDK переносит `CMAKE_PREFIX_PATH` в sysroot).

| платформа | где | сборка SDK | пакет обязан нести |
|---|---|---|---|
| `ios-sim` | macOS — всегда | `build-sdk-ios-sim` (`-DCMAKE_SYSTEM_NAME=iOS`, `iphonesimulator`, arm64); минимум игры — `_ln_ios_min` из Config | бинарь `platform IOSSIMULATOR` (`vtool`), `MinimumOSVersion` = минимум префикса, `assets/game.bundle`, `assets/library.bundle`, `licenses/<каждое имя _ln_licenses>` |
| `android-x86_64` | macOS и Linux при пиннутом NDK, иначе строка `SKIP android-x86_64 (<причина android_ndk.sh>)`; `SDK_GAME_ANDROID=required` (джоб CI Linux) — нет NDK = FAIL, `skip` (джоб CI macOS) — строка `SKIP android-x86_64 (SDK_GAME_ANDROID=skip)` | `build-sdk-android-x86_64` (тулчейн NDK пина, `ANDROID_PLATFORM` — `minSdkVersion` шаблона манифеста) | `libneon_rumble.so` — ELF x86-64; в APK `lib/x86_64/libneon_rumble.so`, `lib/x86_64/libc++_shared.so`, оба бандла, `assets/licenses/<каждое имя>` |

Windows печатает `SKIP mobile half`. NDK выбирает тот же `platform/android/android_ndk.sh`, что у
`build_apk.sh`, в подоболочке: его отказ — `exit 1`. В CI Linux ставит пин NDK, build-tools 35,
platforms 35 и `x86_64-linux-android`, macOS — `aarch64-apple-ios-sim`; `ANDROID_NDK_HOME` образа
переставляется на пин (иначе отказ по ревизии). Обязательность задаёт env шага, а не ОС: без него
Linux без NDK (машина владельца без Android SDK) падал бы, а macOS-раннер включал бы или
выключал Android по NDK своего образа.

Фикстура (на каждой собранной платформе): копия игры с `#include "shooter_mobile.hpp"` в
`rumble_mobile.cpp` обязана упасть сборкой с именем заголовка и `not found` / `No such file` —
заголовок оболочки дерева не утёк в префикс путями include.

## Отказы конфигурирования дерева (`cmake/install_sdk.cmake`, `cmake/sdk_links.cmake`)

Идут в КАЖДОМ конфигурировании, не только в гейте:

- `#include "x"` поставленного заголовка — только поставленный; `<x>` — поставленный сторонний или
  стандартный C++ (без точки и слэша);
- элемент ссылок — цель SDK, `Threads::Threads`, `-framework`, голое имя или системный путь;
  файл из дерева или его сборки — отказ;
- `INTERFACE_COMPILE_OPTIONS` / `LINK_OPTIONS` / `LINK_DIRECTORIES` цели SDK — отказ; каталог
  include — только поставленный (плюс stb: его не подключает ни один поставленный заголовок);
- макрос с `$<`, `]==]` или путём дерева — отказ; значения пишутся в Config bracket-аргументом.

Мутации `like_nes_bake` 2026-10-02 (macOS, префикс `--keep`): без `DEPFILE`, без копии бандла в
каталог exe, копия через `POST_BUILD` вместо отдельной цели — каждая валит свою фикстуру или сверку.
Последнюю ловит только подмена PNG ДРУГИМ файлом: после голого `touch` байты те же, и недоехавший
бандл неотличим от доехавшего.

Мутации 2026-10-01 (macOS): `<stb_image.h>` в `arena.hpp`, PUBLIC include `tools/` у
`framework_physics`, ссылка на `build-sdk-release/libfoo.a` — каждая валит конфигурирование своим
текстом.

## Где идёт

- preflight — этап группы `preflight_build_rules.sh`;
- CI — джоб `sdk-game` в `ci.yml` на трёх ОС (мобильная половина — iOS-sim на macOS, Android x86_64 на Linux).

Окно игры на живом железе (Wayland, драйвер) CI не открыть: `--keep` оставляет префикс для
оконного прогона владельцем — `docs/owner-setup.txt`, раздел S.

Имя заголовка игры против поставленного судит не этот гейт, а include-seam (правило 3,
`.context/gates/include-seam.md`): ему не нужна сборка, и он идёт на каждом коммите.

  на экране — шаг 5 §30 и шаг 7 §31 `docs/owner-verification.md`.
