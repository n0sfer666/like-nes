# Лицензии чужих ассетов игр — `scripts/check_asset_licenses.py`

```
python3 scripts/check_asset_licenses.py             # блокирующий гейт, в checks.json
python3 scripts/check_asset_licenses.py --write     # перегенерировать NOTICES.txt и credits.txt
python3 scripts/check_asset_licenses.py --selftest  # правила проверяются сломанными фикстурами
```

Спека #24, В2 — заведён ДО первого ассета в дереве: файл без записи о происхождении нельзя
распространять, и узнают об этом не в коммите, а в чужом письме. Правила —
`scripts/asset_licenses.py`, генерация титров — `scripts/asset_notices.py`, раскладка и обход
каталогов — `scripts/game_assets.py` (общий с [asset-budget](asset-budget.md)), фикстуры —
`scripts/check_asset_licenses_fixtures.py`.

## Устройство

- **Область — `games/*/assets/`, и там только чужое.** Свои файлы игры (манифест, уровни `.tmj`,
  листы `.sheet`) живут вне `assets/` — решение владельца 2026-10-01: белый список лицензий их не
  пускает, а запись в инвентаре требовала бы ручной правки sha256 после каждой правки уровня.
  Исключения по расширению нет сознательно: паки сами приносят `.tsj` и JSON. Под `assets/` вне
  инвентаря лежат только `LICENSES.toml`, сгенерированные `NOTICES.txt`, `credits.txt` и
  `licenses/<SPDX>.txt`.
- **`[[pack]]` + `[[file]]`** (решение владельца 2026-10-01). Пак — `name`, `url`, `author`,
  `license`, `attribution`; файл — `path`, `pack`, `sha256`, `changes`. Источник и автор пишутся
  один раз: двести копий на файлы одного пака дали бы пак с двумя авторами от первой опечатки.
  Неизвестный ключ, дубликат, ссылка на необъявленный пак и пак без файлов — отказ.
- **Белый список:** `CC0-1.0`, `CC-BY-3.0`, `CC-BY-4.0`, `OFL-1.1`. CC-BY требует `attribution` у
  пака и `changes` у КАЖДОГО файла (`"none"`, если не правился): CC-BY обязывает указать правки, а
  отсутствие поля гейт отличить от «забыли» не может — явное `none` может.
- **Листинг сверяется в обе стороны с учётом регистра**: `Tiles.png` в инвентаре против `tiles.png`
  на диске — отказ на любой ОС, отдельным видом `case`. Каждая запись закрывает ровно ОДИН файл
  (`match`, чистая функция): на Linux `a.png` и `A.png` — два файла, и запись `a.png` второй не
  прикрывает (находка ревью 2026-10-01; до неё пара проходила молча). Два пути инвентаря, равные без
  учёта регистра, — `schema`: macOS и Windows держат лишь один из них. Ссылка вместо файла — `link`.
- **Путь — печатный ASCII через `/`, без `..`**, иначе запись отбрасывается разбором (`schema`):
  macOS отдаёт не-ASCII имя в NFD, инвентарь пишется в NFC, и одно имя расходилось бы только там.
- **Служебные файлы ОС** (`.DS_Store`, `Thumbs.db`, `desktop.ini`) обход пропускает: гейт смотрит
  рабочее дерево, `.gitignore` их в коммит не пускает, а без списка pre-commit падал бы на файле,
  которого нет ни в коммите, ни в игре. Список один на оба гейта и совпадает с `.gitignore`.
- **Тексты лицензий — ровно использованные:** нет текста — отказ, лишний текст или чужое имя в
  `licenses/` — тоже (иначе каталог стал бы обходом инвентаря).
- **`NOTICES.txt` и `credits.txt` — байт в байт генерация**, порядок по именам: перестановка записей
  инвентаря файлы не устаревает (фикстура это пинит). `credits.txt` — `|`-грамматика, как
  `library.mat`: `credit | <пак> | <автор> | <SPDX> | <url>`, следом `attribution | <текст>` у
  CC-BY.
  Поэтому поле инвентаря не может содержать `|`, `#`, перевод строки и пробел по краю:
  `split_fields` обрезал бы край, а `#` читатели `|`-грамматики режут как комментарий в любом месте
  строки (`atlas_parse.cpp`, `profile_parse.cpp`, `preset_bake.cpp`) — находка ревью 2026-10-01.
- **BOM в начале инвентаря — свой вид `bom`**: `tomllib` и сам отбил бы его как `toml`, но с
  сообщением, из которого причина не видна.
- Аргументы — `--selftest`, `--write` или ничего; иное — код 2 (опечатка `--wirte` молча гоняла
  бы гейт вместо записи).
- **Python ≥ 3.11** (`tomllib`). Младший — отказ с версией ДО импорта, код 2.
- **`.gitattributes`: `games/*/assets/** -text`.** Гейт по дереву в CI идёт на ВСЕХ трёх ОС, а не
  только на Linux, как соседние текстовые гейты: его предмет — байты checkout, и autocrlf менял бы
  sha256 и `NOTICES.txt` только на windows-раннере.
- Пустой обход (`games/*/assets` не нашлось) — отказ, а не PASS. Пустой инвентарь при пустом
  каталоге — законное состояние до В4.
- Перед гейтом молча идёт самопроверка: сломанное правило молчит неотличимо от чистого дерева.

## Самопроверка — 35 контролей

Сверяется МНОЖЕСТВО видов находок, а не их наличие. Восемь фикстур спеки: нет записи (`missing`),
лишняя запись (`extra`), CC-BY-SA (`license`), CC-BY без атрибуции (`attribution`), хеш
(`sha256`), устаревший `NOTICES.txt` (`notices`), нет текста лицензии (`license-text`), CRLF-копия
JSON-тайлсета (`sha256`). Сверх них: устаревший `credits.txt`, регистр, CC-BY без `changes`, лишний
текст лицензии, неизвестный ключ, неизвестная таблица верхнего уровня, `|`, `#` и пробел по краю
поля, путь с `..` и не-ASCII путь (`schema` + `missing`), один путь дважды в разном регистре, пак
без файлов, BOM (`bom`), битый TOML (только `toml`, без лавины листинга), ссылка на файл и на
каталог (обход за неё не идёт), служебные файлы ОС и перестановка записей (находок нет). Отдельно:
три кейса `match` без ФС (пара `a.png`/`A.png` при одной записи — второй файл `missing`), обход
`games/*/assets`, три версии Python. Ссылки на Windows без режима разработчика пропускаются
(`skip` в подробном выводе, `пропущено: N` в итоговой строке): git там отдаёт ссылку файлом, и её
ловит `sha256` или `missing`.

Мутанты 2026-10-01: 21 порча правил `asset_licenses.py`, 19 убиты сразу; выжившие (пробел по краю,
таблица верхнего уровня) убиты двумя новыми фикстурами. Ветка ссылки на каталог в `game_assets.py`
покрыта своей фикстурой — её мутант убит. После ревью — 9 порч новых правил (сопоставление по
регистру ×2, `#`, ASCII-путь, дубликат по регистру, BOM, ссылка без `missing`, список мусора ОС ×2):
8 убиты сразу, BOM выжил (`tomllib` отбивал его тем же видом `toml`) и убит своим видом `bom`.
